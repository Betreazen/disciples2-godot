## Коротко

- **Мини-карта — растр, а не набор значков-точек.** Картинка размером **4·N × 2·N** пикселей (N — размер карты в
  клетках), 16 бит на пиксель. Клетка `(x, y)` попадает в точку **`(2(x − y) + W/2, x + y)`**, где `W` — ширина
  растра; рисуется блоком 4×2 по маске `0x6f3fb0` — 4 пикселя: `(1,0)`, `(0,1)`, `(1,1)`, `(2,1)`. Блоки соседей
  смыкаются без щелей и без наложений.
- **Цвет клетки берётся не из таблицы, а из картинки-узора**: `ISONE/ISOHU/ISODW/ISOUN/ISOEL/ISOHE` (96×96),
  `ISOWA` (вода), `ISOWB` (кромка воды), `ISOMO` (горы), `ISOFO` (туман) — 132×132 у `ISOMO`/`ISOWB`. Пиксель
  берётся из узора по **тому же адресу растра** `mod (ширина, высота узора)`, то есть узор привязан к мини-карте,
  а не к клетке. Лес на мини-карте не выделяется — берётся узор расы.
- **Три прохода** (`0x67eeb6`): земля и вода → значки → туман поверх. Клетка под туманом земли не рисует, но воду
  рисует, а сверху всё равно ложится `ISOFO`.
- **Значки** — 29 картинок `CAP*/CITY*/STCK*/CRYS*/MOUNTNE1..5/RUIN` из `PalMap.ff`, кладутся **центром** в ту же
  точку клетки (+1 по X), маджента прозрачна. Порядок — по слою из таблицы `0x6edc10`: горы 0, города и руины 1,
  столицы 2, кристаллы 3, отряды 4.
- **Мини-карта прокручивается вместе с видом.** Растр кладётся в `IMG_PALMAP` (150×132) так, что **центр текущего
  вида приходится на центр окна**; у карт крупнее окна видна только часть. Поверх рисуется белая рамка
  постоянного размера: 40×34 точки при ширине экрана 640/800, 52×44 при 1024, 66×61 при 1280.
- **Щелчок** по мини-карте центрирует вид на клетке, **протаскивание** сдвигает вид на разницу в клетках; знак
  сдвига переворачивает `Disciple.ini InversedPalMap`. Три прямоугольника кнопок, налезающих на `IMG_PALMAP`
  (`BTN_RES_PAL`, `TOG_BANNERS`, `TOG_RESPOPUP`), из обработки мыши исключены.
- **Прокрутка карты** — ступенями ровно в одну клетку: `(±32, ±16)` пикселей мира за шаг, 8 направлений. Зона у
  края экрана — **4 пикселя** (координаты `0..3` и `S−3..S`). Интервал между шагами — `ScrollSpeed`
  **миллисекунд** (`0` быстро … `100` медленно, по умолчанию в коде 100, в поставляемом ini 0). Стрелки клавиатуры
  дают такой же шаг, но без задержки. За край карты вид не уходит: шаг, после которого центральная клетка
  оказалась бы вне карты, отменяется и пробуется «скользящее» направление.
- `TOG_BANNERS` — переключатель флага `[0x838650]`; значки-знамёна над отрядами, руинами и лавками рисуются, когда
  этот флаг **или** флаг `[0x838651]`, который ставится по зажатому **Shift**. Это закрывает вопрос из
  `docs/map-render.md` («кто ставит `0x838650`/`0x838651`»).
- `TOG_RESPOPUP` — переключатель `[0x835a7c]`; показывает/прячет `DLG_ISO_RESPOPUP` (или `DLG_ISO_GOLDPOPUP`).
- `BTN_RES_PAL` переключает `[0x835a78]` 0↔1 и заново показывает `DLG_ISO_PAL` (мини-карта) или `DLG_ISO_LAND`
  (проценты захваченной земли).

## 1. Мини-карта

### 1.1 Место и размеры

`DLG_ISO_PAL` (160×203) из `Interf.dlg`: `IMG_PALMAP` занимает `4,62 … 154,194`, то есть **150×132**. На картинку
налезают `BTN_RES_PAL` (`0,166…32,195`), `TOG_BANNERS` (`0,63…32,92`) и `TOG_RESPOPUP` (`1,2…33,31`). `0x48854c`
берёт области этих трёх элементов и передаёт их конструктору `CPalMapInterf` (`0x5cb7a0`) вместе с областью
`IMG_PALMAP`; счётчик исключений — 3. Мышь внутри любого из них мини-карта не обрабатывает (`0x5cbaca`).

Растр мини-карты создаётся один раз на карту: `4·max(N) × 2·max(N)` пикселей, 2 байта на пиксель в формате экрана
(`[0x6e0480]`, то есть RGB565, как и вся графика карты). Для карты 48×48 это 192×96, для 144×144 — 576×288.
Размер карты обязан быть в пределах `0x30…0x90` (48…144), иначе мини-карта не создаётся (`0x5ca627`).

### 1.2 Геометрия

Клетка `(x, y)` → точка растра:

```text
p = (2·(x − y) + W/2, x + y)          W — ширина растра (4·max(N))
```

В точке `p` рисуются четыре пикселя — те, где маска `0x6f3fb0` (8 байт, индекс `столбец + 4·строка`) равна нулю:

```text
строка 0:  . X . .          маска: 1 0 1 1
строка 1:  X X X .          маска: 0 0 0 1
```

Соседняя клетка по `x` смещена на `(+2, +1)`, по `y` — на `(−2, +1)`; ромбы смыкаются без щелей и без повторной
записи пикселей (проверено перебором: строка растра покрывается полностью). Обратное преобразование
(`0x67d6d2`) — ровно эта же раскладка: `x' = px − W/2 + 1`, `qx = ⌊x'/4⌋`, `qy = ⌊py/2⌋`, клетка
`(qx + qy, qy − qx)` и поправка по остаткам `rx = x' − 4·qx`, `ry = py − 2·qy` из таблицы `0x6f3fb8`:
`rx=0, ry=0 → x−1`; `rx=2 или 3 при ry=0 → y−1`; `rx=3, ry=1 → x+1`; иначе без поправки.

### 1.3 Чем закрашена клетка

Пиксели берутся из картинки-узора (`0x67f17c`): источник — `(p.x mod ширина_узора, p.y mod высота_узора)`, с
поправкой, чтобы блок 4×2 не вылез за край узора (`sx += 4 − ширина`, если `sx + 4 ≥ ширина`; так же по Y).
Узор привязан к координатам растра, поэтому соседние клетки одного типа дают непрерывную «ткань», а не плитки.

Номер узора (`0x5cae4b`, порядок имён в `0x7b05f0`):

| условие | номер | картинка |
|---|---|---|
| грунт — вода | 6 | `ISOWA` |
| грунт — горы | 8 | `ISOMO` (132×132) |
| раса — Легионы | 5 | `ISOHE` |
| раса — Империя | 1 | `ISOHU` |
| раса — Кланы | 2 | `ISODW` |
| раса — Орды нежити | 3 | `ISOUN` |
| раса — эльфы | 4 | `ISOEL` |
| иначе (нейтралы) | 0 | `ISONE` |
| кромка воды (служебный) | 7 | `ISOWB` (132×132) |
| туман (служебный) | 9 | `ISOFO` |

Грунт «лес» отдельного номера не имеет: лесная клетка красится узором своей расы. Категории узнаются сравнением
поля `+8` категории с глобалями: грунт `0x837328` (вода), `0x837348` (горы); расы `0x837968` (Легионы),
`0x837980` (Империя), `0x837948` (Кланы), `0x837958` (нежить), `0x837928` (эльфы) — адреса сверены с тулсетом
(`groundcat.cpp`, `terraincat.cpp`).

Проход земли (`0x67ef78` с флагом 0) для каждой клетки:

1. `0x67e225`: если клетка — вода, рисуется `ISOWA`; иначе, если клетки `(x+1, y+1)` и `(x+2, y+2)` — вода (у
   правого/нижнего края карты проверяется только `(x+1, y+1)`), рисуется `ISOWB` — это затенённая кромка берега
   (на экране `(x+1, y+1)` находится ровно на 2 точки ниже).
2. `0x67e1da`: если клетка не под туманом и не вода — поверх рисуется её узор.

Проход тумана (флаг 1) рисует `ISOFO` над каждой клеткой с поднятым признаком тумана. У клеток на краю карты
туман дополнительно продлевается на **5 клеток наружу** (`x < 0`, `y < 0`, `x ≥ N`, `y ≥ N`) — так закрашивается
часть растра за ромбом карты.

Признак тумана и узор клетки приходят в мини-карту из того же кода, который обновляет большую карту: `0x5ac1c4`
(смена грунта/расы) → `0x5cadaa`, `0x5ac56a` (смена тумана) → `0x5caee3`. Отдельного «своего» тумана у
мини-карты нет. Видимость подчиняется правилу из `docs/map-render-stacks.md` §4.

Раса берётся сравнением с глобалями рас (`0x8372c8` Империя, `0x8372e8` Кланы, `0x8372d8` Легионы, `0x837298`

Слой значка берётся из таблицы `0x6edc10` (по номеру значка): горы 0, города и руины 1, столицы 2, кристаллы 3,
отряды 4. На одну клетку — по одному значку на слой, рисуются снизу вверх. Точка: та же формула, но `+1` по X, и
картинка кладётся **центром** (`p − (ширина/2, высота/2)`, `0x67f2a9`); маджента прозрачна. Лавки (`site`)
своего значка на мини-карте не имеют.

### 1.5 Где растр оказывается в окне, рамка вида, мышь

`CIsoScroller` (`0x5ca7c1`) подписан на прокрутку вида (`0x54113a`). При каждой прокрутке (`0x5ca811`) он
получает от `0x540b6c` **центральную клетку вида** и остаток `(dx, dy)` — разницу между точным центром области
вида и опорной точкой этой клетки в пикселях мира; в мини-карту кладутся клетка и `(dx·4/64, dy·2/32)`, то есть
тот же остаток в масштабе **1/16** (клетка 64×32 против 4×2).

Смещение растра (`0x67ecb0`): пиксель растра, который приходится на левый верхний угол `IMG_PALMAP`, равен
`точка_растра(центральная клетка) + (dx/16, dy/16) − (ширина области/2, высота области/2)`. Растр рисуется в
`угол области − это смещение` с обрезкой по области (`0x67ec25`). То есть центр вида всегда в центре окошка
150×132, а всё, что не влезло, обрезано. Даже у самой маленькой карты (48 клеток → растр 192 точки) по ширине
влезает не всё.

Белая рамка вида — отдельная картинка сплошного цвета `0xffffff` (`0x5cb999`), её размер посчитан один раз как
разница точек растра для клеток `(0,0)` и `(27,7)`, `(35,9)` или `(47,14)` — по ширине экрана (иначе / 1024 /
1280), то есть **40×34**, **52×44** или **66×61** точек. Положение (`0x5cbf4b`):
`точка_в_области(центральная клетка) + (dx/16, dy/16) − размер_рамки/2`. Рисуется поверх растра (`0x5cbf0c`).

Мышь (`0x5cba99`):

- **`WM_LBUTTONDOWN`** внутри области и вне трёх исключённых прямоугольников: запоминается точка, ставится
  признак «тащим».
- **`WM_MOUSEMOVE`** при зажатой левой (`0x5cbdf3`, проверка `0x56142a(1)`): `0x5cbbf6` с признаком «тащим»
  переводит текущую и предыдущую точки в клетки (`0x67ed26`), берёт разницу и прибавляет её к текущей
  центральной клетке вида (при `[0x838938] = 0` — **вычитает**), обрезает по `0 … N−1` и центрирует вид
  (`0x540c38`). `[0x838938]` ставится из ini `InversedPalMap` (`0x405e04` при старте, `0x4c1454` из настроек).
- **`WM_LBUTTONUP`** без предшествовавшего перетаскивания: та же `0x5cbbf6`, но вид просто центрируется на
  клетке под курсором.

Перерисовка растра делается не каждый кадр: запись узора, тумана или значка ставит признак «грязно»
(`0x67e412`), а `0x67eeb6` перерисовывает всё целиком и сбрасывает признак.

## 2. Прокрутка основной карты

Шаг прокрутки один для всех источников: `0x541271` просит 2D-движок сдвинуть начало вида на `(32, 16)` в одном
из 8 направлений (`0x66c50b(направление, 0x20, 0x10)`), то есть ровно на одну клетку по диагонали или на клетку
по оси. Нумерация направлений: 0 вверх, 1 вверх-вправо, 2 вправо, 3 вниз-вправо, 4 вниз, 5 вниз-влево, 6 влево,
7 вверх-влево.

**Ограничение у края.** После сдвига считается центральная клетка вида (`0x540b6c`). Если она вне `0…N−1` по
любой оси, сдвиг откатывается (`0x66c3d7`), и по таблице у `0x54148c` пробуется «скользящее» направление — та же
прокрутка вдоль края. Значит, камера не может уйти за ромб карты дальше, чем на половину области вида: упор идёт
по центральной клетке, а не по краю экрана.

**Когда карта стоит.** Под окном поверх карты (список, настройки, город), в бою и в ход ИИ прокрутка выключена — и стрелками,
и краем экрана (подтверждено пользователем 14.10; у движка это признак `[mapGraphics+0x44]` ниже). В режимах прицела
(заклинание, бросок предмета, обмен, посох) карта едет — цель может быть далеко. Порт: `MapView.ScrollEnabled`, его ставит
`MapScreen.ShowMap` («карта открыта и не закрыта»); проверка — `ui-render-check.py` «прокрутка стрелкой» (шаг `--clicks arrows`).

**Мышь у края экрана** (`0x541955`, вызывается по таймеру интерфейса):

1. Требуется признак `[mapGraphics+0x44]` (прокрутка разрешена; ставится `0x540b4e`) и проверка фокуса/курсора
   (`0x5613d6`).
2. Позиция курсора сравнивается с четырьмя полосами, заданными в конструкторе `CIsoInterface` (`0x541786`):
   `x ∈ [0, 3]`, `x ∈ [ширина−3, ширина]`, `y ∈ [0, 3]`, `y ∈ [высота−3, высота]`. **Ширина полосы — 4
   пикселя.** Углы дают диагональные направления.
3. Темп: `последний_шаг + [mapGraphics+0x40] > текущее_время` → шага нет. `[mapGraphics+0x40]` — это
   `ScrollSpeed` из ini (`0x540b60` ← `0x61a27b`), то есть **задержка в миллисекундах между шагами по клетке**.
   Потолок 100 (`0x61a2ec`), умолчание в коде 100, в поставляемом `Disciple.ini` — 0; комментарий там же:
   «0 - fast; 50 - normal; 100 - slow». В настройках игры это `SPIN_SCROLL_SPEED`, значение выбирается из
   заготовленного списка ближайшим (`0x4c14eb`). Список (`0x4bf30c`…`0x4bf389`): `100 + trunc(−100·доля)` при долях 0/.5/1 —
   100, 50, 0 мс, подписи `X005TA0117`…`0119` «Медлен./Нормал./Быстро» (`MapSettings.ScrollSteps`; в порте — задержка шага краем
   окна, стрелки без задержки).

**Клавиатура** (`0x5418fb`, обработчик нажатия): `VK_LEFT (0x25)` → 6, `VK_RIGHT (0x27)` → 2, `VK_DOWN (0x28)` →
4, `VK_UP (0x26)` → 0. Шаг делается сразу, задержка `ScrollSpeed` к клавишам не применяется — темп задаёт
автоповтор Windows.

**Перевод вида на клетку** (`0x540c38(клетка, dx, dy)`): начало вида = `мир(клетка) − область_вида/2 + (32,16) +
(dx,dy)`, затем сдвигается движок земли (`0x54272c`) и уведомляются слушатели прокрутки (`0x540d37`) — именно так
обновляется мини-карта. Выбор лидера кнопкой `BTN_NEXT_LEADER` центрирует вид этим вызовом **без** плавности
(`0x48ed72`: позиция объекта → `0x540c38`).

**Плавность (разбор 16.10, `CMidAnimSmoothScroll`; порт — `SmoothScrollPath`, `MapView.Scroll.cs`).** `SmoothScroll` (ini,
settings+0x17b, `0x61a5c1`) читается в задаче прокрутки (`0x4f4aed`, `0x4f4e36`), `StackSmoothScroll` (+0x17d) — в задаче хода
(`0x4f5d59`, `0x4f5e7c`); к ручной прокрутке оба не относятся. Задачу прокрутки ставит перед анимацией команды
`0x4f4a0c(игрок, …, клетка, без_проверки, только_если_далеко, система)`:

- без флага «без проверки» — сначала видимость окна клеток вокруг (`0x4f4ce9`, те же 9 клеток, что у литья): не видно — ни прокрутки, ни
  анимации команды;
- «только если далеко» — клетка центра вида (`0x540b6c`) и цель расходятся на 2 и больше по одной из осей (`0x4f4a7c`, `jge`);
- кто ставит и с какими флагами (`0x4f2ad0`, разбор по целям приведения): `BattleStart`, `StackIllusion`, `StackDestroyed`, `NobleAction`,
  `CityGrow`, `RemoveLMark`, `MapChange`, `TerrainChange`, `LootRuin`, `RmvRiot`, `ChangeOwner`, `CreateStack`, `PickupBag`, `ChangeLandmark` —
  «только если далеко»; `CastSpell` — всегда (`0x4f3301`, `0x4f33e4` — второй без проверки видимости); `ChangeFog` — «только если далеко»,
  без проверки (`0x4f351d`); ход отряда — перед каждым видным куском пути, к его началу (`0x4f7dbc` → `0x4f7f9b`);
- задача в быстрой группе (33 мс, `0x4f4920`): старт (`0x4f4e19`) при выключенном флажке ставит вид на цель сразу (`0x540c38` без
  сдвига), при включённом — первое положение списка; шаг (`0x4f4dac`) — следующее положение (центр — середина цели плюс сдвиг из головы
  списка), конец — список пуст;
- список (`0x4f4b51`): клетки совпали — пуст; иначе отрезок `0x51f452` от сдвига «центр вида − середина цели» до нуля, с начала — точки
  0, 4, 12, 24, … (шаг +4 до 128), пока номер меньше половины длины, с конца — симметрично. Пример: 400 точек по оси — 20 положений,
  19 тиков (≈0,63 с).

В порте прокрутка — перед ходами отрядов ИИ (и перед видными кусками после тумана), перед событиями хода ИИ и действиями человека из очереди
эффектов (литьё — всегда, прочее — если дальше 2 клеток), перед ходом своего отряда; показ ждёт её конца (`SpellPlaying`).
«Следующий лидер», мини-карта, стрелки и край окна — без плавности. Проверка — `ui-render-check` «плавная прокрутка» (положения по тикам
против своего пересчёта, тик ≥ 33 мс, флажок выключен — прокруток 0).

## 3. Содержимое панелей

### 3.1 `DLG_STRATEGIC` (160×397)

Элементы по `Interf.dlg`: `IMG_LEADER` (8,75…78,160 — 70×85), `TXT_LEADER_NAME` (12,163…150,181),
`TXT_LEADER_STATS` (82,75…155,158, выравнивание `\hC;\vC;`), `TXT_TURNNB` (65,196…100,216), кнопки
`BTN_CAPITAL`, `BTN_CAST_SPELL`, `BTN_CONT_MOVE`, `BTN_DIPLOMACY`, `BTN_DROP_ROD`, `BTN_END_TURN`,
`BTN_EXCHANGE`, `BTN_GUARD`, `BTN_NEXT_LEADER`, `BTN_WAND_SCROLL`.

**Портрет и имя.** `0x48d688` по выбранному объекту заполняет `IMG_LEADER` картинкой, полученной через
`0x5340b9/0x50afe3` с номером слоя 9; имя — `0x5e97dc` от объекта. Портрет отряда (`0x48d8f3`, разбор 17.10, `docs/ui-windows.md` §26):
лицо `CFaceImgImpl` (`0x5b1e6a`) **отражено** (`setLeftSide(0)`, `0x48da79`; снимок оригинала — 4,9 против 37,4 без отражения); лидер
жив — доля здоровья `hp·100/max` (нижняя потерянная доля наполовину красным), **павший — состояние 10: маска-череп `MASKDEADS`** поверх
лица (`0x48dac5`); поверх — значки усиления (0, 0), зелья (0, 28), ослабления (0, 56) по цепочке лидера (`0x5ea500`) и высокого уровня
по центру сверху (`0x61ea4c`), составная картинка `0x5b4f54`. Текст `TXT_LEADER_STATS` у павшего тот же. Порт — `PanelFace`,
`MapScreen.PanelFaceImage`; гость панели столицы (`0x486a6f`) — та же маска и доля без значков (`CapitalGuestFace`). Имя архива в этом месте не встречается: путь
идёт через общий загрузчик картинок интерфейса, а не через прямое имя файла — **какой архив и какое имя, здесь не
доказано** (см. «Не закрыто»).

**`TXT_LEADER_STATS`.** Для отряда (`0x48dc4e`) строка собирается из шаблона **`X005TA0396`** =
`Движение:\n%COLOR%%MOVE1% / %MOVE2%`:

- `%MOVE1%` — байт `[отряд+0x98]` (остаток очков хода);
- `%MOVE2%` — `0x5ed035` (полный запас хода отряда);
- `%COLOR%` — `X005TA0397` (`\c000;000;000;`, чёрный), если `%MOVE1% > 0`, иначе `X005TA0398`
  (`\c150;000;000;`, красный).

Для второго случая (`0x48e156`) используется шаблон **`X005TA0399`** = `\hL;\c000;000;000;%NAME%` с подстановкой
`%NAME%` — это ветка, где у объекта есть только имя.

**`TXT_TURNNB`.** По событию 0x1b (`0x490b88`) в элемент пишется число, полученное `0x5e42a0 → 0x47a91a`
(номер дня), переведённое в строку `0x51eb5e`. Шаблон `X005TA0935` (`\fLarge;\hC;\vT;\c255;255;255;\o000;000;000;%TURN%`)
в этом месте **не подставляется** — строка в элемент кладётся как есть, а оформление задаёт сам элемент в `.dlg`.
Где применяется `X005TA0935`, здесь не прослежено.

**Кнопки.** В конструкторе (`0x48fc60…0x48ff90`) каждой кнопке ставится обработчик, и четыре сразу выключаются
(`setEnabled(false)`, vtable +0xa0): `BTN_GUARD` (`0x48fcdd`), `BTN_DROP_ROD` (`0x48fd34`), `BTN_CONT_MOVE`
(`0x48fdd3`), `BTN_WAND_SCROLL` (`0x48feba`). `BTN_NEXT_LEADER`, `BTN_EXCHANGE`, `BTN_CAST_SPELL`,
`BTN_DIPLOMACY`, `BTN_CAPITAL`, `BTN_END_TURN` в конструкторе не выключаются.

Дальше состояние пересчитывается при смене выбора:

| кнопка | включается | адрес |
|---|---|---|
| `BTN_WAND_SCROLL` | выбран **отряд** (тип 0x23) **и** проверка `0x48de96` по отряду (что именно проверяется, не разбиралось) **и** идёт ход игрока (`phaseGame->data+0x28`) | `0x48de33` |
| `BTN_EXCHANGE` | сначала выключается всегда; включается, если идёт ход игрока и выбран отряд (дальше проверяется соседний отряд) | `0x48df76` |
| `BTN_GUARD` | в ветке отряда: по результату поиска объекта в списке `phaseGame->data+0x34` (`0x41a4e1`); включена, когда поиск пуст | `0x48dd67` |
| `BTN_NEXT_LEADER` | по двум проверкам того же списка (`0x41a4e1`, `0x41a44e`) — есть ли ещё отряды с ходом | `0x48eb51…0x48ebd6` |
| `BTN_CONT_MOVE` | отдельной процедурой `0x4d2346`: находит `DLG_STRATEGIC` и выставляет состояние; вызывается из задачи движения (`0x4d2213`) | `0x4d2346` |
| `BTN_CAST_SPELL`, `BTN_CAPITAL`, `BTN_DIPLOMACY`, `BTN_END_TURN` | явного `setEnabled` в разобранных местах нет | — |

Смысл списков `phaseGame->data+0x34` (`listPtr` в тулсете) не разбирался, поэтому условия `BTN_GUARD` и
`BTN_NEXT_LEADER` описаны механически.

### 3.2 `DLG_ISO_RESPOPUP` (640×600, полоса вверху)

Шесть текстов шириной 40, высотой 25 в строке `y = 0…25`: `TXT_ORANGE` (370), `TXT_BLANC` (410), `TXT_JAUNE`
(450), `TXT_ROUGE` (490), `TXT_BLUE` (530), `TXT_GOLD` (571). Заполняет `0x4891bb`: у объекта игрока берётся банк
(`игрок+0x70`), значение ресурса — `0x586a2e(банк, номер)` (int16), формат `"%d"` (`0x6d4534`):

| элемент | номер ресурса | ресурс |
|---|---|---|
| `TXT_GOLD` | 0 | золото |
| `TXT_ROUGE` | 1 | адская мана |
| `TXT_JAUNE` | 2 | мана жизни |
| `TXT_ORANGE` | 3 | мана смерти |
| `TXT_BLANC` | 4 | руническая мана |
| `TXT_BLUE` | 5 | мана рощи |

Порядок ресурсов сверен с тулсетом (`resourcetype.cpp`, GOG-адреса `0x8381b8…0x838208`). Каждый элемент
обновляется, только если он есть в диалоге (`0x50b70a`), поэтому та же процедура годится и для
`DLG_ISO_GOLDPOPUP` (там только золото).

Показ/скрытие — `0x489093` (обработчик `TOG_RESPOPUP`): состояние пишется в `[0x835a7c]`, при включении
показывается `DLG_ISO_RESPOPUP` (или `DLG_ISO_GOLDPOPUP`, если поднят признак `[view+0x48]`), при выключении
диалог снимается. Начальное состояние — 0 (`0x488f96`), при показе панели переключателю оно возвращается
(`0x4889a7`).

### 3.3 `DLG_ISO` (640×600)

Три элемента: `IMG_ISOAREA` (весь экран), `IMG_SENDER` (15,490…42,510), `TXT_CHAT_AREA` (45,490…368,507).
**Ни одной из строк `TXT_CHAT_AREA`, `IMG_SENDER` в `Discipl2.exe` нет**, а указатель на `IMG_ISOAREA`
(`0x799fa0`) ни разу не используется — по именам эти элементы движок не ищет. Сам диалог создаётся по имени
`DLG_ISO` (`0x4880e4`) и служит подложкой области карты. Строки чата выводит `CIsoChatDisplay` (`0x486c3c`,
vtable `0x6d4174`), который держит очередь не длиннее 5 сообщений (`0x48727b`: при 5 снимается старейшее) и
рисует их сам. Куда именно — не разбиралось. Строка — оформление `X005TA0703` (`0x4872fb`), живёт 10 с с первого показа
(`0x4875ff`, `+0x2710`). Сюда же движок пишет строки записи партии (`X005TA0581`/`X005TA0582`, `docs/day-cycle.md` §21а); порт —
`IsoChatLogic`, последняя строка в `TXT_CHAT_AREA` (ранг 2).

## Для порта

- Мини-карту разумно повторить один в один: растр `4N × 2N`, точка `(2(x−y) + W/2, x + y)`, блок 4×2 по маске,
  выборка из `ISO*` по `mod` размера узора. Тогда картинка совпадёт с оригиналом попиксельно, без таблицы цветов.
- Порядок слоёв: вода и берег → земля → значки (по слоям 0…4) → туман. Туман продлевается на 5 клеток за край.
- Окно 150×132 показывает растр со смещением «центр вида в центре окна»; белая рамка — прямоугольник
  фиксированного размера по разрешению. Для Godot это просто `TextureRect` с обрезкой и смещением.
- Щелчок — центрировать вид на клетке; протаскивание — сдвиг на разницу в клетках, направление зависит от
  настройки `InversedPalMap`. Зоны трёх кнопок из обработки мыши исключить.
- Прокрутка: шаг ровно в клетку `(32,16)`, зона у края 4 пикселя, интервал `ScrollSpeed` мс, ограничение —
  по центральной клетке вида, а не по краю экрана. Плавность нужна только для автоматических переводов вида.
- `TOG_BANNERS` и Shift дают один и тот же результат — включение значков-знамён (`docs/map-render.md`, слой
  `BANNERS`).
- Строки: `X005TA0396` (ходы отряда), `X005TA0397`/`X005TA0398` (цвет), `X005TA0399` (имя), ресурсы — просто
  `%d`.

## Не закрыто

- Попиксельной сверки мини-карты с кадром игры нет: нужен снимок `DLG_ISO_PAL` на известной карте и известном
  положении вида.
- Не проверено на глаз, что у крупных карт мини-карта действительно обрезана (из кода следует именно это).
- Картинка `IMG_LEADER`: панель отряда `0x48d8f3` берёт её у `0x5b1e6a` (вызов `0x48da55`) по типу лидера, а та — у **базового**
  типа (`vtable+0x2c`, `Gunits.BASE_UNIT`; пустой `[0x8372f4]` — сам тип), как портреты окон (`UnitFaces.SmallName`). У 100 типов из
  356 своего `FACE` в `Faces.ff` нет (лидер-ассасин сценария `G000UU5354` → `G000UU0154FACE`; пометка 1 прогона 14.10). Точное
  составление имени внутри `0x5b1e6a` (суффикс `FACE`) по коду не дочитано — порт берёт малый `FACE` по описи графики.
- Где применяется шаблон `X005TA0935` (`%TURN%`) — не найдено; в `TXT_TURNNB` кладётся голое число.
- Условия `BTN_GUARD` и `BTN_NEXT_LEADER` опираются на список `phaseGame->data+0x34`, содержимое списка не
  разбиралось. У `BTN_CAST_SPELL`, `BTN_CAPITAL`, `BTN_DIPLOMACY`, `BTN_END_TURN` управление состоянием не
  найдено.
- Список допустимых значений `SPIN_SCROLL_SPEED` в настройках (`0x4c14eb`) не разобран — известен только потолок
  100 и смысл «миллисекунды задержки».
- Глобаль `[0x8372f4]`, с которой `0x5cb3e5`/`0x5cb456`/`0x5cb5a1` сравнивают поле объекта перед постановкой
  значка на мини-карту, не опознана.
- Куда `CIsoChatDisplay` рисует текст и картинку отправителя (использует ли он вообще координаты `DLG_ISO`) — не
  разбиралось.
