# Начало новой одиночной партии из сценария (GOG 3.01) — что делает движок

Ранги: 1 — доказано кодом движка и/или данными без исключений; 2 — согласуется с данными, код не дочитан;
3 — гипотеза. Exe — `game-pristine/Discipl2.exe` (тот же размер 4474880, что в журналах зонда).

**Главная поправка к исходным данным.** Игра грузила **русский** сценарий `game-dev/Exports/Power to Corrupt.sg`
(475 569 байт, 2004 г.), а не английский `game-pristine/Exports/...`. Против русского файла дифф дня 1 короткий
(`diff-dwarf-dev.txt`, `diff-legions-dev.txt`); почти всё «изменённое» против pristine — это локализация.

## Точка входа в код

`CMidServerLogic`, слот vtable `0x6ce0c0` → **`0x421667`**. На первом ходу (`0x47a91a`: CUR_TURN == 0) цикл по всем
`NetPlayerInfo` (`0x42923b` — число, `0x42927f` — i-й; список сервера `+4 → +0x30`, переставленный при старте `0x42b8ab` → `0x42b8e8` → `0x432165` — очередь дня: хозяин, затем по ключу расы `0x42e1fe`, не по id; журнал `20261018b-port-synth`, карта 16: новые лидеры UN001d человеку, UN001e Легионам PL0002, UN001f Кланам PL0001, UN0020 Нежити PL0003), для
играбельной расы:

1. `0x4220eb` — **замена стартового лидера** (у тулсета это `changeStackLeaderInCapital`, GOG `0x4220eb`);
2. `0x421f2f` — **бесплатная постройка по категории лорда**;

затем только для локального игрока-человека (`0x429291` → его `NetPlayerInfo`):

3. `0x421d6a` — только на Лёгкой: копия зелий в инвентаре столицы (4 категории предметов; см. отчёт H);
4. `0x421b2c` — если имя игрока `Calamity` (XOR-строка 0x24), то `0x5e6b90(1, map, 1)` (пасхалка; действие не разбирал);
5. если флаг `0x4292f9` сброшен (не хотсит/сеть): `0x421be0` — **множитель казны по сложности**.

Ветка `0x4217a0` делает п. 1–3 для партий, где флаг `0x4292f9` взведён (хотсит): в корпусе у хотсита
(`20260920-ui`, партии S092 и S135) постройки есть, строки `bank` нет.

## 1. Тип стартового лидера по категории лорда — ранг 1

`0x4220eb`: `0x5e471a(player)` → категория лорда; сравнение с `LLordCategory.id` GOG (тулсет `lordcat.cpp`):
воитель `0x837750` → `L_FIGHTER` (`0x837a18`), дипломат (Гильдмастер) `0x837778` → `L_EXPLORER` (`0x837a38`),
иначе (маг) → `L_MAGE` (`0x837a28`). Имена категорий — таблица `0x58bcb3`: указатели `0x7ac55c..` = `L_FIGHTER`,
`L_EXPLORER`, `L_MAGE`, `L_ROD`, `L_NOBLE` (`LLeadC.dbf`).
Затем список найма лидеров `getLeadersHireList` (`0x5d475e`: `Grace.LEADER_1..4` + `NOBLE`) и **первый** юнит,
чей `Gunits.LEADER_CAT` равен этой категории (`0x4223a9`).

По таблицам всех играбельных рас LEADER_CAT = 1,2,3,4,5 у LEADER_1..4, NOBLE, поэтому:

| Лорд (Glord.CATEGORY) | Категория лидера | Поле Grace | Пример |
|---|---|---|---|
| 1 воитель | L_FIGHTER (1) | LEADER_1 | G000UU0019/0044/0070/0096/8009 |
| 2 гильдмастер | L_EXPLORER (2) | **LEADER_2** | Империя G000UU0020 (HP 90, MOVE 35) — ai-g2, ai-q43, f7-m6 |
| 0 маг | L_MAGE (3) | LEADER_3 | гномы G000UU0046 (HP 95) — rastlennaya-vlast-dwarf |

Для порта: не хардкодить LEADER_N, а искать по `LEADER_CAT` в порядке LEADER_1..4, NOBLE (так моды с другим
составом рас тоже будут работать).

## 2. Какой отряд, что у нового лидера, что со старым id

- **Отряд** (ранг 1, код): `0x5e9450` FindCapitalByPlayerId → `capital.stackId` (отряд, стоящий в столице).
  Нет отряда (пустой id) — выход; `CMidUnitGroup::getUnitsCount` (`0x5f4441`) ≠ 1 — выход, то есть лидер
  заменяется, **только если в отряде столицы стоит один лидер**. Отряды вне столицы не трогаются
  (KC0069 Легионов, KC0025/26 в ai-g2). В начале функции есть ещё проверки импорта лидера кампании (`0x421335`,
  `0x4221bc`), они не разобраны. Это делается для **всех** игроков рас, ИИ тоже (данные: 4/4 столицы PtC, все карты обзора).
- **Создание** (ранг 1): уровень = `ScenarioInfo.SUGG_LVL` (`0x45f9cc` = `+0x70` suggestedLevel);
  `CUnitGenerator` `+4` generateUnitImplId(тип, уровень), `+8` generateUnitImpl; `ChangeStackLeader` (`0x5e77bf`)
  ставит нового лидера на место старого (та же клетка отряда, `POS_*` не меняются).
- **Id** (ранг 1, данные): новый `MidUnit` получает следующий свободный id (max+1: PtC `UN01f7` → `UN01f8..01fb`,
  f7-m7 `UN0001` → `UN0002`, ai-q09 `…0244` → `0245..0248`); сначала человек, потом ИИ. Старая запись юнита
  **удаляется** (число MidUnit не меняется: 278 → 278).
- **Поля нового юнита** (ранг 1, данные): LEVEL = SUGG_LVL, HP = полное HP типа на этом уровне (UU0046 95; UU0019 L3 180,
  UU8009 L3 165), XP 0, модификаторов нет, CREATION 0, TRANSF 0, DYNLEVEL 0.
- **Отряд** (ранг 1, код + ai-g3/q30/q34, где SUGG_LVL 3): `0x5e8b10(stack, SUGG_LVL)` → `CREAT_LVL` = SUGG_LVL (1 → 3);
  `n = min(SUGG_LVL, GVars.LDRMAXABIL(+0x4c)) − 1`, при n > 0 `0x5e8513(stack, n)` → `UPGCOUNT` = n
  (у ИИ `upg 2`, человек выбрал 2 навыка: G000UM4006 Leadership, G000UM4007 Boots Lore).
- **Имя** (ранг 1 для ИИ, ранг 2 для человека): `0x5e97dc(старый юнит)` → имя старого лидера, `0x5e768f` пишет его
  новому, поэтому у ИИ имя сохраняется (Адроберт, Бергезен, Хуунрех, Eraric, Thorne…). У человека имя **другое**:
  случайное мужское имя расы из `Tleader.dbf` (все 10 разных имён из корпуса есть в списке: Charulf, Begrezen, Virgile, Merlot,
  Savary, Urbain, Renard, Rainon, Winfrid, Wolfgar; разные в разных партиях). Откуда бросок, не найдено: это не первый
  `crt_rand` (он всегда 41), и не R250 после reseed `new_game_time` (перебор 0..600 шагов, общего смещения нет,
  `name_rng2.py`). Скорее всего имя выбирает клиент в окне лорда (ранг 3).
- **MOVE**: сама замена MOVE не трогает. На старте дня 1 `ap_restore` доводит ход **отрядов человека** до максимума
  по новому лидеру (дварф KC0001 15 → 20, KC0069 Легионов 20 → 25, гильдмастер 20 → 35). Отряды ИИ в t01-001
  остаются как в файле, потому что их ход ещё не начался.

## 4. Казна на старте

Цепочка для дварфа-человека: файл G200/100×4 → **до сервера уже 400/120×4** → `0x421be0` ×1 → доход дня 1
+150 золота и +125 рун → 550/245 (сохранение).

- **Множитель по сложности** (ранг 1 по коду; данные только для Средней): `0x421be0` берёт
  `GVars.BONUS_{E|A|H|V}` (`0x587915`: `+0x108/0x10c/0x110/0x114`, категории сложности GOG `0x837988/9b8/9a8/998`),
  делит на 100 **целочисленно** (`idiv 100`) и умножает на это каждую из 6 валют казны локального человека,
  затем `CVisitorChangePlayerBank` (mode 0, «присвоить»; в журнале это `bank` с before == after).
  При таблицах ванили множитель равен 3 на Лёгкой, 1 на Средней и **0 на Высокой и Очень высокой**
  (50/100 и 25/100 при целочисленном делении дают 0, казна обнуляется). На Лёгкой/Высокой прогонов нет, поэтому
  эмпирически это не проверено. У ИИ и в хотсите вызова нет.
- **Доход дня 1** (ранг 1): это ровно `Economy.DailyIncome` порта при INCOME_A = 0 %. Дварф: столица 100 зол. + 25 рун,
  жилы на своей земле (terrain 2): CR0002 золото +50, CR0017 и CR001c руны +50+50 → 150 / 125. Легионы: только
  столица (100 зол. + 25 адской маны). Начисляется в начале хода человека, до автосейва t01-001.
- **+200 золота и +20 каждой маны до сервера — `SPELL_BANK`** (ранг 1, седьмой круг, `docs/day-cycle.md` §17): при занятии места
  человеком `CVisitorChangePlayerType` (`0x60befe`, сервер `0x42ae90`) вливает казну ИИ на заклинания в казну и обнуляет её; у всех
  игроков Power to Corrupt `SPELL_BANK` = 200/20. Старты `ng-diffgame` с `DIFFGAME` 0 и 2 дают одну казну (650/75) — гипотеза ниже
  отпала. Порт — `NewGame.Retype`. Прежний разбор (до 27.09): Видно во всех 6 стартах Power to Corrupt
  (дварф 200→400, Легионы/Империя/Нежить 300→500, мана 100→120), а на остальных стартах корпуса (f7, ai-*, Fardale's Web; 26 партий в журналах)
  его нет. Прибавка не идёт через визитор казны и появляется раньше `0x421667`. Ни `BONUS_*`, ни `INCOME_*`
  больше нигде в коде не читаются (побайтовый поиск геттеров), строки банка «0200/0020» в exe нет. Единственное
  отличие, которое видно: в файле PtC `DIFFGAME = 0` (Лёгкая), у остальных карт 1. В сохранении 1.
  Гипотеза: клиент при выборе сценария пересчитывает казну человека из сложности файла в выбранную
  (+200 = BONUS_E − BONUS_A, +20 = то же / 10). Как проверить: синтетическая карта с `DIFFGAME = 0` и с
  `DIFFGAME = 2`, старт на Средней, сравнить казну в первой строке `bank`.
  Проверено 23.09: у всех сценариев `Exports` в файле `CUR_TURN = 0` (нулевой ход, в который никто не ходит, —
  со слов пользователя), а прибавка есть только у Power to Corrupt (`DIFFGAME 0`) и её нет у Fardale's Web
  (`DIFFGAME 1`); в журнале она видна уже в первой строке `bank`, строки `income turn=0` нет, и она одинакова у всех
  рас (доход расы разный). То есть это не доход нулевого хода; остаётся гипотеза пересчёта из сложности файла.
- **Казна ИИ в t01-001 не меняется** (ранг 1): 300/100×4 как в файле, множителя у ИИ нет, дохода ещё не было.

## 5. Что ещё меняется

Логика игры:
- `ScenarioInfo.CUR_TURN` 0 → 1; `DIFFGAME` становится выбранной в меню сложностью (PtC 0 → 1, в меню её не трогали,
  значит, по умолчанию Средняя — ранг 2).
- Игрок-человек: `IS_HUMAN` 1, `LORD_ID` выбранный, `FACE` выбранный, `NAME_TXT` введённое имя (у Легионов с ведущим
  пробелом, «␠Betreazen»), `DESC_TXT` = `Tplayer.TEXT_M` расы (текст из `game-dev/Globals`, английский). У ИИ
  LORD/NAME/DESC остаются из файла.
- **Бесплатная постройка** (ранг 1): `0x421f2f` сначала снимает все постройки игрока (`0x421fb6`: цикл
  `0x5e6d64`; в данных не видно, во всех сценариях PB пустые), потом через `0x42200a` берёт первую по порядку id
  постройку нужной категории из `GbuiList` лорда: маг → `L_MAGIC` (`0x837a00`), гильдмастер → `L_GUILD`
  (`0x8379e0`), воитель ничего не получает. У каждой расы такая постройка одна: башня 0024/0048/0073/0098/0119,
  гильдия 0025/0049/0074/0099/0120. Данные: дварф-маг BB0048, Империя-маг BB0024, Империя-гильдмастер BB0025
  (строки `build` с id2 G000000000, без `bank`). В порте стартовой башни/гильдии нет (так отмечено и в отчёте E).
- События дня 1 человека (раса-фильтр, условие частоты 1) срабатывают до автосейва: `EV001d`/`EV0002`
  (`OCCUR_ONCE`) получают `ENABLED` 0, в `MidQuestLog` появляется по записи на каждый попап
  (`seq_num`, `cur_turn 1`, `type 0`, `eff_num`). Это обычная обработка начала хода, не инициализация.
- `ap_restore` отрядов человека (см. п. 2). Земля (`MidgardMapBlock`), дипломатия, лавки, руины, жилы, заклинания,
  талисманы и события ИИ в t01-001 не меняются.
- Rng: `rng_seed cause=new_game_time` (`0x429dcd`) пересевает R250 от времени; затем один `crt_rand` (`0x548587`, r=41).

Формат/локализация (для порта игнорировать):
- Против pristine: все русские тексты, `DYNLEVEL` у MidUnit, `P_O_EL` у деревень, `ALWAYSAI`/`EXMAP_*` у
  MidPlayer, `grove` в банках, пустые `MidScenVariables`/`TurnSummary`/`MidQuestLog`. В русском файле `game-dev`
  всё это уже есть.
- `BRIEFLONG1..5` перерезаны на куски по 254 байта с `_` на конце; текст тот же.
- `MidgardPlan` пересортирован (f7-m7: множество записей то же, 42 = 42).

## 6. Номера id объектов: счётчики карты — ранг 1 (листинг + журнал)

**Движок.** Номер нового объекта даёт карта сценария сервера `CMidgardScenarioMap` (vftable `0x6eebb4`): слот 9 `0x5ee8bd`
`(out, тип)` берёт `[this+0x30+4·тип]` и пишет туда +1 (строка зонда `id_alloc`), слот 10 `0x5ee900` — тот же номер без сдвига,
слот 11 `0x5ee8f1` — запись счётчика. **В файле счётчиков нет.** Загрузка `0x4297e3`: чтение карты `0x5eea31` (`0x429851`) берёт
запись самой карты (id типа `0x17`, число объектов `+0xc`) и объекты (`0x5eeb79`/`0x5eec7f`) — массив `+0x30` не трогает; затем
`0x4298a6` → `0x5ee996`: `memset(this+0x30, 0, 0xec)` и по каждому объекту (`0x5ee30f`/`0x5ee329` — обход) тип `0x57f3b6`, номер
`0x57f3d2`, `if (счётчик <= номер) счётчик = номер + 1` (`0x5ee9f6`…`0x5eea01`). Дальше за сессию счётчик только растёт.
Отсюда: **без перезагрузки** номер снятого объекта движок не выдаёт (ai-q09 день 3, `KC0095` → наём `KC0096`, §29
`docs/ai-tactic-candidates.md`); **после загрузки** сохранения номера объектов, которых в файле нет, снова свободны —
`20261014-replay` passive-001: могила `S135TB0000` выдана в партии до загрузки (seq 2585338, после последнего сохранения) и снова
после `game_phase load` (2646745). Новая игра — то же чтение: первая выдача каждого класса = наибольший номер сценария + 1
(у замены стартового лидера, §2, — `UN003e…UN0041` на карте 1 прежней сборки).

**Порт.** Счётчик — `MapState.IdNext`, выдача — `GameSession.NewId` (найм, призыв в бою и на карте, отряд события, жезл,
мешок, экземпляры предметов). Три входа считают счётчики заново, как `0x5ee996`, — в файлы они не пишутся:
- `.sg` — `MapLoader` (по всем объектам файла);
- сохранение порта — `GameSave.FromJson` (`GameSession.IdNextOf` по объектам модели);
- сценарий порта (`data/scenarios`, слои модов) — `ScenarioFile.FromJson`. **До 18.10 здесь счётчиков не было** (`IdNext`
  не сериализуется), и новая партия порта шла по запасному правилу «наибольший из живых + 1»: номер класса, наибольший объект
  которого пал до первой выдачи этого класса, порт отдавал снова, движок — нет (`IdNextLoadTests.NewGame_DoesNotReuseNumberOfStackLostBeforeFirstHire`:
