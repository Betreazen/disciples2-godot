# Экономика ИИ из карты: найм лидеров, рост деревень, навык лидера, исследование (срез 3; 23.09.2026)

Разбор `Discipl2.exe` (GOG 3.01) и сверка с корпусом (`20260919-human`, `20260920-legions`, `20260918-probe65`).
Ранги: 1 — листинг, 2 — выведено (листинг + корпус), 3 — догадка. Код: `src/D2.Data/Play/AiEconomy.Leaders.cs`,
действие `GameSession.HireLeader` (`GameSession.City.cs`). Правила выбора (`PickByShare`, `PickLeader`, `RankCities`) —
`src/D2.Rules/Map/AiStrategicRules.cs`, сверены с журналом раньше (600 вызовов probe65).

## 1. Построитель `0x44a7c2` (ранг 1)

```
нейтрал → ничего (0x5e4e73)
счётчики c = 0x44a405(игрок); допуски; доли 0x44ac95; пределы 0x44a71e (только при уровне сценария ≥ 10, 0x61eb31)
для каждого города по порядку 0x44809c (слабейший гарнизон + гость — первым):
    есть гость (+0x8c) → пропуск
    роль = PickByShare(допуск (1, жезл, вор), счётчики (бойцы, жезлы, воры), доли PCT_FIGHTR/ROD/THIEF·0,01, ответы (0,1,2))
    вор:   предел T_MAX → пропуск; подприказ = PickByShare((помощь, обычный, кража), счётчики, (0,5; 0,3; 0,2), (1,0,2))
    иначе: предел L_MAX/R_MAX → пропуск; подприказ = PickByShare((1, помощь, защита города), счётчики, (0,4; 0,4; 0,1), (0,2,1))
    помощь = вор и подприказ 1, или боец и подприказ 2
    тип = PickLeader(лидеры расы, роль, казна, помощь, R250)   # бросок — при каждой сборке списка
    тип пуст → конец перебора
    бюджет типа 0 не пускает (0x4465ba) → пропуск
    счётчики += (будто нанят); оценка с приоритетом города (id оценки — город, память дня)
```

Исполнение `0x44b09f`: проверка `0x5de921` (в журнале всегда 0), имя — CRT `rand()` по мужским именам расы
(косметика), найм `0x41ef71`: отряд-гость в укреплении, лидер своего уровня с полным здоровьем, приказ `L_NORMAL`,
приказ ИИ — подприказ, запас хода 0.

## 2. Входы

- **Счётчики `0x44a405`**: свои отряды с приказом `L_NORMAL` (`+0xa8`), лидер своей расы (`Gunits.RACE_ID`), роль
  `0x44a6e0` (призыв — не считается; вор; жезл — способность `0x837618`; иначе боец). У бойца — по приказу ИИ (`+0xb8`):
  защита города / помощь / прочие; у вора — кража / помощь / прочие.
- **Допуски**: вор (`0x44a232`) — в списке лидеров найма (`0x5d475e`) есть вор, а вор туда кладётся только при гильдии игрока
  (`0x5d4857`: `0x41b399` → `0x5f94a7` категории `0x8379e0`; карта 21 — Кланы строят гильдию проходом 8 дня 1, Нежить — проходом 9, вора обе нанимают днём 2,
  `r19b/m21`); помощь (`0x44b1d7`) — есть боец с обычным приказом;
  защита города — защитников меньше, чем своих деревень («угрозы» `0x474072`); кража — на карте есть лавка
  (`0x601e55`). 30.09, ранг 1 по листингу: жезл (`0x44a207`) от расы не зависит — на карте есть кристалл (`0x44b545`: число объектов
  типа 0x2c, `iterator_omap<0x2c>`) или событие, чей последний эффект `L_WIN`, а среди условий `L_TRANSFORM_LAND` (`0x5f2701`,
  категория `0x837df0`); «обычный вор» (`0x44b1d7` → `0x44b282`, флаг — отрицание результата) — есть другой не нейтральный игрок,
  ещё не разведанный (`0x5e46c2`, `MapPlayer.Spied`). В корпусе оба всегда 1 — харнессы не сдвинулись; тесты `AiLeaderFlagsTests`.
- **Доли** (`0x44ac95`): роли — `GAI.PCT_*`·0,01 (константа `0x6cf6f0`); подприказы — константы.
- **Пределы** (`0x44a71e`, 28.09 ранг 1; зовут список 0 `0x44a8ce` и база бюджета `0x44a3a3`): `L/T/R_MIN/MAX` (поля
  `+0x38 +0x3c +0x44 +0x48 +0x50 +0x54`); действуют с уровня сценария 10 (`CScenarioInfo +0x70`); тогда движок берёт строку `GAI`
  `L_AI_SMALL` (`[0x8380a0]`, `LaiAtt` 0) у всех игроков, и у лорда-дипломата (`L_DIPLOMAT`, `[0x837778]`) `T_MAX` + 1
  (`AiStrategicRules.LeaderLimits`, тест `AiStrategicTests.LeaderLimits_HighLevelSmallRowAndDiplomat`; корпус уровня 1 — сверить нечем).

Сверка входов (`AiLeaderHireHarnessTests`, первый вызов каждого вида в проходе): допуски — все (human 232 + 59 + 177,
legions 272 + 48 + 230); счётчики роли 226/232 и 262/272, подприказов 177/177, 224/230, 58/59, 48/48. У зонда имена
функций подприказа переставлены: `fighter` — это `0x44b6f3`, подприказ вора.

## 3. Базы бюджета списков (ранг 1 по листингу, 26.09)

`pct = min(база + 5·дней без траты, 100)`; базу три списка считают сами (слот 2 списка), прочие берут `GAI.B_*`
(`AiStrategicRules.*BudgetBase`, в партии — `AiEconomy.BudgetRules`):

| Список | Функция | База |
|---|---|---|
| найм лидера | `0x44a339` → `0x44a053` | бойцов нет — 100; бойцов меньше `L_MIN`, воров меньше `T_MIN` при допуске вора (`0x44a232`) или жезлоносцев меньше `R_MIN` при допуске жезла (`0x44a207`) — 90; бойцов меньше `L_MAX` (на уровне 10 ещё воров меньше `T_MAX`, жезлоносцев меньше `R_MAX` при допуске) — `B_LEADERS`; иначе 0 |
| столица | `0x446a48` | нет храма (`0x5dcc28` == 2) или ни одного полевого лидера (боец, разведчик, маг; не `AI_IGNORE` — `0x446b59`) — 90; иначе `B_CAPITAL` |
| найм юнита | `0x44bba0` → `0x44bc09` | день 1 — 100; иначе `B_UNITS` |

«Первого дня» отдельно нет: 95 % у столицы и найма лидера в день 1 — это 90 + 5. Проверка (`AiTurnStartHarnessTests.DayBudget_ByType`):
найм лидера 371 из 375 (было 369 по правилу из журнала; дни без единого бойца сошлись), остаток — повтор дня после перезагрузки.

## 4. Итог за день (`AiTurnHarnessTests`, human)

Наймы лидеров «сохранение дня → `EndTurn` порта» против `hire_leader` журнала: из 59 дней с наймом у кого-то из них —
сошлись укрепление и тип 51, только укрепление 3, разошлись 5. Постройки (202/213) и найм юнитов (210/213) не изменились.

Харнессы тактики теперь применяют наймы лидеров из журнала (`AiLiveDay.HireLeader`), а свой найм порта в
воспроизведении выключен (`BeginAiTurn(hireLeaders: false)`), — отсюда сдвиг их чисел 23.09.

## 5. Рост деревень (список 3, `0x44972d`, ранг 1)

Свои деревни в порядке `0x44809c` (`AiEconomy.CityRank`, тот же, что у найма лидеров); рост разрешён `0x5dc62a`
(`Fortifications.CheckGrow`: размер, бунт, день прошлого роста, казна) и цена `0x5dc722` (`Treasury.CityGrowthPrice`)
в бюджете типа 3 (`AiStrategicRules.GrowCandidates`). Оценка — по деревне, память дня. Исполнение —
`GameSession.GrowCity` (общее с окном города человека). Бросков нет.

За день (`AiTurnHarnessTests`, human): сошлось 2, разошлось 2 — оба расхождения у Легионов в дни 38–41, где уже разошлась
постройка в столице (казна другая). 28.09: построитель столицы проверяет у здания юнитов казну и «сегодня уже строили»
(`0x446e37` → `getBuildingStatus 0x5dc9e8` с флагом `IgnoresCost`, статусы 3 и 6) — постройки 209 из 210, рост 4 из 4.

## 6. Навык лидера (список 1, `0x44ef81`/`0x44f0e6`/`0x44f3d2`, ранг 1)

Свои отряды с отложенным выбором (`upgCount +0x9a` > 0) в порядке отрядов карты; оценка — по отряду (память дня: один
навык на героя за ход). Предложение `0x5d8b84` — строки `GleaUpg` лорда с `MIN_LEVEL` ≤ уровня, ещё не взятые, в порядке
таблицы; фильтр `0x5e84c2` (`apply = 0`) отсекает навыки, дающие врождённую способность типа (`GLabi`). Выбор —
наибольший `PRIORITY`, первый при равенстве (`SkillChoice.ByAi`). Бюджет не проверяется, броска нет. Исполнение —
`visitorLeaderUpgrade` (`apply = 1`): `MODIF_ID` в цепочку лидера, `upgCount − 1`.

Порт: `GameSession.SkillOffer` и `GameSession.ChooseSkill` (`GameSession.Leaders.cs`, общие с окном навыка человека),
построитель `AiEconomy.UpgradeLeader`. `GameBook` теперь несёт `GleaUpg` и `GLabi`.

Сверка (`AiUpgradeLeaderHarnessTests`): журнальный `skill_offer` — список **до** фильтра врождённых; с ним совпали все
предложения (human 3, legions 5), выбор стратегии порта против `ai_exec` списка 1 — 5 из 5 ходов в каждой партии.

## 7. Исследование (список 6, `0x44ce1e`/`0x44d28a`/`0x44d30c`, ранг 1–2)

Только в день, кратный 5, и при известных < 12 (у мага < 15); заклинания лорда из `GspellR` в порядке таблицы, доступные
проверке `0x604039` (`GameSession.ResearchCheck`: в списке лорда, не известно, сегодня не исследовали — `RESEAR_T`,
хватает казны на цену; магу вдвое дешевле); выбор `AiStrategicRules.PickResearch` (уровень 1..4, внутри SUMMON → ATTACK →
HEAL → BOOST → LOWER, без `AI_CAT` = `L_AIS_NONE`). Цена — в бюджете типа 6. Исполнение `0x41e915` —
`GameSession.ResearchSpell` (общее с окном столицы): цена, известное, день.

«Раз в день» у ИИ — вывод: ни в одной партии корпуса ИИ не исследовал дважды за день, а память дня список 6 не держит.
Сверка за день (`AiTurnHarnessTests`, human): 21 из 21.

## 8. Повтор найма в харнессах

`AiLiveDay.HireLeader` нанимает по журналу при любой казне порта (цена — с обрезкой в ноль): раньше найм молча
отказывал, когда порт тратил золото иначе, чем движок (рост деревень, постройки), и отряд пропадал из воспроизведения.
После исправления: счётчики ролей 228/232 и 270/272, перемещений 633 и 737.
