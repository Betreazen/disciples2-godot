# Моддинг: видение и требования (PRD)

Рабочее пространство «Мод» в «Мастерской» и CLI `d2mod` ([`../README.md`](../README.md)). Формат слоёв сейчас —
[`docs/modding.md`](../../modding.md).

## 1. Зачем

Принцип проекта — устройство под моддинг ([`docs/principles.md`](../../principles.md) §2). Сейчас мод может заменить экраны,
кадры, графику мира и боя, строки, шрифты, ролики, карточки и файлы сценариев, данные карты. **Не может**: менять таблицы
правил (юниты, предметы, заклинания, постройки, ИИ — `data/rules`, `GameBook.Load(RulesDir)` читает только базу) и звук
(`data/sound`, `SoundAssets` — только база). Нет зависимостей и версий модов, проверки мода целиком, упаковки, горячей
перезагрузки.

## 2. Пользователи и сценарии

| Кто | Сценарий |
|---|---|
| модер-«балансер» | поднять урон юниту, цену предмета; увидеть «база → мод», проверить, сыграть бой |
| модер-«контентщик» | новый юнит: строка `Gunits` + атака `Gattacks` + имя и описание в строках + портрет и анимации боя + звуки; поставить его в город/наёмникам и на карту |
| художник (HD) | заменить графику кадров на высокое разрешение (размер берётся из файла) — уже работает, нужна проверка «все кадры описи на месте» |
| переводчик | слой `strings.<яз>.json` + переводы сценариев; отчёт «что не переведено» |
| автор кампании | мод = карты + кампания + свои юниты; упаковать и отдать |
| игрок | положить архив мода в `user://mods`, включить, увидеть конфликты и несовместимость до старта |
| агент | `d2mod validate/pack/run` без окна, числа и коды возврата |

## 3. Требования

| № | Требование | Приоритет |
|---|---|---|
| R1 | слой правил: мод добавляет и меняет строки таблиц `data/rules` по ключу | обязательно (K0) |
| R2 | схема таблиц: тип, смысл, ссылки (`ATTACK_ID → Gattacks`), пределы колонок | обязательно (K0) |
| R3 | `mod.json` v2: `version`, `gameVersion` (версия порта), `dependencies`, `conflicts`, `loadAfter` | обязательно (K1) |
| R4 | `d2mod validate`: ссылки, типы, обязательные элементы экранов, наличие файлов графики/звука, строки для новых id | обязательно (K1) |
| R5 | `d2mod pack`: архив с манифестом и хэшами; `d2mod install` в `user://mods` | обязательно (K2) |
| R6 | `d2mod run`: игра с модом (и без прочих), с картой | обязательно (K2) |
| R7 | слой звука | обязательно (K3) |
| R8 | окно «Мод»: дерево файлов слоя, таблица «база / мод / итог», конфликты слоёв | желательно (K4) |
| R9 | горячая перезагрузка экранов, строк, графики в идущей игре | желательно (K5) |
| R10 | точки расширения кодом (новая механика) | **вне набора**: это задачи `D2.Rules` с харнессами, П3 |

## 4. Границы

- Мод не меняет код и не грузит сборки .NET (вопрос пользователю: плагины-сборки или Lua позже? Рекомендация: нет до
  отдельного решения — безопасность и проверяемость; новая механика — в ядро порта).
- Поведение базы с модом, который трогает только графику/тексты, обязано совпасть с базой (харнессы С1/С2/Ф7 с таким модом —
  те же числа).
- Сетевая совместимость модов не нужна (сеть не переносится).

## 5. Мерила готовности

| Мерило | Значение |
|---|---|
| пример «новый юнит» | `mods/_examples/example-new-unit`: юнит в найме столицы и на карте, бой проходит, `validate errors=0` |
| пример «баланс» | `mods/_examples/example-balance`: правка 3 колонок 2 юнитов; `BattleSim` на эталонном бою даёт ожидаемо другое число, без мода — прежнее |
| регресс | `dotnet test` без модов и с `mods/_examples/example-plain-backdrop` — те же числа, кроме экрана примера |
| упаковка | `pack` → `install` → игра видит мод, `mods: <id>` в строке запуска |
