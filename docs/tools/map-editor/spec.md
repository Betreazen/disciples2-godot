# Редактор карт: спецификация

Что правится и как. Формат и общие правила — [`../data-contract.md`](../data-contract.md). Модель — `ScenarioData`
(`src/D2.Data/Play/ScenarioFile.cs`), `MapState` (`src/D2.Rules/Map/Model.cs`), события —
`src/D2.Rules/Map/ScenarioEventModel.cs`. Номера правил проверки — `MAPnnn` (§11).

## 1. Документ карты

- Открыть: сценарий из любого слоя (`GameContent.ScenarioPath`); из базы — только «Открыть копию в моде» (новый `Id`,
  П4); `.sg` — импортом (§13).
- Новая карта: размер 48/72/96/120/144 (как ScenEdit; в порте это не предел устройства — вопрос пользователю, пускать ли
  больше 144 только для карт порта; рекомендация: да, с запретом экспорта в `.sg`), земля по умолчанию, игроки (§7),
  `MapSeed` случайный.
- Сохранить: `<мод>/data/scenarios/<Id>.json` + карточка в `<мод>/data/game/scenarios.json` (имя, описание, размер, расы,
  сложность — как у `GameCatalog`) + переводы `<мод>/data/scenarios/lang/<яз>/<Id>.json`.

## 2. Рельеф

| Инструмент | Что пишет | Ограничения (из правил) |
|---|---|---|
| кисть земли расы | биты 0–2 `Tile` (`Terrain` 1..6: раса-владелец, нейтральная) | — |
| кисть грунта | биты 3–5 (`Ground.Plain`/`Forest`/`Water`) | вода под объектом запрещена, кроме допустимых (`MAP020`) |
| деревья | `Looks.TreeImage`/`TreeGroup` клетки | вариант картинки — случайно по `MapSeed` или явно |
| горы | объект гор `MountainLook(Id, X, Y, Width, Height, Image, Race)` + `Ground.Mountain` клеток следа | след целиком на карте, не под объектами |
| дороги | `RoadLook(Id, X, Y, Index, Variant)` | индекс соединения пересчитывается по соседям (как в игре) |
| заливка, прямоугольник, кисть 1/3/5/7 | — | — |

Вид земли редактор не рисует сам: `GroundComposer` + `GroundArt` после каждой правки перестраивают затронутые куски
(`GroundChunks`, кусок 256). Растекание земли расы от столиц/жезлов — правило игры (`Land`), в редакторе — только показ
«как станет на день N» (режим просмотра, не правка).

## 3. Объекты карты

Общие операции: поставить из палитры, выделить, сдвинуть, удалить, копировать, свойства. Занятость клеток — `Plan`
(клетка → id), след объекта — по виду (столица 5×5, город 4×4, прочее по описи `data/map`).

| Объект | Модель | Свойства в редакторе |
|---|---|---|
| столица | `Sites[Kind=Capital]` + `FortLook(Capital=true)` | владелец, имя, описание, гарнизон (§4), склад предметов, постройки игрока (§7) |
| город | `Sites` + `FortLook` | уровень 1..5, владелец/нейтральный, имя, описание, гарнизон, склад, бунт, рост (поля `Size`, `GrowthTurn`, `RiotTurn` — как в модели) |
| руина | `RuinLook` + место | охрана (отряд), награда: золото/ресурсы (`Cash`), предмет (`ItemId`), картинка |
| лавки: торговец, маг, наёмники, тренер | `SiteLook(Type = MERH/MAGE/MERC/TRAI)` + `MapSite` | имя, описание, товар: предметы / заклинания / юниты с ценой и количеством, картинка |
| источник ресурса (кристалл) | `CrystalLook(Resource)` | вид ресурса |
| мешок с сокровищем | `BagLook` + `Objects[Kind=BG]` | предметы, картинка |
| ориентир | `LandmarkLook(Type)` | тип из `GLmark` (и модов), след |
| жезл | `RodLook(Owner)` | владелец (обычно ставится игрой; в редакторе — разрешено, предупреждение `MAP041`) |
| могила | `TombLook` | ставит игра; в редакторе только показ |

## 4. Отряды и юниты

- Отряд — `Stacks[Id]`: владелец, подраса, лидер (`LeaderId`), юниты (`UnitIds`) и раскладка `Slots[6]` (−1 — пусто),
  предметы `Items` и надетое `Equipment[7]`, приказ `Order`/`OrderTarget`, приказ ИИ `AiOrder`/`AiOrderTarget`/`AiPriority`,
  `AiIgnore`, направление, невидимость, `Inside` (в крепости).
- Юнит — `Units[Id]`: `TypeId` (из `Gunits` всех слоёв), `Level`, `Hp`, `Xp`, `Modifiers`.
- Окно отряда — сетка 2×3 как в игре; большой юнит занимает две клетки (`SIZE_SMALL = false`); лидер обязателен
  (`Gunits.UNIT_CAT` лидера или вора, `MAP030`); лидерство лидера ограничивает число юнитов (`MAP031`).
- `Hp` по умолчанию — полное по таблице и уровню (формулы роста — из `D2.Rules.Units`, не свои).
- Шаблоны отрядов (`Events.Templates`) правятся тем же окном (для `CreateStack`).

## 5. Игроки, расы, дипломатия

- Игрок — `Players[Id]`: раса (`RaceId` из `Grace`), лорд (`LordId`), имя, лицо, человек/ИИ (по умолчанию — при старте
  выбирает игрок, как в меню), казна `Bank` (6 ресурсов), казна заклинаний, известные заклинания, постройки столицы.
- Нейтральный игрок — всегда есть, удалить нельзя (`MAP050`).
- Подрасы `Subraces` и знамёна `Banners` — создаются с игроком и для нейтральных групп.
- Отношения — `Relations[{Race1, Race2, Raw}]`: таблица N×N в окне (война/мир/союз и число отношения).
- Ограничения сценария — `Limits`: `MaxUnit`, `MaxSpell`, `MaxLeader`, `MaxCity`, сложность, `SuggestedLevel`.

## 6. Туман

`Fog[FogId]` по игроку — по умолчанию закрыто всё, кроме обзора от объектов игрока на старте (как делает игра —
`MapFog`/`Fog`); кисть «открыть/закрыть» для автора.

## 7. Зоны, события, переменные

- Зона — `Zones[Id] {X, Y, Radius}`; рисуется на карте рамкой, задаётся кистью.
- Событие — `Events[]`: имя, включено, однократно, шанс, порядок, для каких рас срабатывает (`Races`, `TriggerRaces`),
  условия и действия списками.
- **Набор условий и действий — ровно тот, что исполняют правила** (П3): 17 условий (`Frequency`, `Zone`, `EnterCity`,
  `OwnCity`, `KillStack`, `OwnItem`, `LeaderOwnItem`, `Diplomacy`, `Alliance`, `LootRuin`, `TransformLand`, `VisitSite`,
  `LeaderToZone`, `LeaderToCity`, `ItemToZone`, `StackExists`, `VariableInRange`) и 24 действия (`Win`, `CreateStack`,
  `CastSpellOnTriggerer`, `CastSpellAt`, `ChangeOwner`, `MoveBeside`, `Battle`, `EnableEvent`, `GiveSpell`, `GiveItem`,
  `MoveStack`, `Ally`, `Diplomacy`, `Unfog`, `RemoveMountains`, `RemoveLandmark`, `ChangeObjective`, `Popup`, `ChangeOrder`,
  `DestroyItem`, `RemoveStack`, `ChangeLandmark`, `ChangeTerrain`, `ModifyVariable`). Список строится из
  `JsonDerivedType` модели, а не руками — новый вид в модели сразу появляется в редакторе с общим окном полей.
- `Unknown` (импорт с неизвестной категорией) показывается только на чтение с `MAP070`.
- Поля-ссылки (`StackId`, `LocationId`, `CityId`, `TemplateId`, `SpellId`, `ItemType`, `PlayerId`, `EventId`) выбираются из
  списков по виду, щелчком по карте или «пипеткой»; висячая ссылка — `MAP071`.
- Переменные — `Variables` (номер → начальное значение, 32 бита).
- Порядок проверки событий и их семантика — `docs/scenario-events.md`; редактор показывает подсказку из него, не
  переопределяет.

## 8. Цели и тексты сценария

Имя, описание, брифинг (короткий и длинный), текст победы и поражения — поля карточки (`GameCatalog`) и ключи перевода
`name`, `description`, `briefing`, `briefingLong`, `winText`, `loseText` (`tools/scenario-ru/README.md`). Цели — через
события (`Win`, `ChangeObjective`) и журнал заданий — как в оригинале.

## 9. Переводы

- Язык карты — свойство документа (вопрос пользователю: писать оригинал на русском и переводы на `en`, или всегда
  оригинал на `en`; рекомендация — оригинал на языке автора, поле `Language` в карточке; для базы ничего не меняется).
- Окно «Тексты»: все ключи сценария (как `tools/scenario-ru/extract.py`) в две колонки «оригинал / перевод», пустой перевод —
  показ оригинала (как в игре), `MAP080` — перевод длиннее места на экране (замер шрифтом `UiFonts`).

## 10. Пробный запуск

Кнопка «Играть» = сохранить во временный слой `<мод>/.studio/playtest/` и запустить `MapScreen.tscn -- --scenario <Id>
--player <PlayerId> --mods <корень с playtest>` отдельным процессом (§2 `../studio-architecture.md`). Журнал зонда порта
пишется как обычно (`docs/port-probe.md`), разбор — `python tools/port_log_report.py`.

## 11. Проверка карты (каталог правил, начальный)

| Id | Уровень | Что |
|---|---|---|
| MAP001 | error | файл не читается `ScenarioFile.FromJson` или версия новее сборки |
| MAP002 | error | висячий id в `Plan`, `Stacks`, `Sites`, `Objects` |
| MAP003 | error | `Looks` расходится с `Map` (после `LooksBuilder` разница ≠ 0) |
| MAP010 | error | объект вне карты или след выходит за край |
| MAP011 | error | два объекта на одной клетке, где игра этого не допускает |
| MAP020 | error | непроходимый грунт под объектом, требующим прохода (вход крепости, лавка) |
| MAP021 | warning | столица недостижима по суше от других столиц (`PathFinder`) |
| MAP030 | error | у отряда нет лидера / во главе солдат |
| MAP031 | error | юнитов больше лидерства; большой юнит не в двух клетках |
| MAP032 | error | `TypeId` нет в `Gunits` активных слоёв |
| MAP040 | error | у игрока-не-нейтрала нет столицы |
| MAP041 | warning | жезл на старте |
| MAP050 | error | нет нейтрального игрока |
| MAP060 | error | ссылка на таблицу (предмет, заклинание, ориентир) нет в активных слоях |
| MAP070 | warning | событие с `Unknown` условием/действием |
| MAP071 | error | висячая ссылка в событии |
| MAP072 | warning | событие не может сработать (условие на объект, которого нет / зона вне карты) |
| MAP073 | warning | нет ни одного события `Win` (кроме стандартной победы захватом столиц) |
| MAP074 | error | правила событий ScenEdit (`prd.md` §3): ≥1 раса/условие/действие; одно `Frequency` и одно `Zone`; «всегда» только с ними и не с `Win`; `Win` и `Battle` — не более раза и последним действием |
| MAP075 | error | отряд «только по воде» на суше; шаблон с двумя лидерами; отряд без юнитов |
| MAP080 | warning | перевод не помещается |
| MAP090 | error | пробная загрузка: `GameSession` не стартует (`NewGame`), текст исключения |

## 12. Сохранение и формат

`d2-port-scenario` v5 через `ScenarioFile.Write`, требования записи — `../data-contract.md` §4. Свои данные редактора
(положение камеры, открытые окна, слои видимости) — в `<мод>/.studio/<Id>.studio.json`, не в сценарии.

## 13. Импорт `.sg`

Тем же кодом, что `tools/ScenarioImport` (`ScenarioFile.FromSg`): «Файл → Импорт `.sg`» кладёт сценарий в мод под новым
`Id`. Если импорт даёт `Unknown`-события — отчёт со списком. Старый путь `tools/synth-maps` (Python пишет `.sg`, затем
импорт) остаётся для карт, которые обязаны идти в оригинале, пока нет экспорта.

## 14. Экспорт `.sg`

Не в первой версии. Условия и проверка совместимости — `../data-contract.md` §6, веха E6 в [`plan.md`](plan.md).

## 15. Генератор случайных карт

Вне первой версии (вопрос пользователю, `../README.md` п. 6). Если делать — как команда ядра `GenerateMap(template, seed)`,
результат — обычный документ, проходит те же проверки.
