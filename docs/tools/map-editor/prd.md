# Редактор карт: видение и требования (PRD)

Рабочее пространство «Карта» в «Мастерской» ([`../README.md`](../README.md)). Новый редактор порта, не перенос ScenEdit.

## 1. Зачем

- Делать и править сценарии порта без `.sg` и без ScenEdit оригинала (П2 — старые форматы только на входе).
- Карты под проверки порта (как `port-synth-*`) — сейчас они собираются Python-генератором через `.sg`
  (`tools/synth-maps` → `tools/ScenarioImport`); редактор даёт ручную правку и тот же формат напрямую.
- Карты для модов: юниты, предметы, ориентиры мода в палитре.

## 2. Пользователи и сценарии

| Кто | Сценарий |
|---|---|
| автор карт (пользователь) | новая карта 96×96 на 4 расы: рельеф, столицы, города, лавки, нейтралы, 10 событий, брифинг → «Играть» → правка → упаковка мода с картой |
| автор кампании | 3 карты, общая кампания, тексты на русском и английском |
| модер | ставит на карту юнит своего мода, проверяет, что карта не открывается без мода (зависимость) |
| разработчик-агент | открывает карту из CLI, применяет скрипт команд, проверяет, запускает партию с зондом, сверяет числа |
| тестировщик правил | правит одну ситуацию на синтетической карте (поставить отряд, событие) и сразу играет её |

## 3. Что умел ScenEdit (GOG 3.01)

разметка `game-pristine/Interf/ScenEdit.dlg` (116 окон), строки `Interf/TAppEdit.DBF` (`X150TA*`, `X160TA*` — Rise of the Elves),
таблицы `Globals/LEvCond.DBF`, `LEvEffct.DBF`, `LOrder.DBF`; разбор `.sg` — `../disciples-modding/reference/D2SGFormat/sg.ksy`.

Проверки ScenEdit, которые переносятся как правила (`TAppEdit`): у события ≥1 раса, ≥1 условие, ≥1 действие; одно
`Frequency` и одно `Zone` на событие; «всегда» — только с `Frequency`/`Zone`, не с `Win`; `Win` и `Battle` — не более
раза и последним действием; событие с удалёнными объектами; отряд «только по воде» на суше; шаблон с двумя лидерами;
уровень города не понизить при полном резерве; у отряда ≥1 юнит; длины имён; в саге ≥2 сценариев без повторов.

Слабости ScenEdit, которые не повторяем: нет отмены и копирования областей; предел 200 отрядов (`X001TA0021`); лавки не
ставятся на воду; эльфы не выбираются заклинателем в «заклинании на место»; падения на русской сборке и на
повторе ключа в `.dbf`; кириллица в именах файлов; интерфейс 800×600; молчаливая потеря объектов при сценарии >512 КБ.

## 4. Новое по сравнению со ScenEdit

1. Отмена/повтор всего, копирование и вставка областей (с объектами).
2. Проверка карты списком с переходом к объекту; пробная загрузка в `GameSession`.
3. «Играть» — партия порта с этой картой в один щелчок, с зондом.
4. Палитра из **всех активных слоёв** (юниты, предметы, ориентиры мода); зависимость карты от мода — явная.
5. Тексты и переводы рядом (`lang/<яз>`), замер «влезает ли».
6. Работа без окна: каждая операция — команда CLI/скрипт (агенты, тесты).
7. Слои показа: зоны, приказы ИИ (стрелки к целям), владение землёй, проходимость, туман игрока.
8. Обычный интерфейс Godot (масштаб, окна, клавиши), карта — тем же рендером, что в игре.

## 5. Чего редактор не делает (границы)

- Не меняет правила и не добавляет механик (П3): нового вида события, объекта или приказа в редакторе нет, пока его нет в
  `D2.Rules`.
- Не правит таблицы юнитов/предметов — это рабочее пространство «Мод».
- Не пишет `.sg` до вехи E6.
- Не заменяет ScenEdit для карт, которые должны идти в оригинале, до E6.

## 6. Мерила готовности

| Мерило | Значение |
|---|---|
| круговая проверка | 85 сценариев (81 базы — 33 квеста и главы саг — + 4 `port-synth`): открыть → сохранить → байт в байт |
| пересоздание | `port-synth-3-events` можно повторить в редакторе скриптом команд, проверка карты `errors=0`, партия по памятке идёт |
| скорость | открытие 144×144 ≤ 2 с (земля кусками уже ~0,1 с, `docs/perf-log.md`); мазок кисти ≤ 16 мс на перестройку куска |
| пользователь | делает карту 48×48 с событием и играет её без помощи агента |
