# Редактор карт: план по вехам

Каждая задача — отдельная ветка `wt/editor-<веха>` в рабочей копии `../dg-wt-*` (снос — только
`python tools/wt_remove.py <путь> --branch`), коммит `feat(editor): …`, после серии правок — `PYTHONHASHSEED=0 graphify update .`.
Полный `dotnet test` — перед слиянием (≈1,5 мин); новые тесты не должны заново разбирать все сценарии, если соседний тест уже
это делает (общий кэш, как `TreasuryJournal.Load`).

Порядок с моддингом: **K0 ([`../modding-kit/plan.md`](../modding-kit/plan.md)) можно делать параллельно с E0–E1**; E2 (палитра)
ждёт K0, иначе палитра видит только базу.

## Риски

| Риск | Последствие | Мера |
|---|---|---|
| `SaveJson` не даёт байт в байт | ложные изменения в git модов | E0.2 первым; порядок ключей закрепить тестом |
| `Looks` и `Map` расходятся в импорте (поля, которых нет в модели) | `LooksBuilder` не может заменить импорт | E0.3 с отчётом; недостающее — в модель (с `Version + 1`) |
| поля `.sg`, которые порт не читает | редактор их теряет → экспорт E6 невозможен | список «не переносится» из `sg.ksy` против `ScenarioData` в E0.3 |
| `MapView` жёстко завязан на `GameSession` | дорогая перестройка на каждую команду | замер E1.2; при нужде — лёгкий `IMapDocumentView` |
| таблицы без слоя модов | палитра без юнитов мода | K0 до E2 |
| размер карты > 144 | части порта с массивами 144 (ИИ) | вопрос пользователю; до решения — предел 144 |
| интерфейс редактора разрастается | недоделанные окна | каждое окно — после команды и теста в ядре; окно без CLI-аналога не принимается |
