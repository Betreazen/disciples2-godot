## Как запустить сессию

1. Рабочие копии уже созданы и стоят на `main` (`git worktree list`). Новую создавать так (из основного каталога):
   `git worktree add ../dg-wt-<имя> -b feat/<ветка> main`, затем граф проекта: `cp -r graphify-out ../dg-wt-<имя>/` и
   `PYTHONHASHSEED=0 graphify update .` в новой копии (раздел «Граф проекта» в `CLAUDE.md`). Сносить — **только**
   `python tools/wt_remove.py ../dg-wt-<имя> --branch`.
2. Открыть Claude Code в каталоге рабочей копии (VS Code: «Открыть папку» → `C:\Claude code projects\dg-wt-…`, или `claude` в терминале
   из этого каталога).
3. Вставить промпт сессии целиком (файл из таблицы, текст после линии `---`).
4. Первый запуск сцены Godot в новой копии дольше — он импортирует ресурсы. Графика и корпус — не в копии, а через переменные
   окружения (ниже).
5. Когда кусок готов, сессия пишет «ветка готова к слиянию»; это передают сессии А, она сливает.

## Правила для всех (из `CLAUDE.md`)

- Рабочие копии сносить **только** `python tools/wt_remove.py <путь> --branch`. Никаких symlink/junction.
- Данные вне git — переменными окружения, в каждой команде (состояние оболочки между командами не сохраняется):
  `D2_CORPUS_DIR="C:/Claude code projects/disciples-godot/corpus"`, `D2_ASSETS_DIR="C:/Claude code projects/disciples-godot/assets"`.
  Пример: `D2_CORPUS_DIR=… D2_ASSETS_DIR=… dotnet test`.
- Поведение — как в оригинале, доказывается кодом движка и журналами зонда; интерфейс и поведение, которого нет в данных, — спрашивать у
  пользователя. Устройство — по `docs/principles.md`.
- Не запускать два `dotnet test` в одной рабочей копии. Полный прогон ~4 мин; в нескольких копиях сразу — медленнее, это нормально.
  `dotnet test` — с `DOTNET_CLI_UI_LANGUAGE=en` (иначе вывод русский и фильтры его не видят).
- Перед сценами — `dotnet build godot/D2.Godot.csproj`; проверка экранов — `PYTHONIOENCODING=utf-8 python tools/ui-render-check.py`
  (с `D2_ASSETS_DIR` и `D2_CORPUS_DIR`).
- В рабочих копиях без своего корпуса бывают падения не от ветки: `RulesDataTests.Import_IsRepeatable`, `MapCorpusTests.F4BattleJournals…`
  (корпус Ф4 ищется по пути репозитория) — сравнивать с `main`, а не чинить в ветке.
- Темп (с пятого круга, цель — все части ~99 % за два круга): задачи пакетами по 6–9 (у А — 5–8 правок). На каждую задачу — сборка и
  тесты своей области по фильтру (~1 мин); раз на пакет — полный `dotnet test` в фоне, `dotnet build godot/D2.Godot.csproj`,
  `ui-render-check`, одно ревью подагентом на весь дифф, документ, коммиты по задачам, `git push`. Вопросы пользователю — пачкой в начале
  пакета; между задачами пакета не останавливаться ради отчёта.
- Сетевую игру не переносим (решение 19.09); «горячий стул» (игра на одном ПК) — переносим до конца, это отдельная часть готовности.
- Стыки пакета 1 сессии А (26.09, в `main`): модель — `MapState.SpellEffects` (записи `CMidSpellEffects`, копируются во всех `With*` —
  новые поля модели добавлять туда же), `MapStack.AiIgnore`; сценарии пересобраны. `GameState.Offers` — теперь и сделки
  (`AllianceOffer.Trade`, ответ `GameSession.AnswerTradeOffer`): окно союза в `MapScreen.Windows.cs` их пропускает, окно сделки — Б.
  При конфликте `data/scenarios` после слияния — пересобрать `dotnet run --project tools/ScenarioImport`.
- Стыки пакета 1 шестого круга А (27.09, в `main`): для окна дипломатии Б — `GameSession.ProposeTradeBy` (предмет из склада своей
  крепости или заклинание, цена; ИИ отвечает сразу, `ProposalResult`), `ProposeExchangeMapBy`, ответ человека на обмен картами от
  человека — `AnswerExchangeOffer` (предложение — `AllianceOffer.Exchange`; окна для него ещё нет), `GiveGold(..., report)` — реплика
  ИИ-получателя в отчёте, как у союза. `AllianceOffer.IsAlliance` — только союз.
- Общий каталог `assets` правят все копии: 27.09 сессия Г запекла пурпур в `assets/ui` раньше слияния — тест описи графики в `main`
  падал до слияния её описи. Меняешь графику в `assets` — пересобери опись в своей ветке и скажи пользователю, что `main` до слияния
  будет красным.
- Heredoc в Git Bash теряет бэкслеши — скрипты правки писать Write-инструментом во временный каталог; рабочая копия в CRLF. `git stash`
  не использовать.

## Слияние

1. Ветка готова к слиянию: `git rebase main`, полный `dotnet test`, `dotnet build godot/D2.Godot.csproj`, `ui-render-check` — всё зелёное.
2. Резерв ветки: `git push -u origin <ветка>` (хуки сами пушат только `main`).
3. Сессия сообщает пользователю «ветка готова»; сливает сессия А (`git merge --no-ff <ветка>` в `main`, прогон тестов, перенос итогов в
   `HANDOFF.md`). Потом ветка продолжает работу с `git merge --ff-only main` (или `git rebase main`).
