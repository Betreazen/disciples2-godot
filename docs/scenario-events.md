# События сценария (CMidEvent) — разбор движка GOG 3.01

_Разбор 25.09.2026 подагентом сессии В по `Discipl2.exe` (дизассемблер `exe_x86.py` из `../disciples-modding`, заголовки
тулсета `mss32/include`). Ранги: **1** — доказано кодом, **2** — согласуется, код не дочитан, **3** — гипотеза. Реализация
в порте и сверка с журналами — `docs/day-cycle.md` §2._

Поправка к тулсету: `CTestLocation::Test` у GOG — **`0x444a26`** (vft `0x6cf3bc`), а не `0x6fd6b8`. Остальные адреса тестов тулсета
совпали.

Смещения (сверены кодом): `CMidEvent` +0x14 `affectedRaces` (`HUMAN…ELF`), +0x30 `racesCanTrigger` (`VERHUMAN…VERELF`), +0x4C
`ENABLED`, +0x4D `OCCUR_ONCE`, +0x50 `ORDER`, +0x54 `CHANCE`, +0x58 условия, +0x68 эффекты (поток `0x5f0b50`: `0x5f0c93` — `HUMAN…`,
`0x5f0da9` — `VER…`), ранг 1. `CMidEvEffect` +8 — `NUM` (порядковый номер, `0x615c2d`). `CScenarioInfo` +0x18 `DEBUNKW`, +0x1C
`DEBUNKL`, +0x20 текущий день, +0x5C кампания. `CMidStack` +0x24 `SRCTMPL_ID`, +0x8C владелец, +0x94 «внутри». `CMidPlayer` +0x88
человек, +0x8C `capturedById`.

## 1. Когда и как проверяются события

### 1.1. Механизм (ранг 1)

Действие сервера — список `IEventEffect`, его применяет рекурсивная `0x41f762`:

1. Вектор триггереров T: triggererId, если он не пуст.
2. Эффекты применяются по порядку (`0x41f640`): `stopProcessing()` (слот +0x10, истинен только у `CEffectBattle`) ставит stop;
   `apply(map, sender, &T)`; в T дописывают только `CEffectCreateStack` (новый отряд, `0x436d19`) и `CEffectKillStack` (`0x438d0b`).
   stop остальные эффекты не прерывает.
3. Если stop не выставлен — для каждого id из T свой список «выполненных» и цикл: id — существующий отряд →
   `FilterAndProcessEvents(игрок пуст, триггерер id)` (`0x44296c`), иначе `(пусто, пусто)` (`0x441985`); новые эффекты — рекурсивно
   (`0x41f762`, триггерер пуст); повтор, пока срабатывают события и нет stop.
4. Второй проход (слот +8, `0x41f6e3`); на верхнем уровне — отсчёт конца сценария (`0x421077`, §4).

**`FilterAndProcessEvents` (`0x4419aa`)** — не больше одного события за вызов:
1. Триггерер задан, но отряда нет — обнуляется.
2. События — в порядке списка; уже выполненные пропускаются.
3. Кандидаты — игроки, чья раса есть в `racesCanTrigger` (`VER…`); с отрядом-триггерером — только его владелец.
4. Для **каждого** кандидата X — `CheckAndExecuteEvent` (`0x441d5d`) с `samePlayer = (игрок вызова == X)`; успех цикл не прерывает.
5. Сработало хоть у одного — событие в «выполненные», возврат true.

**`CheckEventConditions` (`0x441d9f`):**
1. День 0 — false (`0x4422c8`): **в нулевой день событий нет**.
2. `ENABLED == 0` — false.
3. Условия по порядку файла, логическое И до первого ложного: `ITestCondition::Create(cond, samePlayer, triggerer)` (`0x441f1c`) →
   `test(map, X, eventId)`.
4. Шанс: `r = GenerateRandomNumber(100)` (`0x54851f`, R250), выполняется при **`r ≤ CHANCE`** (CHANCE 100 — всегда, **0 — 1 %**).
   Бросок только после всех условий, свой на каждого кандидата.
5. `OCCUR_ONCE`: первым эффектом кладётся `CEffectEnableEvent(событие, false, 0)` (`0x4378c2`) — применяется позже, поэтому в том
   же проходе событие срабатывает и для остальных кандидатов.
6. `ExecuteEventEffects` (`0x4422e1`): эффекты по вектору (после загрузки отсортирован по `NUM`, `0x5f2f3e`); результат
   (`IEffectResult::Create`, `0x442427`) не меняет карту, а дописывает `IEventEffect` в общий список — применяется потом по порядку.

### 1.2. Точки проверки (ранг 1)

| Точка | Функция | Игрок | Триггерер |
|---|---|---|---|
| **Начало хода игрока P** | BeginTurn `0x41e290` → `0x41f4ca` | P | нет |
| Каждая клетка пути (упреждающая) | `0x440284` | нет | движущийся отряд |
| После хода: конечная клетка, вход в город, посещение | StackMove `0x41e46b` | нет | отряд |
| После боя | EndBattle `0x41e3e2` | нет | группа-победитель (не отряд — без триггерера) |
| Действие вора и отмена, «бросить мешок» (`DropBag`), постановка жезла (`LeaderDropRod`), «Меню героя» после боя (`RequestPaperdoll`, `BTN_PAPERDOLL`; переключатель куклы в окнах отряда сервер не зовёт) | `0x41e6e6`, `0x41e771`, `0x41f257`, `0x41f30d`, `0x41f397` (имена — строки обработчиков, REA 13.10) | нет | отряд |
| Отряд, созданный / убитый эффектом | через T | нет | новый отряд / нет |

Без проверок: литьё, свиток/посох, исследование, рост деревни, стройка, дипломатия, торговля, союзы. Смена дня (`0x41e318`)
проверяет только через CreateStack/KillStack; день 1 — без проверок (`0x41f4a8`).

**Начало хода (`0x41f4ca`):** эффекты начала хода (`0x443ca2`), затем цикл `FilterAndProcessEvents(P, без триггерера)` (обёртка
`0x442941`) → применение → повтор, пока срабатывают события; «выполненные» — общие на цикл. Кандидаты — **все** игроки с расой из
`VER…`, `samePlayer` истинно только у P.

**Упреждающая проверка пути (`0x43fc3c` → `0x440284`):** на каждой клетке (без объекта типа 0x27) отряд временно ставится туда и
зовётся `FilterAndProcessEventsNoPlayer`; появились эффекты — **путь обрывается на этой клетке**. Исключение: владелец — человек
(`0x4405ce`) и у всех эффектов слот +0xC ложен (`0x4405fb`: только `CEffectChangeOrder` и `CEffectEnableEvent` из `OCCUR_ONCE`) —
тогда эффекты идут в список хода, и отряд идёт дальше. ИИ останавливается всегда. Шанс бросается на каждой клетке, где выполнены
условия. После реального хода события проверяются заново.

### 1.3. Порядок, флаги, расы

- Список событий при загрузке (`0x429603`) сортируется `0x4297b5`: **ORDER по возрастанию, при равенстве — id** (32 бита). Ранг 1.
- Две расовые проверки: `VER…` — кто может быть кандидатом; `HUMAN…` — `AffectsPlayer` (`0x444b33`), какого игрока — зависит от
  условия (§2); по ним же получатели попапа в режиме 2. В результат эффекта передаётся кандидат X.

### 1.4. `MidQuestLog`

Пишется только в `CEffectPopup::apply` (`0x43b290`, вызов `0x5fa8a1` из `0x43b33d`): `ID_PLAYER` — получатель, `SEQ_NUM` — максимум
у игрока + 1 со стартом 0 (ранг 1, §9), `CUR_TURN` — день, **`TYPE` всегда 0**, `ID_EVENT`/`EFF_NUM` — событие и `NUM` попапа. Пишется и для ИИ.

## 3а. Применение эффектов — подробно (разбор 25.09, второй круг)

Сигнатура результата: `apply(out, map, list, X, triggerer, playingStack)` (X — кандидат). Отряды эффекта (`0x43f3ae`): id типа `KC` —
этот отряд (даже если его нет — тогда пропуск), иначе шаблон — экземпляры по `SRCTMPL_ID`, при `FIRST_ONLY` — первый. Ранг 1, где не
сказано иначе.

**L_CREATE_STACK** (`0x43bd74` → `CEffectCreateStack` `0x436c9a`).
- Шаблон (поток `0x5fee0b`): список `UNIT_n` **обрывается на первом пустом**; `positions[p]` — индекс юнита шаблона для клетки p
  (−1 — пусто; один юнит шаблона может стоять в нескольких клетках — это несколько юнитов одного типа). `LEADER`+`LEADER_LVL` — тип
  лидера; предметов в шаблоне нет.
- Первым эффектом — туман владельцу шаблона вокруг **центра локации**: квадрат `±scout` лидера (без +1), нейтралу — нет; применяется,
  даже если клетки для отряда не нашлось.
- Клетка (`0x5edded`): кольца радиусов 0, 1, 3 (только периметр), обход x снаружи, y внутри, первая клетка кольца `(x−r, y−r)` — в
  конец; берётся первая свободная: в карте, в плане нет укрепления/ландмарка/объекта/руины/жезла/жилы/сумки, нет отряда, земля не горы
  (вода годится; водному лидеру — вода, окружённая водой). Нет клетки — нет отряда.
- Отряд: лидер — тип лидера шаблона, день создания — текущий, HP полное, опыт 0; ход — полный запас; сначала нейтральный с приказом
  «стоять»; лидер в клетке 2 (3), затем переставляется в первую клетку p с `positions[p]` = лидер; для каждой p: юнит шаблона, если он не
  тот же, что лидер, и клетка свободна; модификаторы шаблона по клеткам, HP до полного с модификаторами; facing из шаблона при
  `USE_FACING`; приоритет ИИ; владелец и подраса шаблона (приказ «обычный», у нейтрала «стоять»); приказ шаблона с целью, если
  допустим (`0x60ed92`), иначе ATTACK_STACK → BEZERK, нейтрал → ROAM, иначе NORMAL; имя лидера из `NAME_TXT`; `SRCTMPL_ID` = шаблон.
  Новый отряд — триггерер следующей проверки.

**L_CAST_SPELL** (`0x43bfe4`) / **L_CAST_SPELL_MAP** (`0x43c192`) → `0x4416b6` → `0x443600`. Заклинатель: для SUMMON/UNFOG/area 999 —
`ID_PLAYER1`, пусто — у `L_CAST_SPELL` владелец триггерера (нейтрал — ничего), у `L_CAST_SPELL_MAP` запасной ветки нет (§9); для
остальных — **пусто**. CAST_SPELL — клетка триггерера (нет его —
ничего), area 999 не кастуется; CAST_SPELL_MAP — центр локации. Мана не тратится, известность не проверяется, запись литья не пишется,
бросков нет. Проверка цели (кроме SUMMON/FOG/UNFOG/REMOVE_ROD/CHANGE_TERRAIN): area 1 — отряд на клетке, иначе отряды в квадрате
`±area/2` не в городах; ATTACK/LOWER — не свои и не союзные заклинателю (пустой — без проверки «свой»); BOOST/HEAL/RESTORE/INVIS —
свои, если заклинатель задан; RESTORE — ход не полный; ATTACK — есть неиммунный; GIVE_WARDS с пустым заклинателем не срабатывает.
Действие — общее с обычным литьём.

**L_REMOVE_LMARK** (`CVisitorEraseLandmark`): ландмарк убирается из плана и с карты, земля не меняется; `BOOLVALUE` — только анимация.
**L_CHANGE_LANDMARK**: новый тип того же размера — иначе ничего; план тот же.

**L_UNFOG** (`CEffectFog` `0x438314`): каждому игроку списка (EVENT_ID записи отбрасывается), нейтралу — нет: квадрат `±r` вокруг центра
локации, `r = (NUMVALUE == −1 ? радиус локации : NUMVALUE) + 1`, без четырёх угловых клеток (§9); `ENABLE` 1 — открыть, 0 — закрыть
(затем игроку заново открывается обзор его крепостей и отрядов, ранг 1, §9).

**L_CHANGE_OWNER** (`CEffectChangeOwner` `0x4366e2`): `ID_PLAYER1` — **подраса** (владелец — её игрок); пусто — владелец и подраса
триггерера; нет триггерера — ничего. Каждому отряду: туман новому владельцу `±scout` (квадрат без углов, §10), отряд в городе выходит
в соседнюю свободную клетку (вход и сдвиги `0x6ee7e0`, ранг 1), facing 7, владелец и подраса (приказ «обычный», у нейтрала «стоять», цель пуста, приказ ИИ «обычный»).
Смена хозяина (`CVisitorChangeStackOwner` `0x60d6a5` → `0x60d3ea`) сбрасывает чужие приказы на отряд: у отрядов другой подрасы с
`L_DEFEND_STACK` на него — `L_NORMAL` (у нейтрала `L_STAND`), цель пуста (`GameSession.StackOwnerChanged`, 15.10); клиенту нового
хозяина — `CCmdStackActionMsg`(отряд, 1) «выделить», прежнему — (отряд, 2) «снять выделение» (`docs/ui-windows.md` §19).

**L_REMOVE_MOUNTAIN** (`0x439a3d`): в квадрате `±R` локации (без +1) клетки с землёй «горы» → «равнина», местность — нейтральная;
объекты гор, задевающие зону, удаляются, затем горы вне зоны перекладываются новыми объектами (ранг 1, §9); нет горных клеток — ничего.

**L_MOVE_STACK / L_MOVE_BESIDE** (`CEffectMove` `0x439e84`): MOVE_STACK — `ID_STKTEMP` (первый экземпляр) или триггерер при `BOOLVALUE`,
к центру локации; MOVE_BESIDE — к клетке триггерера. Обычный путь без учёта очков хода, отряд выходит из города, **телепорт** в конец
пути (клетка должна быть свободна), очки хода не меняются, туман владельцу по точкам пути, facing по последним точкам. Путь не найден —
ничего. Где кончается путь к клетке триггерера — §7.

**L_GIVE_ITEM** (`0x438616`): получатель — триггерер, иначе играющий отряд, иначе (или при `GIVETO` 1) столица кандидата; новый экземпляр
предмета в инвентарь. **L_DESTROY_ITEM**: `TRIG_ONLY` — все экземпляры типа у триггерера (снаряжение и инвентарь), иначе — все на карте.

**L_BATTLE** (`0x43c485`): отряд S (или первый экземпляр шаблона) подходит к триггереру (как MOVE_BESIDE); лидер триггерера — иллюзия →
триггерер уничтожен; иначе бой: **нападает S, защищается триггерер**; остановка проверок.

**L_CHANGE_TERRAIN** (`0x43f128`): `LOOKUP` — местность (`LTerrain`), `NUMVALUE` — сторона квадрата N: x ∈ [cx − ⌊N/2⌋, cx − ⌊N/2⌋ + N);
меняются только клетки равнины и леса.

**L_DIPLOMACY**: новое значение не «мирное» (≤ `D_NEUTRAL`) — союз разрывается; текущее = `DIPLOMACY`, «вечная война» = `ENABLE`,
прежнее не меняется (поправка §7). **L_ALLY**: текущее = `D_PEACE`, затем союз общим путём (`D_MK_ALLY`, `PERMALLY`, ход — текущий
день; §7).

**L_GIVE_SPELL**: кандидату в известные (уже известное — пропуск).

Поправки к §3: заклинатель `L_CAST_SPELL` — для SUMMON/UNFOG/999, а не для «вредных»; туман `L_UNFOG` — квадрат, r+1 (ранг 1);
`ID_PLAYER1` у `L_CHANGE_OWNER` — подраса (ранг 1).

  прочее (крепость, руина, площадка, область, игрок, шаблон) — как есть.
- **Кто рисует круг** (реестр `0x5bb76e`): столица, деревня, отряд (не внутри крепости), мешок, руина, лавка, маг, наёмники, тренер,

## 10. Девятый круг: последние ранги 2–3 (28.09.2026)

Подагенты, статически по `Discipl2.exe` (ранг 1, если не сказано иное). Порт — `docs/day-cycle.md` §19.

- **Эпилог**: ролик, текст и звук ищут запись `CScen.dbf` одинаково — кампания сценария в `CCamp.dbf` (`0x669464`, нет — эпилога нет),

  открытии (`0x4bc49f`), звук после затухания музыки 750 мс (`0x4bca73`), конец звука включает (`0x4bcd11`).
- **Победа**: объявляется после обработчика команды (`0x421077`, слот +0x24 `IMidMsgSender`); флаг «окончена» (+0x134) проверки событий
  не читают — события того же действия после `L_WIN` идут. Косвенных путей к `CEffectWin` нет.
- **`L_CREATE_STACK`**: туман — `CEffectFog` первым эффектом (`0x43bd74` → `0x4382a8`), до создания; радиус — `getScout` лидера шаблона
  без +1, форма — обычный обзор, квадрат без угловых клеток (`0x5d4dfc`); нейтралу нет (`0x5e5358`). Так же у `L_CHANGE_OWNER`
  (`0x4367e0`).
- **`L_REMOVE_MOUNTAIN`, перекладка** (`0x5f0206` → `0x5efb81`):
  1. Охват — общий прямоугольник удалённых объектов (правые границы исключены, `0x5f0296`); объекты удаляются по id.
  2. Сетка по охвату (`0x5eff35`): клетка закрыта (0xFF), если земля не горы (в том числе клетки зоны — они уже равнина) или её
     накрывает оставшийся объект (`0x5ef8f3`); иначе — буква местности (`0x5f006d`): HU `d`, DW `e`, HE `f`, UN `g`, EL `i`, прочее `h`.
     Годные — `d…h` (`0x5efdb0`).
  3. Проходы 5, 3, 2, 1 (`0x838978`); y снаружи, x внутри. Квадрат > 1 — только целиком в охвате и из годных клеток (`0x5efe96`).
     Негодная клетка не 0xFF — прыжок `x += байт − 1` и ещё +1: через поставленный квадрат (в сетке — его размер), у эльфийской `i`
     (0x69) — на 105, остаток строки прохода пропускается.
  4. Квадрат: раса — строгий максимум букв, при равенстве — первая из `d, e, f, g, h` (`0x5efe12`) → `LRace` (d 0, e 3, f 2, g 1, h 4,
     `0x5efdd1`); число картинок — `Globals/GTileDBI.dbf` (местность расы, земля M, `NDX` = размер → `QTY`; `0x57f707` → `0x59ab8d`);
     картинка — R250 `0x54851f(QTY)`, 0-based, до добавления; при 0 шага нет.
  5. Добавление (`CMidMountains::add` `0x5ef989`): id — счётчик (при загрузке — наибольший `ID_MOUNT` + 1, `0x5ef77f`; удаление его не
     уменьшает), угол (x, y), s×s, картинка, раса. Земля не меняется.
- **Попап в ходе ИИ**: показ сразу (`0x489e90`), очередь команд клиента ждёт «ОК» (`0x4bd98a`). **Хотсит**: местный игрок — один
  (последний начавший ход человек, `0x4177bf` → `0x403834`), фильтр `0x489536`; попап другому человеку пропадает, запись журнала
  заданий остаётся (`0x43b290`).
