# Разбор: показ боя (CBatUnitAnim, эффекты, TUCH/HEFF, шаги, надписи, звуки) — точки для зонда

Discipl2.exe GOG 3.01, база 0x400000. Инструменты: capstone (`d2dis.py`), Ghidra 12.1.4 (REA). Рабочие скрипты — `scratchpad\batanim\`
(`fn.py` — функция до следующей процедуры, `ctx.py` — окрестность вызова, `vt.py` — vtable). Ранги: **1** — по листингу, **2** — по
косвенным признакам (смысл поля/имени), **3** — догадка. Все адреса возврата = адрес `call` + 5.

## 0. Общие структуры (нужны всем точкам)

**CBatUnitAnim** (12 штук, конструктор `0x6512b0`, vtable `0x6f287c`: только деструктор и ещё одна; всё остальное — не виртуальное).
`this+4` → данные `D` (0x1028 байт, `0x654a00`). Поля (ранг 1 — запись в конструкторе `0x6512b0` и в `0x652c8a`):

| поле D | что |
|---|---|
| +0x08 | контекст вида (`interf.data+0x1500`) |
| +0x0c | **id юнита** на месте (CMidgardID, 4 байта; пусто = `0x8372f4`), ставит `0x652c8a` → `0x652fb3` |
| +0x10 | id типа для картинок (`0x6497bf`); +0x28 — id облика при превращении (если байт +0x27) — его берёт `0x653f54` |
| +0x14 | строка расы для `UPGRADE` (`0x652f1b`) |
| +0x20 / +0x21 | отступил (статус 0x1c) / отступает (0x1d) → `0x6549c1` = «зеркально» |
| +0x22 | скрыт (статус 0x1e); +0x23 — убит (статус 1); +0x26 — паралич/окаменение (2/3 — кадры стоят) |
| +0x24 | «после HHIT — смерть»; +0x25 — большой юнит (`0x649749`) |
| +0x2c | стойкий код эффекта (3/5/7/9 → откат 4/6/8/10 в `playEffect`) |
| +0xf80 | группа нападающих (bool); **+0xf81 — слева на экране** (`isUnitOnTheLeft`); **+0xf84 — позиция 0..5** |
| +0xf88 / +0xf8c / +0xf90 | движок `CBatViewer2DEngine` / загрузчик картинок / `CAnimCounter*` (общий счётчик шага) |
| +0xfe0 / +0xfe4 | текущая картинка тела / тени (IMqImage2*, обёртка `CImage2Movable`) |
| +0xff4 / +0xff5 | `battleAnimations` / мгновенный бой (`battleSpeed==4`) |
| +0xff8 | имя звука замаха (CMqString, `c_str` = `[s+8]`, пусто → `""`) |
| +0x100c | имя звука «больно» (CMqString) |
| +0x101c / +0x1020 | длительность HHIT (кадры, SNDINFO+0x58 бьющего) / уже сыграно |

**IMqImage2**: число кадров — `vtbl+0x10`, thiscall без аргументов, eax (ранг 1 по месту: `0x6529c3` берёт `>>1` как кадр смены облика,
`0x6537f6` — случайный начальный кадр `0x54851f(n)`; смысл «число кадров» — ранг 2). Обёртки `CImage2Movable` (`0x6f28dc`) и
`CImage2Callback` (`0x6f2914`, `0x6f2954`, `0x6f29e4`) перенаправляют `+0x10` во внутреннюю (`0x55e567: mov ecx,[ecx+4]; jmp [eax+0x10]`).
Звать из хука можно — движок сам зовёт так же.

**Запись шага** (аргумент просмотра `0x630a7b`): `holder → R`; `R+0` id ходящего, `R+4` байт «ходящий — нападающий» (`0x62c2a4`),
`R+8` **вид шага 0..16** (`0x62c2b7`), `R+0xc` номер атаки (1 — первая, `0x62c2ca`), `R+0x10` второй id (шаг 12 — предмет, `0x62c5b3`),
`R+0x14` список результатов по целям. Список (ранг 1: `0x4c7e28` begin, `0x40b43f` end, `0x62c8a0` ++, `0x62c8e0` *):
`head=[R+0x18]; for (n=[head]; n!=head; n=[n]) rec=n+8;`. Запись цели (0x14 байт): `+0` id цели, `+8` промах, `+9` иммунитет/оберег
(`+0xa`=0 → «Ward» `X008TA0011`, иначе «Immune» `X008TA0002`), `+0xc` урон, `+0x10` прибавка крита (ранг 1 — по `0x63b391`).

**Данные вида** `V = [interf+0x1c]` (в `0x630a7b` `ecx = interf+0x18`, и там `V=[ecx+4]`): `V+0x14d8` — `CAnimCounter` шага,
`V+0x14e0` — байт «шаг показан», `V+0x14a8` — имя звука HEFF, `V+0x13e8+pos*0x10` — заготовленные TUCH по местам (картинка в `+8`).

## 2. bat_anim — `0x646ec5` (смена анимации юнита)

Единственная точка, через которую любая картинка встаёт на место в движке боя: `слой = база[pos] + *sub` (`0x6f2708` слева / `0x6f2720`
справа), особые `*sub` 1500/1600 — слои группы 79/799 и 139/1399 (HEFF). Тень тела идёт отдельно (`0x646fd1`) — дублей нет.

```
0x646ec5: push ebp / mov ebp,esp / sub esp,0xc / mov [ebp-0xc],ecx
0x646ece: mov eax,[ebp+0x10]  ; bool слева
0x646edd: cmp dword ptr [ecx],0x5dc       ; *sub == 1500 → слой 0x4f
0x646ef1: cmp dword ptr [edx],0x640       ; *sub == 1600 → слой 0x31f
0x646f05: mov ecx,[eax*4+0x6f2708] / add ecx,[edx]   ; база[pos] + *sub
0x646f27: call 0x6469a3 ... 0x646f83: ret 0x18
```

Вид — по адресу возврата (ранг 1, у каждого вызова видно, откуда картинка и какой `*sub`):

| возврат | функция | kind | sub |
|---|---|---|---|
| `0x653e10` | `0x6537f6` покой | `IDLE`/`STIL` (по `D+0xff4`), зеркально при `D+0x20|0x21`; кадр — случайный, если арг.1=0 | 5 |
| `0x653a01` | `0x6537f6`, ветка «убит» (`D+0x23`) | `DEAD_` (труп, `0x651741`→`0x5b3730`→`0x5c626d`) | 5 |
| `0x6547da` | `0x654346` замах | `HMOV` (загрузчик `0x6480d1`) | 5 |
| `0x65424f` | `0x653fb7` удар | `HHIT` (загрузка `0x6517e1`→`0x648025`); повтор до `D+0x101c` — новая строка на повтор | 5 |
| `0x652006` | `0x651c9c` предмет | `G000IG{1111|2222|3333}HMOV` (арг. — id предмета) | 6 |
| `0x652932` | `0x65255b` эффект | картинка `Battle.ff` по коду (§3) | 12 |
| `0x6362af` / `0x636330` | `0x636239` | TUCH / тик (§4); вторая — подсветка при `0x667d20(0)` | 7 / 3 |
| `0x63a177` / `0x63a236` | `0x639f2b` | `HEFF` тело / тень над группой целей, pos=0 | 1600 / 1500 |

Частота: только на смену. **Но** `update` вида (`0x62f823` → `0x6515d8` → `0x6537f6`) переставляет покой всем 12 юнитам на каждом
сообщении — писать строку только при смене (слот, kind, img) против прошлой по слоту. Слот: `(left, pos)`; id юнита на месте —
из `D+0xc` (для вызовов из CBatUnitAnim) или по `(left,pos)` из данных боя. Попутная поправка к `docs/ai-screen.md` §15: подслой тела
юнита (покой, замах, удар, труп) — **5** (`0x653db5`, `0x6539ac`, в `0x653fb7`/`0x654346` тоже 5), 6 — только у анимации предмета
(`0x651c9c`), TUCH — 7, эффекты — 12 (ранг 1).

Загрузчики `CBatImagesLoader` (кто зовёт — единственный вызов у каждого, ранг 1): `0x647f41` IDLE/STIL (`0x5b8a8d`→`0x5c683a`) ←
`0x653ad0`; `0x648025` HHIT (`0x5c68ba`) ← `0x6518b7`; `0x6480d1` HMOV (`0x5c6930`) ← `0x6543fe`, `0x651d0d`; `0x6482ac` HEFF
(`0x5c69a6`) ← `0x6357a2`; `0x6483b1` TUCH юнита (`0x5c6a1c`) ← `0x635277`; `0x64845d` TUCH класса (`0x5c6a92`) ← `0x635433`,
`0x63570a`. Выход `0x6480d1` (16 байт, `0x648e80`): `{тело, тень, SNDINFO+0x2c, SNDINFO+0x28}` — `+8` идёт в кадр удара `0x6531df`,
`+0xc` — в кадр звука замаха `0x6532b7` (`0x654346`, ранг 1).

## 3. bat_effect — `0x65255b` playEffect

```
0x65255b: push ebp / mov ebp,esp / push -1 / push 0x6c6f4a ...
0x652579: mov [ebp-0x70],ecx                 ; CBatUnitAnim
0x652588: mov dl,[ecx+0x23] ; убит → только код 2 (воскрешение)
0x65259a: lea ecx,[ebp+0x10] ; код = [esp+0xc] на входе
...       call 0x6529c3(loader=[D+0xf8c], id, &код, [ebp+0x14], [D+0x25], D+0x14, &half)
0x6529c0: ret 0x10
```

Коды (`0x6529c3`, таблица имён `0x7ae780…0x7ae83c`, ранг 1): 0 `UPGRADE{HU|HE|DW|UN|NE|EL}{L|S}` (`0x5b3ed3`), 1 `DEATH_*`
(`0x647c47`, кадр смены = `[+0xc]` записи), 2 `REVIVEANIM`, 3 `TRANSF`, 4 откат по `D+0x2c` (3→4 `UTRANSF`, 5→6 `UDOPPEL`, 7→8
`UDRAINLVL`, 9→10), 5 `DOPPEL`, 6 `UDOPPEL`, 7 `DRAINLVL`, 8 `UDRAINLVL`, 9 призыв — пустая картинка на `[esp+0x10]` кадров
(`0x654d40`), 10 `USUMMONANIM`. Суффикс `L|S` — `D+0x25` (большой). Нет картинки (убит, отступил, мгновенно) — al=0, сразу `0x653219`.
Код после отката — прочитать `[D+0x2c]` после вызова (когда вход 4). Кадры — из `0x652932` (§2) или `eax` у `0x6529c3`.

Вызовы (возврат → причина): `0x636ddf` код 0, шаг 15; `0x6535e2` код 1, смерть после HHIT; `0x652305` код 9, призыв; `0x63c700` код 7,
вытягивание (реакция); `0x63c852` код 4, шаги 13/16; `0x63c7c2`, `0x65212e`, `0x65237e`, `0x6533cc` — код по типу превращения (`0x65214b`).

## 4. bat_fx — HEFF и TUCH

- **HEFF**: строка из `0x646ec5` с возвратом `0x63a177` (тело, слой 799/1399) и `0x63a236` (тень); `0x639f2b` зовётся только через
  functor кадра удара. Имя — последний `bat_img` с действием `HEFF` (загрузка в подготовке шага `0x634e0b`, `0x6357a2`) — ранг 2 по
  порядку.
- **TUCH** — `0x636239` (stdcall ret 0x24):

```
0x636239: push ebp / mov ebp,esp / sub esp,0x20
0x63624b: mov eax,[ebp+0x20] / mov ecx,[eax+8]   ; holder → картинка
0x63625b: call 0x63633c        ; CBatMiscAnim (ctor 0x656eb0), 0 → нет картинки
0x636275..: call 0x646ec5 (*sub=7, pos=[ebp+0xc], left=[ebp+0x14])
0x636339: ret 0x24
```

  Возврат `0x63a8fb` — TUCH на цели (стадия `0x63a464`, цикл по целям без промаха и иммунитета: `[rec+8]==0 && [rec+9]==0`);
  `0x63618a` — тик яда/мороза/ожога (`0x635ecc`, картинки `0x647c9f/cec/d39` = `POISONANIM`/`FROSTBITEANIM`/`BLISTERANIM`, `0x7ae794…`);
  `0x63c471` — картинка на вылеченном переливом (`0x63c27d`, ранг 2 по смыслу). Имя TUCH — последний `bat_img` с `TUCH`/классом.
- Конец каждой — `CBatMiscAnim` → `0x6572fa` (`CAnimCounter −1`).

## 5. bat_show — `0x630a7b` (шаги 0..16)

```
0x630a96: mov [ebp-0x58],ecx              ; interf+0x18
0x630ac6: mov byte ptr [edx+0x14e0],0     ; V+0x14e0 = «шаг идёт»
0x630b06: mov edx,[ebp+0xc] / mov eax,[edx] ; R
0x630f49: cmp [ebp-0x6c],0x10 / ja ...
0x630f56: jmp [edx*4+0x6310b3]           ; таблица 17 обработчиков
0x631096: ret 0xc
```

Шаги (таблица `0x6310b3`, текст обработчика — ранг 1 по строке, смысл — по тексту): 0 атака `0x634b78`; 1 «Pass» `0x635a9c`
(`X008TA0010`); 2 отступление — разворот (`0x63cbbb`→`0x652032`); 3 отступил — скрыть (`0x63cbe8`→`0x65205d`); 4 снят паралич
(`X008TA0024`); 5 снято окаменение (`X008TA0025`); 6 яд (`X008TA0014`, `POISON`); 7 мороз (`X008TA0015`, `FRSTBITE`); 8 ожог
(`X160TA0022`, `BLISTER`); 9 «Wait» (`X008TA0020`); 10 «Defend» (`X008TA0021`); 11 только `0x638298(0)` (без показа, смысл — ранг 3);
12 предмет `0x6365f2`→`0x651c9c`; 13 «Restore Form!» `0x63679b(0)`; 14 «Unsummon» `0x6368c3`; 15 рост `0x6369ee`; 16 «Recover Level»
`0x63679b(1)`. Шаг 0: замах только при `R+0xc==1` и не `0x634dd2` (`0x634b78`, ранг 1).

## 6. Конец шага — `0x637473` / `0x638183`

`0x637473` — тик вида (functor из конструктора `0x62d305`, раз в кадр): читает «готово» счётчика `V+0x14d8`; когда стало 0 —
`0x638183(0)`, `V+0x14e0 = 1` и уведомление `[[V2+0xa8]]->vt[0xc]` (`V2 = [interf+0x20]`). Писать конец по хуку `0x638183` с
`[esp] == 0x63751e` (другие вызовы `0x638183(0)` — `0x63ab35` в реакции, это обновление панелей, не конец). Особый путь: у шага 15 при
`[V2+0xc1]` `0x630a7b` ставит `[V2+0xc2]=1` и выходит, конец — `0x6374d4` (без `0x638183`).

```
0x6374e5: call 0x649b4d   ; [[ctr+4]+4] «готово»
0x6374fa: call 0x649b61   ; −1
0x63750b: call 0x649b4d / jne 0x637548
0x637514: push 0 / call 0x638183          ; ← возврат 0x63751e
0x637524: mov byte ptr [edx+0x14e0],1
0x637545: call [eax+0xc]                  ; уведомление интерфейса боя
```

Счётчик шага: +1 — `0x649ac3` у каждой запущенной анимации (тело `0x653fe1`, `0x65449a`, предмет `0x65201d`, эффект `0x652949`,
TUCH `0x657053`, надписи `0x64cfc3`/`0x64d154`), −1 — `0x649ae9` по концу (`0x6531d6` тело, `0x6572fa` TUCH, `0x64d495` надпись,
`0x64c25a`). Значит шаг ждёт и надписей (их срок — 15/10/5 тиков панели при скорости 1/2/3, `0x64a4cd`). Ранг 1 (было 2).

## 7. bat_note — `0x64d09c` надписи

```
0x64d0a3: mov [ebp-0x24],ecx

## 8. bat_snd — `0x5c1dec` и юнит

```
0x5c1dec: push esi / mov esi,[esp+0x10]          ; functor
0x5c1df1: push esi / push [esp+0x10] / push [esp+0x10] / push [ecx]
0x5c1dfc: call 0x5c1e28   ; → 0x56731a (проигрыватель)
0x5c1e25: ret 0xc

Громкость — `{[+0] 0..100, [+4] 64}` (`0x51fb30`, `0x51fb40`). Юнита в аргументах нет; кадр вызывающего не сохраняется (у
`0x5c1dec` нет пролога `ebp`, но и `ebp` вызывающего разный). Предлагаемое: хуки на входы тех функций CBatUnitAnim, что зовут звук,
кладут `ecx` в переменную потока, хук `0x5c1dec` берёт её по адресу возврата:

при старте. `0x5c0fcc` (`ret 0x10`) — выбор варианта из `.LST`; его зовут поиск имени по типу юнита (thiscall, `ret 4`,
`[esp+4]` id типа, eax = `char*`): `0x5c11d3` замах (+4), `0x5c1232` HEFF (+0x30), `0x5c0f2f` TUCH (+0x5c), `0x5c1291` «больно» (+0x7d);
кадры — `0x5c1338` (+0x28), `0x5c12f0` (+0x2c), `0x5c1308` (+0x54 effectFrame), `0x5c1320` (+0x58 длительность HHIT). Вызываются при
подготовке шага (раньше звука), годятся для строки «тип → выбранное имя».

## 9. Что осталось на ранге 2–3

- Смысл `vtbl+0x10` IMqImage2 = «число кадров» — ранг 2 (место вызова — ранг 1).
- Имя для HEFF/TUCH сопоставляется с картинкой по порядку (`bat_img` раньше `bat_fx`) — ранг 2; надёжнее писать имя из `0x5c7587` в
  подготовке `0x634e0b` и позицию из `0x636239`.
- Шаг 11 — что за сообщение, не прослежено (ранг 3).
- Флаг `+0xa` записи цели: 0 → «Ward», иначе «Immune» — ранг 2 по тексту.
