# Разбор Discipl2.exe: анимации карты, прокрутка, курсоры, ролики, тик кадра (для зонда)

Discipl2.exe GOG 3.01, база 0x400000. Всё — по листингу `d2dis.py` (capstone), игра не запускалась. Ранги: 1 — проверено по
листингу, 2 — по косвенным признакам, 3 — догадка. «thiscall» = this в ecx, аргументы на стеке, вызываемый чистит (`ret N`).
Запись `[[a+8]+0x20]` = поле 0x20 блока данных, на который указывает поле 8 объекта.

Общий список STL движка (очередь анимаций, ключевые кадры хода, точки прокрутки — один шаблон, `0x4078cb`/`0x40b2e8`/`0x4f822b`):
`{+0 count, +4 head(узел-страж)}`, узел `{+0 next, +4 prev, +8 значение}`; первый элемент — `[[list+4]]+8` (ранг 1: `0x40b50b` —
`dec [list]`, отцепление узла; `0x4f61d4` — пусто, если `[list]==0`). Умный указатель `{+0 int* refcnt, +4 T*}` (`0x55b7bc`).

## 1. Очередь анимаций карты (`Impl@CMidAnim2System`)

Поля `Impl` (конструктор `0x40ab78`, thiscall, `ret 0x14`): `+0` vptr `0x6ccacc` (слот 0 = `onTick` `0x40ae5f`), `+4` vptr `0x6ccabc` (слот 1 =
`onCommand` `0x40b0ba`), `+8` очередь (count `+8`, head `+0xc`), `+0x1c/+0x20` итератор текущей задачи, `+0x3c` медленный и `+0x40` быстрый
`CTwoSpeedAnimator`, `+0x44` очередь команд клиента (`CMidCommandQueue2`), `+0x4c` сохранённый флаг вида, `+0x4d` «пакет идёт».

`onCommand` (`0x40b0ba`, thiscall(Impl+4), `ret 0`): берёт текущую команду (`0x410162`), фабрика `0x4f2ad0` складывает задачи в локальный
список, каждая — `0x40b36f` в очередь; если очередь пуста — сразу `0x410236` (следующая команда).

```
0x40b1d4: call 0x4f2ad0            ; фабрика задач команды (stdcall, ret 0x18)
0x40b220: mov byte ptr [ebp-4], 1
0x40b224: call 0x40b36f            ; ecx = esi+4 = Impl+8 — push_back(SmartPtr*)
```

`onTick(bool fast)` (`0x40ae5f`), по листингу:

```
0x40ae75: cmp [esi+8], 0 ; je конец                 ; очередь пуста
...  итератор == страж (head [esi+0xc], alt 0)?  -> «не начато»:
0x40aec9: call [eax+0x14] ; cmp al,[ebp+8] ; jne конец   ; группа первой задачи != группа тика
0x40aef6: mov [esi+0x4c], al ... 0x40af24: mov byte [esi+0x4d],1  ; первый старт пакета: запомнить/запереть вид
0x40af3a..: итератор = первый узел ; 0x40af54: call [edx+8]       ; vt[2] старт
... «начато»:
0x40af6f: call [edx+0x14] ; cmp al,[ebp+8] ; jne конец   ; не своя группа
0x40af8e: call [edx+0x10] ; test al,al ; jne +          ; vt[4] isDone?
0x40afa8: call [edx+4]                                    ; vt[1] шаг
0x40afbe: call [edx+0x10] ; je конец                      ; ещё не кончилась
0x40afdc: call [edx+0xc]                                  ; vt[3] конец
0x40afe6..: итератор++ ; 0x40aff9: call 0x40b355          ; снять голову (уничтожить)
0x40b019: очередь кончилась -> clear, вид назад (0x540b4e(сохранённый)), [esi+0x4d]=0, 0x40b064: call 0x410236 (следующая команда)
0x40b07e: иначе: группа следующей == группе тика ? 0x40b0a6: call [eax+8] (старт сразу) : итератор = страж
```

Текущая задача для зонда (на входе и на выходе `0x40ae5f`): «начато», если `[Impl+0x20] != 0 || [Impl+0x1c] != [Impl+0xc]`; тогда
`A = [ ([Impl+0x20] ? [Impl+0x20] : [Impl+0x1c]+8) + 4 ]`. Правило: A после вызова ≠ A до вызова → старт A(после), `start_t`; тик
считать, если до вызова было «начато» и `[[A+4]] == [esp+4]` (байт группы). Конец — на входе `0x40b355`: `A=[[[ecx+4]]+0xc]`, класс и поля
читать здесь (объект ещё жив, на выходе освобождён `0x55b7bc(0)` → удаляющий деструктор). `ticks` у анимаций-наследников
`CMidAnim2Animation` = `[[A+8]+4]` (число кадров). Ранг 1.

Особые случаи: задача, чей `isDone` истинен уже после старта, кончается на следующем тике своей группы (1 тик); пакет команды —
последовательные задачи, часто сначала `CMidAnimSmoothScroll`. Деструктор `Impl` (`0x40adac` → `0x40b394` в `0x40ae33`) очищает очередь
без `finish` — при уходе с карты; конец в журнале у таких задач не появится (ранг 1).

## 2. CTwoSpeedAnimator и группы аниматора

- `0x40ac86` CTwoSpeedAnimator(bool fast, Impl* owner), thiscall `ret 8`: `[this+4]=fast`, `[this+0x10]=owner`, регистрация
  `animator->vt[1]` (быстр.) или `vt[0]` (медл.) — `0x40acd3`/`0x40ace2`; деструктор `0x40ad23` — `vt[3]`/`vt[2]`. Его `animate`
  `0x40acf5`: `mov eax,[esp+4]; mov ecx,[eax+0x10]; mov al,[eax+4]; push eax; call [[ecx]]` → `Impl::onTick(fast)`, `ret 4`. В группы
  попадают **только эти два объекта**, отдельные `CMidAnim2*` в аниматор не регистрируются (ранг 1).
- Аниматор = `[R+0x80]` (`CRendererImpl` R; `0x516580` даёт интерфейс `IMqAnimator2` = `R+0xc`, его слоты `0x518fc0/0x518fe0/0x519000/0x519020`
  при `[R+0x68]==0` зовут `0x51dc10/0x51dd20/0x51de30/0x51df80` с `ecx=[R+0x80]`).
- Группы создаются в `0x51d871` (`[g+0x34]=0x42`, кладётся в `[S]`) и `0x51d929` (`0x21`, в `[S+4]`), `S=[Animator]`.
- Тик `0x51e0d0` (thiscall(Animator), единственный вызов `0x517a59` в конце кадра): для `slow=[[ecx]]`, потом `fast=[[ecx]+4]`:
  `now = clock()`; если `now ≥ [g+0x38]`: `[g+0x40]=1`, каждой анимации списка `+8` — `push a; call [[a]+4]` (IMqAnimation vt[1]),
  отложенные добавления/снятия из `+0x24`, `[g+0x38] = now + [g+0x34]` (без догона), **`inc [g+0x3c]`** (`0x51e247`).

```
0x51e0e4: call 0x5613e1        ; часы
0x51e0ee: cmp ebp, eax ; jb ...  ; now < next
0x51e168: call dword ptr [ecx + 4]   ; animate(a)
0x51e23b: mov eax,[esi+0x34] ; add eax,ebp ; mov [esi+0x38],eax ; mov eax,[esi+0x3c] ; inc eax ; mov [esi+0x3c],eax
```

- Часы `0x5613e1` → `CMqUIKernelSimple` vt+0x38 = `0x56227a` (`[[k+4]+0x30]`) — **время, снятое `timeGetTime` один раз за оборот цикла
  сообщений** (`0x5620ae`: `call [timeGetTime]; mov [edi+0x30], eax`), не «живое» время (ранг 1).
- Для зонда (ранг 1): ничего не хукать в 0x51e0d0; в хуке кадра (8б) взять `Animator=[ecx+0x7c]`, раз в секунду писать
  `anim_clock {slow_ticks: Δ[[A]]+0x3c, fast_ticks: Δ[[A]+4]+0x3c, slow_n: [[[A]]+8], fast_n: [[[A]+4]+8]}`. Число в группе — `count`
  списка `+8` (вставка `0x51ad60`: `inc [esi]`); пока идёт обход (`+0x40`), новые лежат в `+0x24` (ранг 1). В медленной — сотни
  (каждая анимированная картинка карты, курсоры, окна); в быстрой — 1 (`CTwoSpeedAnimator` карты) + чат/титры/прокрутка текста.

## 3. Ход отряда (`CMidAnim2Unit`)

Цепочка: команда хода → `0x4f7dbc` режет путь на отрезки (элемент 0x18 байт: `from.x, from.y, to.x, to.y, +0x10, +0x14`), перед
отрезком — прокрутка `0x4f4a0c` (`0x4f7f9b`), затем `0x4f5851` → конструктор `0x4f5e51` (`0x4f59c3`). Одна задача = один отрезок
(ранг 1 по `0x4f7f60`…`0x4f7fe5`, смысл «отрезок = прямой участок» — ранг 2).

Конструктор `0x4f5e51` (thiscall, `ret 0x18`): `a1` objMap → `[D+0]`, `a2` отрезок, `a3` список → `[D+0x30]`, `a4` CMidgardID* отряда →
`[D+4]`, `a5` байт → `[D+0x58]`, `a6` байт → `[D+0x75]`; `D=[this+8]` (0x78 байт, `0x4f60fc`); `[D+8]` = свой отряд (`0x4f5b41`);
ключевые кадры строит `0x4f5b8d(D+0x20, a2, own, speed)` (`0x4f5f7b`); `[D+0x5c],[D+0x60]` и `[D+0x68],[D+0x6c]` = `to`.

```
0x4f5e74: call 0x61a5fd          ; StackSmoothScroll
0x4f5e79: push eax
0x4f5e7c: call 0x4f1137          ; база: группа = флажок (1 — 33 мс)
0x4f5eb6: mov [eax], ecx         ; D+0 = a1
0x4f5ec5: mov ecx,[ecx] ; mov [eax],ecx   ; D+4 = *a4 (id отряда)
0x4f5ef2: mov [eax+0x5c], ecx    ; D+0x5c = a2->to.x ; 0x4f5ef8: D+0x60 = a2->to.y
0x4f5f7b: call 0x4f5b8d          ; ключевые кадры в D+0x20
```

- Число кадров: `[[A+8]+0x20]` после конструктора или на старте (`0x4f6ac9`); isDone `0x4f61d4` = `[D+0x20]==0`; шаг `0x4f61e2` снимает
  один кадр (`0x4f6224: call 0x55e778` — pop_front), ставит картинки, центрирует вид (`0x4f6539`), в конце пути — `0x4f6671`.
- Элемент кадра (`0x4f5d8c`…`0x4f5de3`, запись `[ebp-0x5c]`): `+0 x, +4 y, +8 dx, +0xc dy, +0x10 байт «первый кадр шага», +0x14 to.x,
  +0x18 to.y` (ранг 1). Кадров с `+0x10`=1 — число клеток отрезка.
- Писать: на 3а — `{A, stack=[D+4], from=a2[0..1], to=a2[2..3], frames=[D+0x20], group=[[A+4]]}`, на конце (1г) — `ms`; кадр не писать.
  Склейка отрезков одного отряда подряд в одну строку — на стороне зонда (ранг 2: подряд в одном пакете команды).

## 4. Прокрутка вида

- `CMidAnimSmoothScroll`: ставит `0x4f4a0c` (stdcall, `ret 0x18`): центр вида `0x540b6c`, «только если далеко» — `|Δ|≥2` по оси
  (`0x4f4a7c`), объект `0x4f490b` (группа 1, `0x4f4920: push 1 → 0x4f1137`), `D=[a+8]`: `[D+0]=a1`, `[D+0x14],[D+0x18]` цель, при
  `SmoothScroll` — список точек `D+4` (`0x4f4b51`, элемент `{+8 dx, +0xc dy}` узла). Старт `0x4f4e19`: без `SmoothScroll` — сразу
  `0x540c38(цель,0,0)`, иначе шаг; шаг `0x4f4dac`: `0x540c38(цель, node.dx, node.dy)`, pop; isDone `0x4f4e8e`: `[D+4]==0`; конец `0x4f4e83`:
  `0x5ad312(0x8385cc)` (обновление слоя, ранг 2).

```
0x4f4dd9: push dword ptr [esi + 0xc]   ; dy   (esi = первый узел списка точек)
0x4f4de3: add ecx, 0x14                ; ecx = D+0x14 (цель)
0x4f4de6: push dword ptr [esi + 8]     ; dx
0x4f4de9: push ecx                     ; &цель
0x4f4ded: call 0x540c38
0x4f4e06: call 0x55e778                ; снять точку
```

- Смена центра: `0x540c38` (thiscall(MapGraphics*), `ret 0xc`; клетка вне `0…N−1` — выход `jl/jge 0x540d31` без смены) и `0x541271`
  (thiscall, `ret 4`, направление 0..7). Обе на успехе зовут `0x540d37(listeners=[mg]+0x48, mg, &центр)` (`0x540d2b`, `0x541361`) — **одна
  общая точка**: `[esp+0xc]` = CMqPoint* новой центральной клетки (уже посчитанной `0x540b6c`).
- Причина — по адресу возврата из `0x540c38` (вызовы: `0x4f4df2`/`0x4f4e68` плавная прокрутка, `0x4f653e`/`0x4f6676` ход отряда, `0x4f47b2`/`0x4f487e`
  тряска, `0x5cbcd6`/`0x5cbdc5` мини-карта, `0x4d1cc2`/`0x4d1d26` (рядом с `CTaskSelectUnit` `0x4d1c25` — выбор, ранг 2), `0x4070e1`, `0x48e2a8`, `0x48edb6`, `0x491548`, `0x4b3e9f`,
  `0x540e8a`, `0x5418a0` — прочие, не разбирал) и из `0x541271` (`0x541b30` — шаг ручной прокрутки, `0x541481` — скольжение у края).
- Писать агрегатом: серия смен центра одной причины с промежутками < ~200 мс → `view_scroll {reason, from, to, steps, t0, t1}`. Чтобы
  взять причину на `0x540d37`, достаточно хука `0x540c38`/`0x541271`, запоминающего адрес возврата в поток-локальную переменную (ранг 1).

## 5. Туман (`CMidAnim2ChangeFog`)

Фабрика `0x4f1a29` (stdcall, `ret 0x14`, вызов только `0x4f354b` из фабрики команд — после прокрутки к клетке `0x4f351d`). Поля
`D=[a+8]` (`0x4f1945`, 0x30 байт): `+0` done, `+1` «открыть» (`a3`; `0x4f354b` передаёт `!0x47a0e0()`), `+4` сторона s, `+8/+0xc`
центр, `+0x10` кольцо (1), `+0x14` objMap, `+0x18` id игрока, `+0x1c..+0x28` рамка, расширенная на радиус и зажатая (`0x4f1aad`…`0x4f1b06`).
Старт `0x4f1d16`: при «закрыть» (`[D+1]==0`) — предпроход `0x4f1d39`, затем шаг; шаг `0x4f1b63`: кольцо, конец при `кольцо+2 > s`
(`0x4f1b9f`); клетка — `0x5f3bdc` (`0x4f1c6c`).

```
0x4f1b9a: mov ecx, [eax+0x10] ; inc ecx ; inc ecx
0x4f1b9f: cmp ecx, [eax+4] ; jle + ; mov byte [eax], 1      ; done
0x4f1c6c: call 0x5f3bdc                                      ; туман клетки (ret 0xc)
```

Писать: на выходе фабрики — `fog_anim {A, player=[[D+0x18]], center=(D+8,D+0xc), side=[D+4], open=[D+1]}`; на конце (1г) — `ms`,
`rings` = число тиков, `cells` — счёт `0x5f3bdc` с возвратом `0x4f1c71`/`0x4f1dde` между стартом и концом (если хук `0x5f3bdc` дешёв: у него
ещё 6 вызовов из модели — фильтр по адресу возврата). Ранг 1.

## 6. Курсор

- Показ: обработчик движения мыши `0x540175` (`CCursorImpl`, подобъект +8, vtable `0x6e1e5c` слот 1): если включён (`vt[2]` = `0x54015c`),
  курсор = `CCursorImpl::get` (`0x54021c`: тащимое `+0x14` → иначе верхний интерфейс), и, если не 0, — `0x532f69(курсор, a, &pos)`. Других
  вызовов `0x532f69` нет. Курсор «поверх всего» ставит `0x540163` (thiscall, `ret 4`).

```
0x5401b0: call dword ptr [eax]      ; get(out, pos) -> [ebp-0x14]{refcnt, holder}
0x5401c7: je 0x5401fe               ; никто не дал курсор — не меняем
0x5401ec: mov ecx, dword ptr [ebp - 0x10]   ; holder
0x5401f9: call 0x532f69
```

- Держатель курсора — 4 байта, `[holder]` → данные 0x20 (`0x532d61`): список слоёв «картинка + точка» (`0x532df9` добавляет слой), `+0x10..0x1c`
  — рамка. Имени в объекте нет. Имя берётся при создании: карта `0x5b27ee` (номер → таблица `0x6ec008`), бой `0x5b345e` (номер → `CU*`),
  окно `0x50cd54` → `0x532ce6` (`0x50d13a`; имя из разметки окна — у всех `_CUDEFAUL`, см. `docs/ui-windows.md`), прочие — по адресу возврата
  `0x532ce6` (6г).
- Писать: в хуке `0x532f69` — если `ecx != прежний` → `cursor {name из словаря | "?"+адрес создателя}`. Ранг: смена указателя — 1; «смена
  держателя = смена видимого курсора» — 2 (кэш задачи карты отдаёт один держатель на вид, `0x4cf8fa`).

## 8. Тик кадра

Цикл сообщений `0x562004`: `timeGetTime` → `[kernel+0x30]` (`0x5620ae`) на каждом обороте; `PeekMessage`/`GetMessage`; при пустой очереди —
обработчики простоя `[eax+0x58]→vt+0x4c` (`0x56211d`), среди них `CMqPresentationManager` `0x516590` (зарегистрирован `0x515eb3`,
`bool`), который при активном окне (`0x5613d6`) зовёт кадр `0x5164a0`:

```
0x5164a8: mov cl, [eax+0x44] ; test cl,cl ; jne выход     ; уже рисуем
0x5164c5: call [edx+8]           ; renderer->beginFrame
0x51650e: call [ebp+4]           ; каждое представление ->draw
0x516535: call [edx+0xc]         ; renderer->endFrame = 0x5179f0
0x51653d: mov byte [eax+0x44], 0
```

`0x5179f0` (thiscall(R+4), `ret 0`): сборка грязных прямоугольников, `[[esi+0x10]]+0x30` (вывод), `0x51d580`, **`0x51e0d0` (тик аниматора)**,
объединение прямоугольников `0x518810`. Писать: хук `0x5164a0` (или `0x5179f0`) — счётчик кадров и `timeGetTime()` на входе; раз в секунду
`frames {n, max_ms, avg_ms}`. Частота — сколько успевает цикл (ограничителя кадров в этой цепочке нет; ожидание — только в выводе
`[..]+0x30`, не разбирал — ранг 3). `0x516650` (функтор `CMqPresentationManager`, `bool`) — тот же кадр по требованию (ранг 2).
