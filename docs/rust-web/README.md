# Rust Web: документация будущего этапа развития

Дата исследования: **22.09.2026**. Статус: **проект решения, реализация не начата**.

Этот комплект описывает будущую игру полностью в браузере: Rust → WebAssembly,
лёгкий 2D-фреймворк и Rust-сервер сетевых партий до пяти игроков.
Документы не меняют текущую задачу Godot-порта и не являются поручением начинать перенос.

## Обязательный порядок работ

1. Завершить рабочий desktop-порт на Godot, воспроизводящий оригинал по поведению и виду.
2. Зафиксировать проверенный выпуск, правила, ресурсы, тесты и корпус как эталон.
3. Начать отдельный Rust-проект и доказать воспроизведение эталона.
4. Развивать игру по собственному замыслу через явно версионированные изменения правил,
   интерфейса и содержимого.

Рекомендуемое место будущей реализации — отдельный репозиторий. Текущая рабочая копия
Godot не превращается в Rust-проект и остаётся источником эталонных результатов.
Существующие [принципы порта](../principles.md) продолжают действовать для Godot.
Для будущего продукта сохранение совместимого набора правил — средство проверки миграции,
а не запрет на последующее развитие.

## Базовое решение

- Клиент: Rust/Wasm + **Macroquad** как исходный кандидат; окончательное принятие
  после браузерного прототипа с настоящими ресурсами.
- Браузерный адаптер: небольшой JavaScript-слой для Fetch, хранилища, media,
  WebSocket и Worker. «Полный Rust» относится к игровой реализации, не запрещает этот слой.
- Одиночная симуляция: локально в браузере, сервер не рассчитывает ходы.
- Сетевая симуляция: тот же Rust-модуль правил на авторитетном сервере.
- Сервер: один сервис Axum/Tokio с ограниченным пулом вычислений и PostgreSQL;
  ресурсы — статическое хранилище за CDN.
- Графика: страницы атласов, ограниченная резидентная память, догрузка по зависимостям.
- Загрузка: меню → выбранный сценарий → выбранная раса → стартовая сцена → остальное.
- Плавность: собственный темп исходных анимаций, рендер до 60 FPS; режим 30 FPS
  допускается после проверки прокрутки и управления.

## Как трактовать числа и решения

**Измерено** — получено чтением текущих файлов; метод указан в документе 08.
**Цель** — предварительный бюджет будущего продукта, не результат профилирования.
**Решение** — предлагаемое устройство первой версии, подлежащее проверке прототипом.
**Отложено** — не включать в начальную реализацию без обоснованной потребности.

Rust не гарантирует заданное ускорение, уменьшение памяти или число комнат на сервере.
Числа из обсуждения о возможных кратных ускорениях не используются как требования.
Разделение загрузки, устройство рендера и модель серверных партий проверяются отдельно
от выбора языка. Отсутствие GC у Rust не исключает задержки аллокатора, браузера,
декодирования, загрузки текстур или JavaScript GC.
