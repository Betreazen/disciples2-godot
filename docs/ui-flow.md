# Граф экранов (`data/ui/flow.json`)

Какой элемент какого экрана куда ведёт, какие окна всплывают сами и где меняется фаза игры (меню → партия →
бой → обратно). Граф — **данные порта**, как `screens.json`: ключи — `Id` экрана и `Id` элемента из
`screens.json`, мод накладывает свой `data/ui/flow.json` поверх базового. Выведен из журналов зонда
(схема 7.0, `docs/corpus-schema.md` «Схема 7.0») и правится руками наравне с тем, что выдал импорт.

## Формат

```jsonc
{
  "Sources": ["20260919-human/passive-001.jsonl", "20260918-probe65/passive-001.jsonl"],
  "EngineScreens": [ { "Id": "CEncyclopediaPopup", "Kind": "popup" } ],   // экраны движка без разметки
  "Screens": [
    {
      "Id": "DLG_CHOOSE_LORD",
      "Phases": ["Menu"],                                   // фазы, в которых экран встречался
      "Edges": [
        { "Element": "BTN_CONTINUE", "Action": "Goto", "Target": "DLG_SCENARIO_BRIEFING",
          "Via": "DLG_WAIT", "Phase": "Game", "Seen": 2 },
        { "Element": "TOG_LORD_MAGE", "Action": "None", "Seen": 2 }
      ]
    }
  ]
}
```

| Поле перехода | Смысл |
|---|---|
| `Element` | `Id` элемента экрана. **Нет поля** — переход не от элемента интерфейса: щелчок по карте, правая кнопка, ход ИИ, событие сценария, таймер |
| `Action` | `Open` — цель встаёт поверх (текущий остаётся под ней); `Goto` — цель встаёт вместо текущего; `Close` — текущий закрывается; `Panel` — внутри экрана сменилась вложенная панель (закладки постройки, панель ожидания хода); `None` — обработчик сработал, экран не сменился |
| `Target` | `Id` экрана цели (`Open`/`Goto`/`Panel`) |
| `Via` | промежуточный экран между текущим и целью: анимация смены меню `DLG_MENU_TRANS`, «подождите» `DLG_WAIT`, заставки, быстрая загрузка |
| `Phase` | фаза после перехода: `Menu`, `Game`, `Battle` |
| `Message` | id текста окна сообщения, которое переход показал (`X005TA0265` — «Нанять героя за …?») |
| `Seen` | сколько раз переход встретился в журналах; мод может не писать |

У одного элемента бывает несколько исходов: «Загрузить» ведёт в партию или к окну ошибки, «ОК» окна сообщения
закрывает его или открывает следующее. Поэтому **мод заменяет все переходы элемента разом**: переходы мода
с `Element = X` вытесняют все базовые с `Element = X` у того же экрана, прочие остаются
(`UiFlows.Merge`, `src/D2.Data/Ui/UiFlow.cs`). Экраны опознаются по `Id` без учёта регистра, новые
добавляются в конец. Слои складывает `GameContent.Load` — так же, как экраны и кадры.

Проверки (`src/D2.Data.Tests/UiFlowTests.cs`): каждый экран, цель, `Via` и элемент графа есть в
`screens.json` или в `EngineScreens` (и экраны движка в `screens.json` не встречаются); числа переходов
закреплены; пересборка из корпуса совпадает с файлом байт в байт; правило пары — на коротких выдуманных
журналах.

## Ручные дополнения (`data/ui/flow.manual.json`)

Переходы, которых зонд не видел, но которые известны (со слов пользователя или по игре), лежат отдельным

`GameContent.Load` накладывает ручной файл поверх импортного тем же `UiFlows.Merge` (переходы элемента

## Исполнение (`UiNavigator`, `UiFlowView`)

`UiNavigator` (`src/D2.Data/Ui/UiNavigator.cs`) держит стек экранов и фазу: `Open` кладёт цель поверх,
`Goto` заменяет верхний, `Close` снимает верхний, `Panel`/`None` стек не трогают; пустой стек — выход из
игры. У элемента с несколькими исходами выбор за логикой экрана; без неё берётся исход со сменой экрана,
из них самый частый. Сцена `godot/scenes/ui/UiFlow.tscn` (`UiFlowView`) — узел на каждый экран стека, ввод
только у верхнего. Какой элемент сработал с точки зрения графа: кнопка и переключатель — сами, в группе —
выбранный участник, в списке — подтверждение выбора. Промежуточные экраны (`Via`) и текст окна сообщения
пока только печатаются.

Проверка без окна — `python tools/ui-render-check.py` (`FLOW_CASES`) или руками:

```sh
"C:/Tools/bin/godot.cmd" --headless --path godot res://scenes/ui/UiFlow.tscn -- --no-mods --input "click BTN_SINGLE; click BTN_NEW_SKIRMISH; key 13; key 13; key 13"
```

## Ролики смены экранов (`data/ui/transitions.json`)

Граф знает, что смена идёт через `DLG_MENU_TRANS`, но не знает, какой ролик на нём играет. Пара экранов →
ролик задана данными по именам роликов `Interf/MenuAnim.ff` (`TRANS_MAIN2SINGLE`, `TRANS_GOD2LORD_{RACE}` —
код выбранной расы подставляется). Пары, которой нет, — смена без ролика: так в игре «Назад» (со слов
пользователя). Пока ролик идёт, ввод выключен; щелчок или клавиша его пропускают.

Движок (разбор 11.10): смена вперёд — `0x4ea230` строит `CMenuFullScreenAnim` (vtable `0x6db0fc`, экран `DLG_MENU_TRANS`,
конструктор `0x4da6fa`), ролик ставится **по центру экрана** (`0x4da85c`: (экран − ролик) / 2), по последнему кадру — новое
меню (`0x4daa9a`). Растворение старого экрана в новый нарисовано в самих роликах (`TRANS_SINGLE2NEW`, `TRANS_NEWQUEST2GOD` —
по кадрам), порт его не делает. Поэтому ролик стоит на месте экрана 800×600 с тем же масштабом, что экраны
(`UiScreenView.Letterbox`), а не тянется во всё окно 16:9 (замечание пользователя 11.10, снимки 1 и 4). «Назад» — `0x4ea2ff`
и соседи зовут `0x4ea33b`, который ставит меню сразу, без `CMenuFullScreenAnim`; граф (журналы зонда) ведёт «Назад» со всех
экранов одиночной игры в главное меню. Поля окна вокруг экрана — чёрные (`GameData`, цвет очистки кодом). Проверка —
`ui-render-check` («логика новой игры»: `vrect` ролика 4:3 по центру, `flow clear=000000`).

## Логика экранов меню (`src/D2.Data/Menu`)

Выбор сценария, расы, лорда и брифинг наполняются логикой (`IScreenLogic`) из каталога `data/game`: список
сценариев, круг рас сценария, лорды расы, тексты брифинга. Хозяин (`UiFlowView`) спрашивает у логики верхнего
экрана `Allows(элемент)` перед переходом: «Продолжить» без выбранного сценария игру не начинает. Окно сообщения,
открытое переходом с `Message`, показывает текст этой строки.

Проверка без окна — `--probe ЭЛЕМЕНТ,…`: после каждого шага строка с текстом, кадром, роликом и пунктами списка
элемента; на ней стоит `CONTENT_STEPS` в `tools/ui-render-check.py`.

## Начальные значения экранов (`data/ui/defaults.json`)

Какой участник группы переключателей отмечен при открытии экрана: `{ "DLG_CHOOSE_LORD": { "RAD_DIFF":
"TOG_DIFF_AVERAGE" } }`. Старая разметка этого не хранит — ставил код экрана. Группа, которой в файле нет,
открывается с первым участником. Мод кладёт свой `data/ui/defaults.json`: его группа заменяет ту же группу базы.

## Правило пары щелчка и смены экрана

Журнал читается по `seq` (порядок вызовов) в потоке интерфейса. Каждое `ui_click` открывает **вспышку** —
следующие события того же потока, пока не случится одно из:

1. следующее `ui_click`;
2. `input` — игрок нажал что-то ещё;
3. разрыв по `t` больше **500 мс** (самое долгое честное следствие щелчка в журналах — 344 мс: конец хода
   меняет панель карты на панель ожидания).

Пока наверху стека промежуточный экран или стек пуст (`top = none`: старый экран снят, новый ещё строится),
вспышка не рвётся ни по разрыву, ни по `input`. Так ловится `DLG_PROTOCOL`, который после анимации смены
строится 2,6 с (`20260919-human` seq 192 → 194), и загрузка карты за `DLG_WAIT`.

Итог вспышки:

- показан экран не из промежуточных — **первый** такой и есть цель. Верхний на момент щелчка экран снят —
  `Goto`, иначе `Open`. Окно, всплывшее следом над целью («Ход 21» над картой), остаётся в `Message`;
- цели нет, верхний снят — `Close`;
- стек не менялся, но диалогов открыто больше, чем закрыто (по имени), — `Panel` с первым таким диалогом.
  Пересоздание одного и того же диалога (`DLG_ISO_PAL` пересоздаётся на каждое действие на карте) гасится;
- иначе `None`.

События стека вне вспышек щелчков начинают свою вспышку с тем же правилом: источник — верхний экран до неё,
элемента нет. Так же начинает вспышку `ui_msgbox` — окно подтверждения, вызванное щелчком по картинке здания
(это не кнопка, `ui_click` его не видит), получает свой `Message`.

Фаза: `game_phase enter` внутри вспышки — `Game`, `leave` — `Menu`; экран боя в стеке — `Battle`. Фазы экрана —
фазы после вспышек, где он показан (заставка сценария показывается до `game_phase enter`, но принадлежит партии).

Три поправки к модели стека — места, где зонд называет экран не так, как нужно (подробнее — «Что зонд пишет
неверно» ниже):

- `DLG_ISO` — общая рамка карты, города и дипломатии; вид различается по классу:
  `CStratInterf` → `DLG_STRATEGIC`, `CCapitalInterf` → `DLG_CAPITAL`, `CDiplomacyInterf` → `DLG_DIPLOMACY`;
- `DLG_BATTLE_B` → `DLG_BATTLE_A`: широкий экран боя DisciplesGL в среде записи;
- экран, названный при показе иначе, чем при снятии, опознаётся по глубине стека.

### Где правило ошибается

1. **Поздняя смена.** Обработчик, который меняет экран позже 500 мс без промежуточного экрана, даст `None` и
   отдельный переход без элемента.
2. **Нажатие во время обработки.** Драйвер партий ИИ жмёт пробел через 78 мс после «Продолжить»
   (`20260918-probe65`, seq 8211138 → 8211139): вспышка рвётся раньше, чем показался `DLG_WAIT`, и в графе
   один раз стоит `DLG_CHOOSE_LORD.BTN_CONTINUE → None` плюс переход без элемента. Порог на время нажатия
   пробовался и отвергнут: он же приписывает «следующему лидеру» двойной щелчок по лидеру, сделанный следом
   (4 ложных перехода против одного).
3. **Щелчок, пока движок занят.** Если событие щелчка пришло до смены экрана от предыдущего действия, смена
   припишется новому щелчку. В журналах не найдено, но исключить нельзя.
4. **Переходы без элемента смешаны.** Щелчок по карте, правая кнопка, ход ИИ и событие сценария неразличимы:
   все они `Element = null` у верхнего экрана. Например, 57 боёв — `DLG_STRATEGIC → Open DLG_BATTLE_A`
   без элемента: бой начался ходом отряда на карте.

## Что зонд пишет неверно или не пишет

С доказательствами — чтобы починить зонд (`tools/d2probe/mss32/src/probeui.cpp`).

**Схема 7.1 (18.09.2026) чинит это в зонде** (`docs/corpus-schema.md`, «Версия 7.1», пп. 71–80); журналы ниже —
7.0, импорт их поправки оставляет. По пунктам: 1 — переключатель пишется одной строкой `toggle`; 2 — `lbox.what`
`select`/`scroll` (для 7.0 читатель выводит из `ret_addr`: 204/111); 3 — причина: в `Interf.dlg` у `DLG_ISO_DIPLO`
нет кнопок, их строит код, зонд пишет `child` и `area`; 4 — `top_class` во всех событиях с `top`; 5 — `iface` в
`ui_show`/`ui_hide`, `parent` в `ui_open`; 6 — `seq` показа берётся до вызова оригинала; 7 — `clearInterfaces` движок
не зовёт, хук снят; 8 — `game_phase new`/`load` до конструктора `CPhaseGame`; 9 — `base: DLG_BATTLE_A` рядом с
`DLG_BATTLE_B` (элементы те же плюс две картинки); 10 — щелчок по карте не поставлен, кандидаты описаны в схеме.

1. **Переключатель пишется дважды.** Каждое нажатие `CToggleButton` даёт `ui_click kind=button` и следом
   `kind=toggle` с тем же элементом и `t` — 112 раз (`20260919-human` seq 224242/224243
   `DLG_BUILD_STRUCTURE.TOG_MAGE`; все 57 `TOG_AUTOBATTLE`). Хук кнопки (слот 44 `CButtonInterf`) срабатывает
   и у переключателя-наследника. Импорт отбрасывает `button` перед `toggle`. Починка: в хуке кнопки
   пропускать объекты с vftable `CToggleButton` (`0x6e15a4`).
2. **`lbox` — не только подтверждение.** Схема пишет «двойной щелчок / Enter, не любое перемещение выбора»,
   но 111 из 315 `lbox` в `20260919-human` (51 из 53 в `20260918-probe65`) стоят в том же `t` сразу за
   кнопкой прокрутки: `BTN_GAME_LIST_DOWN` (клавиша 40) → `TLBOX_GAME_SLOT index=51`, seq 816/817, 664/665.
   Прокрутка кнопкой зовёт тот же `0x535f0c`. Починка: писать признак «вызвано кнопкой прокрутки» (адрес
   возврата уже есть в `ret_addr` — сравнить) или поставить хук на `onSelectionConfirmed` (`+0x74`), а не на
   установку выбора.
3. **Имя элемента не прочитано.** `DLG_ISO_DIPLO`, `element = ""`, три раза (`20260919-human` seq 15626566,
   15730965, 15731021). Подъём по `parent` до `CDialogInterf` находит диалог, но элемента в его дереве имён нет —
   вероятно, кнопка создана кодом, а не разметкой. Починка: писать индекс ребёнка и vftable элемента, когда имя
   не нашлось.
4. **Экран стека назван рамкой, а не содержимым.** Карта, город и дипломатия — все `ui_show screen=DLG_ISO`
   с классами `CStratInterf`/`CCapitalInterf`/`CDiplomacyInterf` (seq 224111, 224218), а щелчки идут по
   `DLG_STRATEGIC`/`DLG_CAPITAL`/`DLG_DIPLOMACY`. Импорт различает по классу (таблица выше). Починка: писать
   в `ui_show` все диалоги-дети экрана или диалог, в котором лежит фокус.
5. **Нет адреса экрана в `ui_show`/`ui_hide`, а имя и класс меняются за жизнь объекта.** Показ идёт из
   конструктора, и класс читается базовый: seq 17 `show CAnimInterf class=CAnimInterf`, снятие того же
   объекта — seq 21 `hide DLG_CINEMATIC class=CIntroAnim`; seq 42 `show CAnimInterf` → seq 43 уже
   `top=CMenuFullScreenAnimSnd`. То же у `ui_open.parent_class`: все 96 окон сообщений — `CPopupDialogInterf`,
   хотя экран — `CMidgardMsgBox`; `DLG_ITEM`, `DLG_BEGIN_TURN` — так же. Импорт сверяет по глубине стека.
   Починка: писать адрес объекта-экрана (`iface`) в `ui_show`/`ui_hide` — пара станет точной без эвристик.
6. **Вложенный показ пишется раньше внешнего.** `ui_show` пишется после оригинала, поэтому окно, показанное
   изнутри показа экрана, стоит в журнале перед ним: seq 6431439 `show DLG_MESSAGE_BOX depth=3`, затем 6431440
   `show DLG_MERCENARIES depth=3 top=DLG_MESSAGE_BOX` (ещё 7727454, 10435252 — всё «нет лидера для
   найма»). Импорт кладёт такой экран под верхний. Починка: брать `seq` до вызова оригинала или писать
   `ui_show_begin`.
7. **`ui_clear` не сработал ни разу.** Хук стоит (`start.hooks` содержит `ui_clear`), а за 12 смен фазы в
   `20260919-human` и 4 в `20260918-probe65` — 0 строк: стек пустеет поштучными `ui_hide` (seq 4416452
   `game_phase leave top=DLG_WAIT`). Либо движок на этих путях `clearInterfaces` (`0x53ccbf`) не зовёт, либо хук
   не на той функции — проверить отдельно.
8. **`game_phase enter` — после показа заставки сценария** (seq 224075 `show DLG_SCENARIO_BRIEFING`, 224076
   `enter`). Не ошибка, но «новая игра или загрузка» по-прежнему не различаются (известный пробел схемы); в графе
   различие видно по источнику: `DLG_CHOOSE_LORD.BTN_CONTINUE` против `DLG_MESSAGE_BOX.BTN_YES` после
   `DLG_LOAD_GAME`.
9. **Среда записи не та, что у порта.** Бой записан как `DLG_BATTLE_B` — широкий экран DisciplesGL
   (`disciples-modding/tools/GLWrapper/DisciplesGL-HD/src/DisciplesGL/Hooks.cpp`, `dlgNames`), в
   `Interf.dlg` игры его нет. Импорт сводит его к `DLG_BATTLE_A`. Починка: писать в `start` версию враппера
   или снимать журналы на игре без него.
10. **Не видны вовсе:** щелчок по карте и правая кнопка (769 вспышек без щелчка — источник известен только
    как «верхний экран»); группы переключателей, счётчики, поля ввода (известный пробел схемы 7.0); щелчок по
    картинке здания в `DLG_BUILD_STRUCTURE` (виден только по `ui_msgbox` «Построить … за …?»). Для карты
    достаточно писать в `ui_click` вид `map` с клеткой из ближайшего `path`.
