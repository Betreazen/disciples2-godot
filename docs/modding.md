# Моды

> Планы развития моддинга (слой таблиц правил, зависимости и версии, проверка, упаковка, CLI `d2mod`, окно «Мод») —
> `docs/tools/modding-kit/`; общий обзор инструментов — `docs/tools/README.md`.

Мод — каталог с файлом `mod.json`, который кладётся поверх базового набора данных. Ничего перезаписывать
и распаковывать в игру не нужно: базовые `data/` и `assets/` мод не трогает.

Откуда моды берутся:

| Корень | Для чего |
| --- | --- |
| `mods/` рядом с репозиторием | разработка: свои слои держатся в git вместе с портом; включены при обычном запуске |
| `mods/_examples` | примеры модов: **не включены** (в корне `mods/` подкаталог без `mod.json` модом не считается); включить — `--mods ../mods/_examples` |
| `user://mods` | каталог игрока (`%APPDATA%\Godot\app_userdata\Disciples\mods` на Windows) |

Порядок наложения — порядок корней, внутри корня каталоги по имени. Побеждает последний слой.
Подкаталог без `mod.json` модом не считается — README, распакованный архив или `.git` рядом не мешают.

## Раскладка мода

```text
mods/<каталог>/
  mod.json                  обязателен: он и делает каталог модом
  data/ui/screens.json      необязательно: экраны, накладываются по Id
  data/ui/assets.json       необязательно: кадры, опознаются парой архив+имя
  data/ui/flow.json         необязательно: переходы между экранами (docs/ui-flow.md)
  data/ui/defaults.json     необязательно: начальные значения групп переключателей (docs/ui-flow.md)
  data/ui/transitions.json  необязательно: ролики смены экранов меню (пара экранов → ролик)
  data/game/races.json      необязательно: расы и лорды, заменяются по типу расы
  data/game/scenarios.json  необязательно: сценарии, заменяются по Id, новые добавляются в список
  data/video/videos.json    необязательно: ролики, опознаются по имени; файлы — в assets/video мода
  data/gfx/<Архив>.json     необязательно: графика карты и боя, опознаётся парой архив+имя; файлы — в assets/gfx мода
  data/ui/strings.<язык>.json  необязательно: строки интерфейса, опознаются по идентификатору
  data/scenarios/lang/<язык>/<сценарий>.json  необязательно: перевод сценария, ключи полей (tools/scenario-ru/README.md)
  data/ui/fonts.json        необязательно: начертания по ключу (Normal, Large…); файлы шрифтов — от каталога мода
  assets/ui/<файл>.png|.webp  кадры, на которые ссылается assets.json мода
  assets/gfx/<путь>.png|.webp картинки и кадры анимаций, на которые ссылаются описи data/gfx мода
```

`mod.json`:

```json
{
  "id": "example-plain-backdrop",
  "name": "Пример: свой фон DLG_ACTION_RESULT",
  "description": "Для чего этот мод"
}
```

`id` обязателен и должен быть устойчивым: по нему мод поминается в строке `mods:` при запуске.
`name` необязателен — без него берётся `id`.

Пути кадров в `assets.json` мода — **от его собственного `assets/ui`**, не от общего. Поэтому мод
самодостаточен: его можно перенести в другой каталог или к игроку, ничего не правя.

## Что можно менять

| Слой | Чем опознаётся | Что делает наложение |
| --- | --- | --- |
| экран (`screens.json`) | `Id` | экран с тем же `Id` заменяется **целиком**; новый `Id` добавляется |
| кадр (`assets.json`) | пара `archive` + `name` | тот же кадр заменяется, новый добавляется |
| переход (`flow.json`) | экран `Id` + `Element` | все переходы элемента заменяются переходами мода; прочие переходы экрана остаются |
| начальное значение (`defaults.json`) | экран `Id` + группа | группа мода заменяет ту же группу; прочие группы экрана остаются |
| строка (`strings.<язык>.json`) | идентификатор (регистр не значим) | текст мода заменяет текст; сначала складываются запасной язык (`en`) всех слоёв, поверх — выбранный язык всех слоёв, так что английская строка мода не перекрывает русский перевод базы |
| перевод сценария (`scenarios/lang/<язык>/<сценарий>.json`) | id сценария + ключ поля (`event:<id>:<n>`, `site:<id>:name`…) | текст мода заменяет текст базы по ключу; нет ключа ни в одном слое — текст самого сценария |
| начертание (`fonts.json`) | ключ (регистр не значим) | начертание мода заменяет то же; `Default` и `Color` — только если они есть в файле мода; путь `File` — от каталога мода |

Замена целиком, а не по полям, — сознательно: экран правится как один файл, и не нужно держать в голове,
что с чем сливается. Чтобы поменять одну кнопку, скопируйте экран из `data/ui/screens.json` и правьте копию.

Кадр опознаётся парой, а не одним именем, потому что одно имя встречается в разных архивах игры с разным
размером (10 пар `Interf`/`IntfScen`, например `DRAGDROP_SMALL_VALID`).

## Разобранный пример

`mods/_examples/example-plain-backdrop/` — рабочий мод, который делает обе вещи разом: заменяет экран и добавляет кадр.
До 15.10 он лежал в корне `mods/` и был включён в обычной игре: окно итога вора становилось заливкой во весь экран с одной
надписью, без картинки и кнопки, — логика окна падала на открытии, и игра стояла (прогон 15.10, `docs/ui-windows.md` §22).
Отсюда два правила:

- **заменяя экран, сохраняйте все его элементы** (`Id`): их заполняет логика окна, и без них она падает; переставлять, менять
  размер и кадры можно. Моды корня `mods/` это проверяют тестом (`GameContentTests.DefaultMods_KeepEveryElementOfReplacedScreens`);
  окно, чья логика всё же упала, карта снимает (`MapScreen.DropFailed`), а не держит игру;
- примеры и пробы держите вне корней по умолчанию.

`data/ui/screens.json` — весь экран `DLG_ACTION_RESULT` вместо базового (был 573×586 с фоном `_PG0250IX`): холст 800×600 со своим
фоном, те же четыре элемента на новых местах (печать кнопки — кадры базы):

```json
[
  {
    "Id": "DLG_ACTION_RESULT",
    "Design": { "X": 0, "Y": 0, "Width": 800, "Height": 600 },
    "Background": "EXAMPLE_BACKDROP",
    "Cursor": "_CUDEFAUL",
    "Elements": [
      { "Id": "BTN_YES", "Kind": "Button", "Rect": { "X": 376, "Y": 480, "Width": 49, "Height": 94 }, "Anchor": "Bottom",
        "Sprites": { "Normal": "DLG_ACTION_RESULT_SEAL_OK_N", "Hover": "DLG_ACTION_RESULT_SEAL_OK_H",
                     "Pressed": "DLG_ACTION_RESULT_SEAL_OK_C", "Disabled": "DLG_ACTION_RESULT_SEAL_OK_N" },
        "TextId": "X100TA0020", "Hotkeys": [13, 27] },
      { "Id": "IMG_ACTION", "Kind": "Image", "Rect": { "X": 275, "Y": 110, "Width": 250, "Height": 250 }, "Anchor": "Center" },
      { "Id": "TXT_ACTION_RESULT", "Kind": "Text", "Rect": { "X": 200, "Y": 60, "Width": 400, "Height": 40 }, "Anchor": "Top" },
      { "Id": "TXT_ACTION_RESULT_2", "Kind": "Text", "Rect": { "X": 200, "Y": 380, "Width": 400, "Height": 80 }, "Anchor": "Center" }
    ]
  }
]
```

`data/ui/assets.json` — кадр `EXAMPLE_BACKDROP`, которого в игре нет:

```json
[
  { "name": "EXAMPLE_BACKDROP", "archive": "ExamplePlainBackdrop",
    "file": "example_backdrop.png", "w": 800, "h": 600, "sha256": "af5c9181be9f1fab" }
]
```

Файл `assets/ui/example_backdrop.png` — обычный PNG 800×600 с альфой. `sha256` — первые 16 знаков sha256
**пикселей** RGBA (строка за строкой, не байтов файла — так же считает сборщик базы, `tools/ui-assets/keyed_webp.py`
`read_sha`); порт по нему не отказывает, но по нему видно, что на диске лежит ожидаемый кадр, а не чужая
распаковка. Маджента (255,0,255) в собственных кадрах не нужна и **при загрузке не вырезается** — ключ прозрачности
знает только сборщик базы (вырезает его при записи кадра); в файле мода храните альфу.

## Форматы картинок: WebP и PNG

База (`assets/ui`, `assets/gfx`, сборщики `tools/ui-assets` и `tools/gfx-assets`) — **WebP без потерь**: пиксели те же,
что в PNG, бит в бит, а места втрое меньше. Мод и HD-замена могут класть и `.png`, и `.webp` — порт грузит файл
`Image.LoadFromFile`, формат — по расширению пути из описи. Замена с другим размером (HD) допустима: размер берётся из
файла.

- Кадр интерфейса (`data/ui/assets.json` мода) и картинка графики (`images` в `data/gfx/<Архив>.json` мода): расширение —
  часть пути `file`.
- Анимация графики (`anims` в описи мода): кадры — `<dir>/<имя кадра><ext>`, поле `ext` по умолчанию `".webp"`; мод с
  кадрами PNG пишет `"ext": ".png"`:

```json
{"archive": "Battle.ff", "images": [], "anims": [
  {"name": "MY_ANIM", "dir": "Battle/anims/MY_ANIM", "ext": ".png", "w": 64, "h": 64, "frames": ["000_A", "001_A"]}]}
```

WebP для мода — без потерь и с `exact` (иначе кодек меняет цвет под альфой 0 и при фильтрации по краю видна кайма):
`Image.save(путь, "WEBP", lossless=True, exact=True)` в Pillow, `cwebp -lossless -exact` из libwebp.

### Проверить, что слой встал

Базовый набор — `drawn=2` (фон и печать кнопки), заполнено 74 % картинки:

```bash
"C:/Tools/bin/godot.cmd" --headless --path godot res://scenes/ui/UiScreen.tscn -- --no-mods --screen DLG_ACTION_RESULT
# mods: -
# content: screens=132 assets=1940
# screen=DLG_ACTION_RESULT drawn=2 skipped=0 magenta=0.000000 opaque=0.7419
```

С модом — экран другой: фон на весь холст и печать кнопки, кадров в наборе на один больше:

```bash
"C:/Tools/bin/godot.cmd" --headless --path godot res://scenes/ui/UiScreen.tscn -- --mods ../mods/_examples --screen DLG_ACTION_RESULT
# mods: example-plain-backdrop
# content: screens=132 assets=1941
# screen=DLG_ACTION_RESULT drawn=2 skipped=0 magenta=0.000000 opaque=1.0000
```

Экранов осталось 132 — экран заменён, а не добавлен.

С окном:

```bash
"C:/Tools/bin/godot.cmd" --path godot res://scenes/ui/UiScreen.tscn -- --mods ../mods/_examples --show --screen DLG_ACTION_RESULT
```

То же самое без движка проверяет `dotnet test` — `src/D2.Data.Tests/GameContentTests.cs` читает настоящие
`data/` и настоящий `mods/_examples/example-plain-backdrop` и сверяет и замену экрана (элементы базы на месте), и то, что файл
добавленного кадра ищется в каталоге мода.

## Свой мод за пять шагов

1. `mods/мой-мод/mod.json` с `id`;
2. скопировать нужный экран из `data/ui/screens.json` в `mods/мой-мод/data/ui/screens.json` (только его,
   а не весь файл) и править;
3. новые картинки — в `mods/мой-мод/assets/ui/`, описать их в `mods/мой-мод/data/ui/assets.json`;
4. запустить сцену без `--no-mods` и убедиться, что в строке `mods:` есть ваш `id`, а `skipped=0`;
5. отдать игроку — каталог целиком кладётся в `user://mods`.

Если `mod.json` не читается или в нём нет `id`, запуск останавливается с именем файла в ошибке: молча
пропустить сломанный слой было бы хуже — мод «как будто есть», а его нет.
