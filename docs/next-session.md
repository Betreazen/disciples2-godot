## 1. Где мы (пункт 6)

Партия живёт в `src/D2.Data/Play` (обычный C#, под тестами). Сцены Godot только показывают её и передают команды.

| Файл | Что делает |
|---|---|
| `GameState.cs` | Снимок партии: `GameInfo` (сценарий, люди, сложность, `SUGG_LVL`, победитель), `MapLooks` с `MapState`, память ИИ `Ai`. Сохранение `GameSave` — свой JSON `d2-port-save` v1, слоты `SaveSlots` (`user://saves/*.d2save`). |
| `SaveJson.cs` | Конвертеры JSON: сетки `[x, y]`, план карты, словари id без учёта регистра. |
| `GameBook.cs` | Правила партии из `data/rules`: бой, рост юнитов, экономика, казна юнитов, лидеры рас, постройки лордов (`GbuiList`), имена героев (`Tleader`), читы ИИ, множитель стартовой казны. |
| `NewGame.cs` | Старт партии по движку: герой по типу лорда, бесплатная постройка, множитель казны, туман, доход и ход дня 1. |
| `GameSession.cs` | Ход партии: `MoveStack`, `EndTurn` (ход по игрокам: ИИ по ключу расы `0x42e1fe` — Империя, Легионы, Кланы, Орды, Эльфы, нейтралы последними, затем день +1 и ход человека), `BeginTurn` (земля, доход, у ИИ — деление дохода и читы, регенерация), `AiTurn` (бюджет дня + `AiStrategic.RunTurn`), `StartBattle`/`FinishBattle`, `Enter` (вход, захват, добыча), туман. |
| `GameSession.City.cs` | Действия в укреплении: `Build`, `HireUnit`, `GrowCity`, `Heal`, `Revive`, `HpMax`. Общие для человека и ИИ. |
| `MapBattle.cs` | Бой из групп карты: отряд, визитёр или гарнизон укрепления (с бронёй укрепления), охрана руины; фон; исход в карту. |
| `BattleAftermath.cs` | Опыт за бой по действиям и повышения (с полным здоровьем). |
| `AiEconomy.cs` | Экономика ИИ из карты: списки 4 (постройка), 2 (найм в гарнизоны), 5 (уход), их исполнение; `AiMemory`. |
| `SaveScreens.cs` | Логика экранов записи и загрузки. |

Сцены: `godot/scenes/ui/UiFlowView.cs` — меню → партия, загрузка из меню и из партии, выход в меню.
`godot/scenes/map/MapScreen.cs` — экран карты, бой поверх карты, стек окон настроек, записи и загрузки.
`MapView*.cs` — вид и ввод карты; цель щелчка — враг, город или руина (`TargetAt`).
`godot/scenes/battle/BattleScreen.cs` — бой от хозяина (`Prepared`, `Rules`, `Rng`, `PlaceName`).

Что работает в игре целиком:
- меню → новая партия → карта;
- отряд идёт, нападает на отряд, город или руину → экран боя → возврат с исходом, опытом, захватом или добычей;
- «Конец хода»: ИИ получают доход, строят, нанимают и лечат; день растёт;
- запись и загрузка через настройки на карте и загрузка из главного меню.

   то есть отойти от врага можно. **Сделано 23.09** (`PathFinder.Reachable`, `docs/map-path.md` §2): по коду

dotnet test                                   # всё, ~2,5 мин (D2.Rules и D2.Data параллельно)

`[CorpusRow(…)]` вместо `InlineData` и `[OnlyCorpus]` (`src/D2.Data.Tests/CorpusRow.cs`); новая партия — строка `CorpusRow` и наследник
(скрипт — перенос `InlineData`, у всех методов класса должны быть строки для каждого корпуса). `tools/repin_harness.py` понимает `CorpusRow`
и параметры по умолчанию. `CorpusReader.Read(путь, [виды])` отбирает строки по имени события до разбора JSON — харнессу не нужно
`Read(путь).OfType<T>()`. D2.Data: 4:00 → 2:38. D2.Rules: узким местом был повторный разбор `.sg` (Kaitai) — один файл корпуса разбирали до полутора десятков харнессов и по нескольку раз внутри одного; `SgFile.Open` кэширует разбор на процесс (ключ — путь, время записи, размер): в отдельной копии D2.Rules 5:10 → 1:45, весь прогон 279 → 202 с даже под нагрузкой пяти параллельных прогонов.

Строки итога: `game …`, `mapscreen …`, `mapbattle start/end …`, `visit …`, `dialog …`, `ui …`, `click …`.

**Стенд для ИИ.** В корпусе `20260919-human` сохранение `tNN` снято прямо перед концом хода человека. Поэтому
«сохранение → `EndTurn` порта» сравнивается с журналом дня NN (`AiTurnHarnessTests`). Память трат ИИ в `.sg` нет —
харнесс берёт её из `ai_budget_spend`. Строки журнала бывают переставлены, сортировать по `seq`. В одном журнале
бывает несколько карт — различать по префиксу id (`S073`, `S143`).

## 6. Грабли этой сессии

- **`git stash` / `stash pop` при `core.autocrlf=true` переписывает рабочие файлы в CRLF** (в репозитории они LF). Не
  пользоваться stash; если случилось — вернуть LF скриптом (`b.replace(b'\r\n', b'\n')`). Часть файлов в рабочей копии
  исходно CRLF (`AiTacticTurnHarnessTests.cs`, `AiTurnHarnessTests.cs`, `docs/ai-attack.md`, `docs/ai-turn-plan.md`,
  `docs/ai-tactic-candidates.md`) — скрипты правки должны сохранять конец строк файла.
- **Кандидаты в журнале — не весь кэш целей**: слабые атаки кандидата не дают, а строка силы (`ai_strength`, возврат
  `0x45375a`) пишется на каждую запись кэша. Кэш сверять по строкам силы.
- **Имена типов действий** брать из `AiActionType` (`src/D2.Rules/Map/AiTactic.cs`), а не по памяти: 12 — `AttackRod`,
  14 — `NobleStack`, 17 — `PlantRod`, 21 — `Guard`, 25 — берсерк, 35 — `Retreat`.
- **Живой день харнессов (24.09, вечер).** Строки `bank` с `mode 1` — казна магии ИИ, основную казну брать только из `mode 0`.
  Доход игрока пишется **до** его `ai_turn begin`, а живой день пересоздаётся из сохранения на первом `ai_turn begin` дня и
  `BeginAiTurn` порта прибавляет доход ещё раз — после начала хода восстанавливать последнюю казну журнала. Кошелёк тактики
  (`CAiTactic +0x515c`) ставить на первой `ai_tactic_stack` игрока (после стратегии). Партию human перезагружали (день 23 сыгран
  трижды) — повторы дня дают ложные расхождения счёта.
- **Проверка по интерфейсному слоту, а не по смещению.** «Поле никто не читает» (кошелёк `+0x515c`) оказалось неверным: его
  читают через слот `0x14` `IAiTacticInternal` (интерфейс на `CAiTactic +4`, геттеры — vtable `0x6d1ebc`). Искать и геттеры.
- **Ошибки оригинала повторять:** лечение не вычитается из кошелька тактики (цена считается после команды), продажа особых
  предметов у торговца сервер отвергает, покупки у торговца идут до `куплено ≠ n` (`jne`).
- **Значения бросков R250 журнал не пишет** — решения на бросках (торговец, маг, заклинание перед атакой) сверять тем, что от
  значений не зависит (число, допустимость, число бросков между `rng_after`/`rng_before` строк `ai_tactic_pick`).

- **Вор (24.09, ночь).** `0x5e46c2` — поиск в множестве разведанных игроков (`CMidPlayer +0x54`, `SPY_N`), а не союз: прежнее
  `ThiefTargetState.OwnerAlly` было названо неверно (теперь `OwnerSpied`, союз — `OwnerAllied`). Статус действий вора в журнале — 5:
  колбэк свитка приходит после записи результата фазы 4. Передачу предметов журнал строкой не пишет — её видно по `ai_tactic_result`
  1 у `GiveItems`; мешок, подобранный не шагом на клетку, живой день раньше не отдавал отряду. Значения бросков вора и перемешивания
  восстанавливаются по траектории R250 от `rng_seed` (`EngineRng.FindAhead` по `dice1`/`dice2`) — так можно сверять и другие решения
  на бросках.

- **Множество `0x5e46c2` — разведанные игроки, `0x5f7ebd`/`0x5f7f5a` — союз.** Не путать: по первому знатный отказывается от
  шпионажа (цель уже разведана), по второму список действий вора пуст. Подписи тулсета тут ошибались — сверять с сохранением (`SPY_N`).
- **Броски в начале хода сдвигают R250 всего дня.** Раскрытие шпионов (`0x44430f`: R250(100) < `SPY_DISCOV` на каждую запись) идёт до
  стратегии; `BeginTurn(..., spies: false)` его выключает. Любая новая проверка на старте хода сдвигает броски дальше по дню — после
  неё пересмотреть закреплённые числа харнессов (`AiTurnHarness`, `EndCells`) с разбором, а не подгонкой: выключить новое и убедиться,
  что числа вернулись к прежним.
- **Журнал пишет результат действия до колбэка.** У вора статус 5 записан раньше, чем свиток вызвал решение ИИ; сверять решение по
  событию `noble_action`, а не по статусу.
- **Чего журнал не пишет, то восстанавливается косвенно:** передача предметов — по `ai_tactic_result` 1 у `GiveItems`; мешок,
  подобранный без шага на клетку (`TakeBag`), — предметы надо отдать отряду-подборщику; раскрытие шпиона — по сохранению следующего
  дня. Если живой день харнесса расходится с движком на ровном месте — сначала искать неписанное событие.
- **Значения R250 журнал не пишет, но их можно вернуть.** От строки `rng_seed`: `EngineRng.FromSeed(table, indexAfter)
  .FindAhead([(100, dice1), (100, dice2)], known, known + slack)` находит позицию броска вора, дальше — отступить на k шагов к
  перемешиванию (`AiThiefHarnessTests`). Годится для любого решения на бросках рядом с записанным броском.
- **Хозяина кэш отрядов не сравнивает** (`0x45ea2e`): нейтрал бьёт нейтрала другой подрасы. Отбор — по подрасе отряда (`+0x90`) и
  её категории (`MapState.Subraces`, `LSubRace` 5 — нейтральная; 11 — нейтралы воды), подрасе типа лидера и союзу.
- **Новое поле `MapState` надо протянуть в копии.** `GameSession.WithTiles`, `With`, `WithRods` копируют поля руками; тестовые сборщики
  `MapState` (`PathHarnessTests`, `AiStrategicHarnessTests`, `AiStrategicCorpusTests` и др.) тоже — `Subraces` в них нет (там не нужно).
  Забытое поле молча становится пустым.
- **Список «свои сильнейшие» (`0x4760b0`/`0x476252`) берёт только `L_NORMAL`** (флаг 1 — список помощников `L_ASSIST`). Кому
  отдавать предметы, решает он.
- **Берсерк — приказ 10 (`L_BEZERK`), действие без порога** (фабрика `0x45165a`, отказ только при p = 0). Счёт у всех его окон
  ×1,125 к журналу — не подгонять: это план тактики (главный враг, «толпа»), он не перенесён.
- **Призыв «только по воде» не читается** (`GameSession.Cast`, `Placeable`): ход, пути, кэши и охрана уже знают `WaterOnly`, постановка
  призыва — нет.
- **Показ расхождений для разбора:** `D2_NEUTRAL_SHOW=1` (кэш у нейтралов, `AiAttackStrengthHarnessTests`), `D2_THIEF_SHOW=1`
  (решения вора), `D2_CAND_SHOW=1` (кандидаты по окнам). Временные переключатели для проверки сдвига чисел — удалять перед коммитом.
- **Git Bash: heredoc ломается и на вложенных кавычках** («unexpected EOF»), не только на бэкслешах. Python-скрипт — только через Write.

- **Память движка, которой нет в `.sg` (25.09, вечер).** Сохранение не хранит память трат стратегии ИИ (`AiMemory`) и статусы тактики
  (`AiTacticMemo`), а движок партию не перезагружал. Харнесс «с сохранения» без них тратит и выбирает иначе: без памяти трат бюджет роста
  деревни выше цены (probe65 — «сетка на 1 больше»), без статусов нет «вчера продвинулся» ×1,25. Брать из журнала: `AiSpendMemory`
  (`ai_budget_spend`), `ai_tactic_result` до окна дня; опыт за бой — строки `xp` до `battle_end`. Новому харнессу живого дня — сразу так.
- **Позиции «из сохранения» — не позиции движка в момент хода.** Сохранение снято до хода ИИ: отряд, который у движка к моменту оценки
  уже ушёл, в порте стоит на месте и закрывает клетки пути (human день 10: `KC0000` на 24,34). Для теста хода конкретного отряда сначала
  переставить соседей, как в журнале (`MoveStack` — он правит и план карты; `with { X, Y }` план не трогает).
- **Выселение в журнале пишется на гостя.** У `CAiKickOutStackAction` (`0x6d10ec`) зонд пишет в `action.stack` и в `ai_tactic_result` выселяемого,
  оценивающий отряд — в `ai_tactic_stack`/`ai_tactic_pick.stack`; фабрика действия (`0x4578d8` у лечения) выбирает класс по положению
  отряда: гость — «стоять», рядом и пусто — вход, рядом и занято — выселение, далеко — ход.
- **Расхождение вида «у движка на 1 меньше во всех клетках»** сначала сверять с состоянием карты порта против сохранения следующего дня
  (крепости, размер), а не с формулой: причиной оказалась стратегия порта того же дня.

- **Наёмники и храм (25.09).** Прежде чем переносить построитель ради «ходил только движок», посчитать его кандидатов в журналах: у 8 и 0xb в
  human и legions их ноль, пометка в §4 была догадкой. Кандидаты по типу — `ai_tactic_candidate.action.type`; живые примеры храма — только
  probe65 (карта `S143`).
- **probe65 — две карты в одном журнале** (`S143` — `ai-q09-…`, `S073` — `rastlennaya-vlast-…`, дни пересекаются). `Candidates_MatchJournal`
  принимает `map` (префикс id) и `stem` (начало имени сохранения).
- **Живой день и здоровье.** Подготовка отряда (зелья, переносы из гарнизона) идёт при выборе отряда, и её строки (`potion_use`,
  `unit_transfer`) лежат в журнале **до** строки `ai_tactic_stack` окна (проверено по seq: probe65 5158903 → 5159011) — харнесс успевает
  их применить до сборки кандидатов. Здоровье из `potion_use` применять (`hp_after`), иначе у порта лишние `HealRevive` и храм. Флаг
  «лидер жив» после боя снимать: без живого лидера голова списка (атаки, руины, места, храм) не строится. `heal` в журнале без здоровья —
  лечить правилом порта по казне (частично), а не до полного: human день 34, 2 золота. Сделано в `Candidates_MatchJournal`,
  `ExecutionPaths_MatchJournal` (без переносов) и `AiAttackStrengthHarnessTests` (зелья и переносы); `AiSiteVisitHarnessTests`,
  `AiStackItemsHarnessTests`, `AiThiefHarnessTests`, `AiSpellHarnessTests` — по-прежнему нет.
- **Исключения кэша — объекты клетки точки, а не цель** (25.09, `docs/ai-attack.md` §11). Харнесс (`AiJournalTactic.AfterPathCheck`) по-прежнему
  выводит их из `top` фазы 3 — выпавший не всегда потерял путь (подмога, чей помощник сегодня не дойдёт, выпадает без исключений); цель,
  оставшаяся другим кандидатом, не исключается.
- **Id новых объектов у движка — счётчик по типу, номера погибших не переиспользуются** (`freeIdTypeIndices`; после загрузки — наибольший + 1). В живом
  дне харнесса id нанятого берётся из журнала (`AiLiveDay.Hired`); если объект «пропал» из живого дня — сначала проверить id.
- **Перезакрепление чисел сразу у многих харнессов** — скрипт по стеку упавшего `Assert.Equal(wantX, …)`: параметр по сигнатуре, значение в `InlineData`
  того же корпуса (так сделано 25.09 для id нанятых); после — пояснение у каждого теста и проверка старого правила переключателем.
- **Рабочая копия — CRLF (autocrlf), в репозитории LF.** Скрипт правки должен искать с концом строк файла (`nl = "\r\n" if "\r\n" in s`);
  `sed -i` из Git Bash переводит файл в LF — в коммите разницы нет, но предупреждения git.
- **Гипотезу мерить по всем трём партиям сразу.** «Производные не исключают цель» улучшила legions на 1 окно и ухудшила human на 9 —
  по одной партии её легко принять за правду.
- **`CMidStack +0x28` — id лидера** (цена `0x5dfd5f` берёт скидку его реализации, код воскрешения `0x5de06e` зовётся от него).
- **Геттеры `IAiTacticInternal` адресуют от `CAiTactic +4`** (`[ecx+0x5158]` — это `+0x515c`). Поле ищи и по смещению −4.
- **Статические категории (`LleadC`, постройки) — глобалы по 0x10** (`vtable`, `+4`, id на `+8`), заполняются при старте по имени;
  какой объект какая категория — по порядку статической инициализации (`0x58bbb6`), и это ранг 2.
- **`0x5869e6` — «хоть одна валюта кошелька меньше цены»** (1 — не хватает). Обороты `neg al; sbb; inc` после него дают «хватает».

- **Скорость тестов (24.09).** Тесты идут параллельно, и один и тот же разбор в двадцати тестах сразу душит машину:
  харнесс Ф7 в одиночку — 36 с, в общем прогоне — 630 с. Поэтому журналы брать через `TreasuryJournal.Load` (кэш на
  процесс), не звать провайдер картинок на каждую точку без кэша, мерить долгие тесты так:
  `dotnet test … --logger "trx;LogFileName=<файл>"` и сортировка `UnitTestResult.duration`.
- **Git Bash: heredoc и `sed` теряют обратные слеши** (`\d`, `\n` в строках). Скрипты правки писать через Write
  в каталог scratchpad и запускать `python файл.py`; мелкие правки — через Edit.
- **Не запускать два `dotnet test` одновременно** и не собирать во время прогона: сборка упрётся в занятые DLL.
  Полный прогон — фоновой задачей (`run_in_background`), а не через `&`.
- **Повисшая проверка Godot** (исключение внутри асинхронной проверки) держит процесс. Снимать так:
  `Get-CimInstance Win32_Process | ? CommandLine -like '*UiFlow.tscn*--check*' | Stop-Process`.
  Запускать с таймаутом.
- **Узлы Godot, которые сами вызвали событие** (закрытие боя, загрузка из окна), снимать отложенно:
  `Callable.From(...).CallDeferred()`.
- **`AiStrategic.RunTurn` на неудачном исполнении крутится до `maxPasses`.** Проверка кандидата и исполнение должны
  считать одинаково (пример — `GameSession.HpMax`). Отчёт дня пишет «не исполнено …» — смотреть туда.
- **Модели карты (`MapStack`, `MapUnit`, `MapPlayer`, `MapLooks`) — record:** копировать через `with`. `MapState` —
  класс (у него кэш дорог), копия — `GameSession.With(...)`.
- **Туман (`bool[,]`) меняется на месте и общий у снимков** — так задумано. Новый туман на старте — `ResetFog`.
- **Tutorial плохо подходит для проверок пути:** столица закрыта горами. Для осады и руин брать сохранения
  `20260919-human` (пример — `t03-008`: `59,22;52,16;52,16`).
