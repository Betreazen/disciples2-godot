# Зонд порта — журнал запуска и отчёт по нему

Зонд порта (`godot/autoload/PortProbe.cs`, ядро журнала — `src/D2.Data/Diagnostics/PortJournal.cs`) пишет всё, что видно при игре,
в журнал `%APPDATA%\Godot\app_userdata\Disciples\probe\port-<дата-время>.jsonl`. Включается сам при каждом запуске игры с окном; без окна
(проверки `--headless`) — только при `D2_PORT_PROBE=1`; `D2_PORT_PROBE=0` выключает; `D2_PORT_PROBE_DIR` — другой каталог.

## Что пишется

| Строка (`ev`) | Что |
|---|---|
| `start` | время, коммит порта, версия Godot, ОС, экран, видеокарта, аргументы |
| `error`, `error_repeat`, `error_counts` | ошибки и предупреждения движка Godot, необработанные исключения C# — со стеком, местом в коде порта и последними 12 сообщениями игры перед ошибкой; повтор той же ошибки — целиком первые 3 раза, дальше счёт (`error_repeat` на 4, 8, 16…), итог — при выходе |
| `print`, `stderr` | все сообщения игры (`walked`, `battle`, `card`, `music`, `event`…; `tag` — первое слово) |
| `screen` | окно или экран открылся/закрылся (`name` — разметка `DLG_*`, карта, бой) |
| `key`, `click` | клавиши и кнопки мыши (точка, окно сверху) |
| `session`, `turn`, `move`, `battle`, `sight`, `offer` | партия: сценарий и день; чей ход (день, казна); шаг отряда; бой; события карты (захват, наём, заклинание, гибель, рост…); предложение ИИ человеку |
| `day` | **снимок мира** в начале хода человека (в «горячем стуле» — каждого) и при подписке на партию; рядом — **сохранение дня** (схема ниже) |
| `invariant` | нарушение инварианта карты (`src/D2.Data/Diagnostics/MapInvariants.cs`): в начале хода любого игрока и после каждого боя |
| `battle_end` | итог боя: стороны, победитель, раундов, павшие и опыт по сторонам, классы атак сторон, применённые предметы, бежавшие |
| `event` | сработавшее событие сценария: id, игрок, триггерер, день, эффекты |
| `ai_pick`, `ai_step`, `ai_turn` | трасса ИИ: выбор тактики отряда, исполненный шаг стратегии, конец хода ИИ (длительность) |
| `slow_frame`, `heartbeat` | кадр дольше 250 мс по часам (до 15.10 мерился по `delta`, которую Godot урезает до ~133 мс, — строка не появлялась никогда); раз в 30 с — кадры в секунду, память, число объектов и узлов |
| `snd`, `snd_end`, `music`, `vol_set`, `video`, `map_anim`, `bat_anim`, `bat_fx`, `bat_text`, `cursor`, `frames` | **схема 7.3** — звук, музыка, громкости, ролики, анимации карты и боя, надписи боя, курсор, кадры за 10 с: те же имена и поля, что у зонда оригинала (`src/D2.Data/Diagnostics/AvTrace.cs`), сверка — `dotnet run --project tools/AvCompare -- <оригинал> <порт>`; `docs/probe-av.md` |
| `bat_flash`, `bat_flash_end`, `bat_text` (с местом), `bat_text_end`, `map_sel`, `map_path` | **схема 7.6** — вспышки и надписи портретов боя (место, строки показано и по правилу переноса движка), эллипс выбранного отряда и флажки пути на смену видимого: те же поля, что у зонда оригинала (`AvTrace`); вспышки пишет вид портретов (`BattleView.TraceFlash`); сверка — `AvCompare`, `AvFaceHarnessTests`; `docs/probe-av.md` §8 |
| `mark` | **F9 — пометка**: снимок экрана (`…-markN.png`) и сохранение партии (`…-markN.d2save`) рядом с журналом; на экране — «Пометка N записана» |
| `end` | штатный выход; нет строки — процесс упал или убит |

## Как пользоваться

1. Играть как обычно. Увидел ошибку — **F9** (на экране появится «Пометка N записана»), можно несколько раз.
2. После игры (или не закрывая её) — отчёт:
   ```
   python tools/port_log_report.py            # самый свежий журнал зонда (или лог Godot, если зонда не было)
   python tools/port_log_report.py путь.jsonl
   python tools/port_log_report.py --all      # все журналы
   python tools/port_log_report.py --synth    # партия на синтетической карте порта: вопросы карты — закрыт/открыт (и в консоль)
   ```
   Отчёт — `.cache/port-report/<имя>.md`: ошибки по группам (сколько, где в коде, что было перед ними), пометки со снимком,
   сохранением и последними действиями, тормоза, мир по дням, нарушения инвариантов, бои, ИИ, события сценария, окна, аварийный конец.
3. Сказать номер пометки и что было не так — сохранение пометки загружается в порт, снимок показывает, что было на экране.
4. Долгая партия (30–50 дней): ничего нажимать не нужно — каждый день в журнале есть снимок мира и сохранение начала хода. Заметил
   странность через несколько дней — назвать день: сохранение `…-dayNNN-<игрок>.d2save` загружается в порт, и день переигрывается с
   того же места (генераторы случайных чисел — в сохранении).
5. Проверка без окна по такому сохранению (пометки или дня): `godot --headless --path godot res://scenes/map/MapScreen.tscn -- --check --state <файл.d2save> --player <игрок> --clicks "…"` (шаги проверки карты, например `highlight x,y`).

Лог Godot (`logs\godot*.log`) тем же инструментом тоже разбирается — для запусков без зонда (только ошибки).

## Долгая партия: схема строк

Общие поля любой строки — `seq`, `t` (мс от старта), `th` (поток), `ev`. Ход ИИ идёт на рабочем потоке — строки ИИ и боёв ИИ с другим `th`.

**`day`** — снимок мира (`src/D2.Data/Diagnostics/DaySnapshot.cs`), ~1–2 КБ:

| поле | что |
|---|---|
| `day`, `player` | день (`CUR_TURN`) и чей ход |
| `players` | по игроку: `bank` — казна `[золото, ад, жизнь, смерть, руны, роща]`; `spell_bank` — второй кошелёк (`SPELL_BANK`, только непустой); `capital` — столица (null — потеряна); `villages` — `{id: уровень}`; `riot` — бунтующие деревни; `stacks`, `units` (живые, в отрядах и гарнизонах), `leaders` (живые лидеры), `levels` (сумма уровней живых), `spells` (известных), `land` (клеток своей земли) |
| `relations`, `allies` | отношение пар рас `{"0-2": 45}` (0 Империя, 1 Орды, 2 Легионы, 3 Кланы, 4 нейтралы, 5 Эльфы) и пары в союзе |
| `rng` | `r250` — индекс генератора боёв, `crt` — состояние `rand()`: расхождение двух запусков видно с первого дня |
| `events_off`, `quest_log` | выключенных событий сценария, записей квест-лога |
| `save` | путь сохранения дня `<журнал>-dayNNN-<игрок>.d2save` (рядом с журналом; тот же день повторно — перезапись); строка пишется до сохранения, сбой сохранения — отдельной строкой `day_save` (`day`, `save`, `error`), недописанный `.tmp` удаляется |
| `attach` | `true` — снимок при подписке на партию (загрузка, новая партия): загруженная партия может быть посреди дня, это не начало хода; сохранение — `…-dayNNN-<игрок>-attach.d2save` |

Снимок и сохранение пишутся в начале хода человека (`ITurnObserver.HumanTurn`: доход, земля и события начала хода уже прошли) и при
подписке на партию, если в этот миг не идёт ход ИИ и не открыт бой (`GameSession.InBattle`). Сохранение дня — без итогов хода окна
(`GameSession.SnapshotWithoutSummaries`): их держит сцена на главном потоке, а начало хода человека приходит с потока хода ИИ; зонд
состояние интерфейса не трогает.

**Размер и прореживание.** Замер 13.10: сохранение на карте 96×96 (Nyullokth's Vengeance, 422 юнита; probe72 q09 — 389) — ~460 КБ,
48×48 — ~120 КБ (gzip сжал бы в 8 раз, но тогда сохранение не открыть загрузкой порта). 50 дней «горячего стула» на большой карте — до
~100 МБ, поэтому сохранения прореживаются: последние 7 дней (`PortJournalWatcher.KeepDays`) — все, старше — только дни, кратные 5
(`KeepEvery`); на 50 дней — ~17 файлов на человека (~8 МБ). Снимки `day` в журнале остаются за все дни.

**Зонд не роняет игру.** Его зовут из хода ИИ (рабочий поток), из конца боя и из событий сценария. Журнал (`PortJournal.Write`/`Error`)
не бросает никогда: сбой записи или разбора поля — счёт, после 5 сбоев подряд (`MaxFailures`) журнал выключается (`Disabled`,
`LastFailure`). Каждый вызов подписчика — под защитой (`Safe`): сбой — строка `error` с `kind = probe`, ход идёт дальше. Проверка —
`PortJournalWatcherTests.BrokenJournal_NeverBreaksTheGame` (журнал, запись в который бросает: 8 дней с ходами ИИ, боями и событиями — как
без зонда). Подписчик привязан к своей партии: загрузка другой посреди хода ИИ карты не смешивает.

**`invariant`** — `code`, `object`, `detail`, `day`, `when` (`turn <игрок>`, `battle <нападающий>><защитник>`, `attach <игрок>`). То же
нарушение того же объекта — не чаще раза в день. Коды (`MapInvariants`): `unit_missing`, `unit_shared` (юнит в двух местах),
`unit_orphan` (ни в одной группе), `slots` (клетки построения не сходятся с юнитами), `hp` (вне [0, максимум с модификаторами]),
`leader`, `leader_alive` (признак «лидер жив» не совпадает со здоровьем лидера), `stack_empty`, `owner`, `bank` (валюта вне [0, 9999], `Economy.CurrencyMax`), `off_map`, `plan` (отряд не в плане своей клетки —
и внутри укрепления тоже, — или план ведёт не на его клетку), `inside` (`Inside` ↔ визитёр укрепления), `capacity` (группа выросла сверх
вместимости: лидерство отряда, уровень деревни), `item` (экземпляр без типа, тип не в правилах, снаряжение не из инвентаря), `talisman`
(заряды не у талисмана), `relation` (вне 0…100).

На сохранениях оригинала — шесть партий корпуса (replay, human, probe72, legions, hotseat, probe65), все ~460 сохранений и пары
соседних — нарушений нет (`MapInvariantsTests`; по умолчанию выборка, `D2_INVARIANTS_ALL=1` — все файлы, ~5 с). Вместимость — правило
добавления, а не состояния: гарнизон и отряд, данные сценарием, движок держит и сверх предела (probe72: по два юнита в деревнях
1-го уровня с первого дня, отряд из трёх клеток при лидерстве 2; одиночный крупный лидер при лидерстве 1 — human, legions), поэтому
`capacity` — только рост группы сверх предела по сравнению с прошлой проверкой.

Цена проверки — ~1 мс на карте 96×96 (422 юнита; потолки здоровья кэшируются по типу, уровню и цепочке модификаторов), поэтому после
боя проверяется вся карта, а не только участники. `hp` и снятие модификаторов: в бою потолок меняют только превращение и вытягивание
уровня — откат пересчитывает здоровье (`LifeAttacks`, `oldHpMax → newHpMax`); на карте снятие заклинания или зелья по сроку
(`GameSession.ExpireEffects`) здоровье не урезает. У движка `hp > max` нет ни в одном из ~460 сохранений корпуса (в них есть и снятые
заклинания), так что срабатывание `hp` после снятия модификатора на прибавку здоровья — не ложное, а расхождение с движком (урезать ли
здоровье при снятии — проверить по журналу `spell_expire`/`hp_change`).

**`battle_end`** — `attacker`, `attacker_owner`, `defender`, `defender_owner` (у руины пусто), `winner`, `winner_owner`, `rounds`,
`fallen` `[нападающих, защитников]` (павшие в этом бою, не призванные; павшие до боя лежат в бою костями и не считаются), `xp` `[нападающим, защитникам]` (полученный опыт), `day`, `classes`
`[[нападающих], [защитников]]` — классы атак (`AttackClass`), которыми били юниты стороны, по всем применениям модели
(`BattleState.Actions`: и атаки по своим без записи хода — усиление, дар атаки, обереги, снятие яда, превращение себя, — и призыв, и вторая
атака по своим — воскрешение; у превращения себя по врагу — класс запасной атаки; по алфавиту; 15.10 вечер, партия на `port-synth-1-battle`), `items` — типы применённых предметов (сфера, талисман, зелье), `retreated` `[нападающих, защитников]` —
бежавших с поля (15.10, синтетические карты, `docs/synthetic-maps-port`). Пишется, когда бой
записан в карту (`GameSession.CommitBattle`, `ITurnObserver.BattleEnded`) — бои ИИ, человека и событий.

**`event`** — `id`, `player`, `triggerer` (отряд; пусто — начало хода), `day`, `effects` (имена `L_*` по порядку). С 17.10 (`r17b/uifix`) —
и события старта партии: их проверка идёт в `NewGame.Begin`, до подписки зонда, — сессия копит сработавшие в день 1 до первой подписки
(`GameSession.TakeUnwatchedFirings`), и зонд пишет их при подписке строками `event` с `start` = true (прежде условия старта, например
C8w/C8p карты 9, срабатывали, а в журнале их не было).

**`move`** — `stack`, `owner`, `from`, `to`, `cells`, `attack`. Действие с соседней клетки (нападение, вход в город, руину, лавку, вор, снос и
постановка жезла, бросок мешка) — у движка та же команда хода с путём из одной точки (`path len 1`, эффекты за концом пути `0x4408cb`);
с 17.10 зонд пишет её строкой `move` с `cells` = 1 (`GameSession.ActInPlace`). В старых журналах такой строки нет: отчёт `--synth`
засчитывает требование «`move` stack=X» и строкой действия X — нападающий `battle`/`battle_end`, начало боя на виду, `print`
вора `thief`/`noble`, сноса `rodbreak` и постановки жезла `droprod placed` (начало прицела не считается; `tools/port_log_report.py`,
`acted`). Журнал `port-20261017-134341`: карта 8 — 15 из 22
(было 10; открыты R1, R3, R4, R7 — у входа в деревню, лавку, мешка и броска мешка в старом журнале нет id отряда; R0, R8 не сыграны, R11 — у порта тогда
не было боя), карта 9 — 34 из 37 (C8w/C8p закроются на новом журнале, E07-on не сыгран).

**`sight`** — `kind` (`TurnSightKind`), `player`, `at`, `object`; у захвата (`Capture`) — ещё `occupy`: захватчику пришло сообщение
`OCCUPY` (у его расы этой деревни раньше не было, `MapSite.PreviousOwners`). Итог вора человека (`ThiefResult`, `object` — действие,
`at` — 0,0) пишется сразу по действию (`ThiefActionsLogic.Act`), до окна итога: с 15.10 — и когда окно итога не открылось.
С 16.10 (синтетические карты 6–9) — ещё действия человека без звука: `Dismissed` (воин отпущен, `object` — воин; отпуск лидера
распускает отряд), `BagDropped` (мешок выброшен на пустую клетку или открыт броском на мешок, `object` — мешок), `Sold` (продажа
торговцу, `object` — тип предмета), `Trained` (обучение у тренера, `object` — воин); покупки, лечение и воскрешение — прежние `Bought`,
`Healed`, `Revived`.

**`stderr`** — сообщения `GD.PrintErr`: так порт печатает исключения, которые ловит сам (логика окна упала — `…: логика экрана
(открытие) — KeyNotFoundException…`). Отчёт сводит их в раздел «Сообщения stderr» и считает в сводке (`stderr N`): строки `error`
у таких нет, и до 15.10 отчёт показывал «ошибок 0» при неоткрывшемся окне.

**Синтетические карты** (`docs/synthetic-maps-port`): если партия шла на `port-synth-*` (строка `session`), отчёт добавляет раздел
«Синтетическая карта» — вопросы карты из её `facts.json` и какие строки журнала их закрывают.

**Трасса ИИ** (`IAiTrace`, `GameSession.AiTrace`; ставит только зонд — в тестах и харнессах её нет, без неё затрат нет). Имена — как у
зонда оригинала (`docs/corpus-schema.md`), день — `turn`:

| строка | у оригинала | поля |
|---|---|---|
| `ai_pick` | `ai_tactic_pick` (фаза 4) | `player`, `turn`, `stack`, `action` (`AiActionType`), `target`, `at`, `score`, `count` (кандидатов после поправок) |
| `ai_step` | `ai_strategic_step` | `player`, `turn`, `type` (0 HireLeader, 1 UpgradeLeader, 2 HireUnit, 3 GrowCities, 4 Capital, 5 HealRevive, 6 SpellResearch, 8 Diplomacy), `kind`, `id`, `target`, `pass`, `step` |
| `ai_turn` | `ai_turn` (`phase = end`) | `player`, `turn`, `ms` — время хода по часам от начала хода игрока до конца оперативного слоя, **вместе с ожиданием показа**: рабочий поток стоит, пока главный показывает шаг отряда, бой с человеком (до закрытия экрана боя), анимацию или паузу события (`MapView.AiTurn.cs`, `AiHooks.Ask`); сам расчёт — десятки мс (`docs/perf-log.md` Г20), `steps`, `picks` |

Разделы отчёта для долгой партии: «Мир по дням» (золото · города · отряды · юниты · уровни по игрокам, сохранение дня), «Нарушения
инвариантов» (по кодам, первый день, пример), «Бои» (победы и поражения по игрокам, павшие, опыт), «ИИ» (выборы и шаги по видам и
игрокам, ходы ИИ, медленные > 2 с с разложением: бой с человеком на экране, шаги отрядов, анимации и паузы, прочее), «События сценария».

Проверка без окна (`D2_PORT_PROBE=1`, `D2_PORT_PROBE_DIR=<каталог>`): `godot --headless --path godot res://scenes/map/MapScreen.tscn --
--no-mods --check --scenario "Drega Zul" --player S001PL000a --humans S001PL000a --clicks "end;ok;16,26;21,32;21,32;ok;end;ok;end;ok"` —
в журнале `day` на каждый день с сохранениями, `battle_end` (бой эффекта и бои ИИ), `event`, `ai_pick`/`ai_step`/`ai_turn`.

## Первая находка инвариантов (13.10)

Партия «Power to Corrupt» без окна (`PortJournalWatcherTests`), день 6, после боя: `plan S073KC0073 — нет в плане клетки (11,11) внутри
S073FT0000`. Найм лидера (`GameSession.HireLeader`) ставил отряд в укрепление, но не в план клетки, а у движка отряд внутри укрепления в
