# Кандидаты тактики ИИ из карты: кто что строит

Разбор `Discipl2.exe` (GOG 3.01) дизассемблером и сверка с корпусом (probe65 / legions / human), 23.09.2026.
Ранги: 1 — прочитано в листинге, 2 — выведено (листинг + корпус), 3 — догадка. Скрипты сверки — в scratchpad
сессии (`re-assist/`, `re-rods/`), вне git. Нужен порту для среза 5 (`docs/ai-turn-plan.md`): харнессы до сих пор
брали кандидатов из `ai_tactic_candidate`.

## 0. Каркас

- `0x4633fe` создаёт объекты-построители и кладёт их через `[vtbl+0x50]`; построитель — слот 2 своей vtable:
  AssistMove `0x6cfc5c` → `0x45011b`, GiveItems `0x6d0924` → `0x456fea`, HealRevive `0x6d0ab4` → `0x4576dd`,
  DefendCity `0x6d05fc` → `0x4546e4`, SecureCity `0x6d182c` → `0x462edf` (ранг 1).
- **Фильтр приказа стоит до счёта**: построитель отдаёт оценку в слот 19 обёртки (`0x46797f` →
  `0x468560(list, [wrapper+0x1c], eval)`), где `IAiActionFilter` (без фильтра — `0x603e28`) решает, попадёт ли
  она в список (`AiTactic.Admits`, ранг 1). Отброшенных приказом кандидатов в журнале нет.
- Вставка — в фазе 2 (`0x4686cf`); `ret_addr` события — адрес за этим вызовом.
- **Позиция объекта** `0x5ed9b2(map, &id)` (ранг 1): отряд в крепости (`+0x94` не пусто) — вход крепости
  (`0x5e94eb` → `0x5e9563`, `pos + size − 1`), иначе `+4/+8`.
- **Проходимость «при нулевых масках»**: сетка `0x602692` → `computeMovementCost 0x6027f3` с `a6 = a7 = 0`,
  `forbidWaterOnlyOnLand = 1` (ранг 1): границы, шесть видов объектов, мешок (0x27) — 0, чужой отряд (0x23) —
  0 (свой — нет, `0x57f529`), грунт. В порте — `PathFinder.CellCost`.
- **Ловушка харнессов**: у выселения (KickOut, vft `0x6d10ec`) зонд пишет в `action.stack` выселяемого гостя;
  оценивающий отряд брать из `ai_tactic_stack`.

## 1. AssistMove (0x20), `0x45011b`, ранг 1

```
цель = действующий приказ == L_NORMAL ? AIORDERTAR : ORDER_TARG
цель пуста или не отряд → нет
T = позиция цели (0x5ed9b2)
best = T, bestD = 999
для (dx,dy) в 0x6cfc10: (0,-2),(0,2),(-2,0),(2,0),(-2,-2),(2,2),(2,-2),(-2,2):
    c = T + (dx,dy); если проходима(c) и Чебышёв(отряд, c) < bestD: best = c
best == позиция отряда → нет
best == T: если Чебышёв(отряд, T) <= 2 → нет; иначе direct = 1
счёт 0x450328: всегда 150
```

Кандидат один — цель приказа; союзность, туман и расстояние не проверяются. На деле есть только у `L_ASSIST`.
Сверка: цель 271/271, 343/343, 262/262; точка 271/271, 341/343, 262/262 (два промаха — реконструкция состояния).

## 2. GiveItems (0x22), `0x456fea`, ранг 1

## 3. Кто кому помощник: `0x45603b` (ранг 1)

Зовётся в начале хода тактики игрока (`0x46586c`), при смене приказа своего отряда на `L_ASSIST` с пустой целью
(`0x46726f`; так появляется помощник при найме) и при снятии отряда из тактики (`0x4670dd`). Отрядам, чья цель
удалена, `0x438d31` ставит `L_ASSIST` с пустой целью (ранг 2).

```
раса неиграбельная → выход
дипломат = категория лорда == L_DIPLOMAT                                  # ранг 2
L = свои отряды с действующим L_NORMAL, лидер не призыв, категория 0 (не призыв, не знатный, без L_ROD)
L пуст: всем своим с действующим L_ASSIST → L_NORMAL с пустой целью; пересобрать L; пуст → выход
L сортируется: сила 0x5dcec7 по убыванию, при равенстве id по возрастанию (0x4766b9 / 0x476604)
для i-го лидера: (cap0, cap1) = i==0 ? (2, дипломат ? 2 : 1) : i==1 ? (2, 1) : (1, 1)
    n0 = число своих с AIORDER = L_ASSIST и целью = этот лидер; n1 = 0 (0x456f39 смотрит категорию лидера —
    похоже на ошибку оригинала, но так в листинге и корпусе)
для каждого своего s с AIORDER = L_ASSIST и пустой целью:
    k = категория лидера s: призыв → пропуск; знатный → 1; иначе 0
    лидеров нет → L_NORMAL; иначе первый с n_k < cap_k, иначе первый с минимальным n_k; n_k += 1
    приказ L_ASSIST с целью = этот лидер
```

Сила `0x5dcec7(map, id, 0, группа, enemies = 1, 0, noFort = 1, maxHp = 1)`: живые юниты, здоровье полное — в порте
`AiStrength.Unit(Hp = HpMax, ignoreCity: false, enemies: 1, fortArmor: 0)` (ранг 2). Сверка — 12/12 случаев с двумя
лидерами, 42/43 назначений (промах — лидер, нанятый вне реконструкции).

## 5. SecureCity (0x13), DefendCity (1)

SecureCity `0x462edf`: цель действующего приказа — крепость, не столица захваченного хозяина, не бунт; один

## 6. Кэш ближайших целей `CMidServerLogicData2` (ранг 1)

Построители жезлов (`0x461347`, `0x450cbe`) и мешков (`0x469418`) идут не по всей карте, а по кэшу
`CMidServerLogic::data2` (`CAiTactic+0x51c4`, слот `+0x18` `IAiTacticInternal`). Его пересобирает `0x45e4c7`
**перед каждой оценкой отряда** (фаза 0, `0x466b36`): шесть векторов по три цели — отряды `+0x0c`, крепости
`+0x1c`, места `+0x2c`, руины `+0x3c`, **мешки `+0x4c`**, **кристаллы `+0x5c`**.

```
pos = позиция отряда (0x5ed9b2: в крепости — вход)
(отряд, pos) изменились → исключения (+0x6c) очистить
R = флаг && ход < ((размер_плана − 48) / 24)·10 + 11 ? размер_плана / 2 : 0       # 0x45e70d
для каждого вида: собрать → multimap по √(dx²+dy²) от pos (равные — в порядке обхода, по id)
    кристаллы — только у лидера с L_ROD, иначе вектор пуст
    R > 0: выбросить цели не из множества +100, у которых Чебышёв до любой чужой столицы ≤ R   # 0x45f5f1
    взять по порядку не исключённые, до трёх (цели из множества +100 счётчик не тратят)        # 0x45f793 (§30)
```

- Кристаллы (`0x45f327`): пропуск, если террейн клетки кристалла — свой или союзника (`0x5f7ebd`). Тумана,
  пути, воды нет; кристалл со своим жезлом отсекается косвенно — квадрат 3×3 жилы уже своя земля.
- Мешки (`0x45f1e3`): водному лидеру — только на воде. Радиуса, тумана и охраны нет.
- Исключения `+0x6c`: путь до точки не найден (`0x46903e` → `0x45f902`) — объекты плана в клетке точки (FT, KC, BG, SI, RU, CR; отряд в
  крепости не исключается — исключается крепость, `docs/ai-attack.md` §11) — и если набор вырос за оценку,
  тот же отряд оценивается заново на той же клетке, вектор сдвигается на следующие цели.
- Флаг радиуса `+0x51d9`: отряд — первый в списке `CAiTactic+0x51fc` (свои сильнейшие начала хода, `CAi +0x24`, найдено
  24.09 — `docs/ai-spells.md` §5). `+0x51d8` («радиус снят») ставит повтор без действия (`0x46653d`), сбрасывают новый выбор
  отряда (`0x466aac`) и следующая оценка без действия (`0x46654e`).
- Оценка без действия с выросшими исключениями ставит отряду байт слабых атак `IAiStack +0x18` (`0x4665cc`) — без него
  атаки с не взятым порогом кандидатов не дают (`docs/ai-attack.md` §8).

## 7. Жезлы и мешки (ранг 1)

**PlantRod / AttackRod** (`0x461347`): хозяин захвачен → нет. По кристаллам вектора: чужие жезлы в восьми
соседях (`0x461525`, таблица `0x6d1660`, любые чужие, в том числе союзные) — при живом лидере AttackRod на
каждый (точка — клетка жезла); нет — клетка жезла (`AiTacticScore.RodCell`), есть — PlantRod, и если до неё
Чебышёв ≤ 1 — перебор кончается. **Общий AttackRod** (`0x450cbe`): при живом лидере и **пустом** векторе
кристаллов — на каждый чужой жезл карты. Сверка: 464/466, 464/470, 322/329 (остаток — жезлы, снесённые за день).

**TakeBag** (`0x469418`): хозяин захвачен → нет; по мешкам вектора, точка — клетка мешка (1920 из 1920).
TakeBagRoam — тот же построитель, мешок не дальше 3; бродяга в крепости — нет. Сверка: расхождения только
составом (подобранные мешки, модель исключений), порядок — евклид от клетки отряда.

**Множество +100** (`CAiTactic+0x51dc`, `0x4662d7`): до порога по сложности партии `DIFFGAME` (60/50/40/30 дней) пусто; после —
цели событий победы глазами игрока ИИ (`0x5f1e06` с флагом 0). Ранг 1, перенесено 30.09 — §30.

## 8. VisitRuin (5), `0x46bdb6`, ранг 1 (24.09)

**Кэш руин** `0x45f0ae` (вектор `+0x3c`): руины карты, нетронутые (`0x45f1cb`: грабитель `+0x80` пуст); позиция — вход
(`0x5fdf70`: `pos + 3 − 1`), евклид от позиции отряда; радиус `0x45f5f1` и отбор трёх `0x45f793` — как у прочих векторов.
Попутно: **«места»** `0x45efa4` (вектор `+0x2c`, торговец, маг, тренер, наёмники) — все площадки без фильтра, позиция — вход
(`0x601181`); тренер, торговец и маг перенесены 24.09 (§10, §11), храм — 25.09 (§14); наёмники кэш мест не берут (§13).

```
построитель 0x46bdb6 (оценщик CAiVisitRuinActionEval, vtable 0x6d24b4):
    столица хозяина взята (слот 0x18 обёртки) → нет
    лидер не категории юнита L_LEADER ([0x838188], LUnitC — не вор, не знатный, не призыв) → нет
    группа не может драться (0x5ddf35) → нет                                 # в порте не проверяется, как у атак
    по руинам кэша: слот 0x10 оценщика 0x46bf1e, вставка — слот 0x4c обёртки (фильтр приказа)
слот 0x10: счёт 0x46c02a, NoScore → нет; вплотную ко входу (слот 0x2c обёртки: Чебышёв 1) — посещение, иначе
    перемещение 0x45a915 к входу (режим 1, N = 0)
счёт 0x46c02a: p = 0x5dda98(свои, охрана руины, точка = вход, поддержка = 1); p < 0,7 → NoScore; I_RUINS, влияние у входа,
    Чебышёв; ×p, захват ×0,1, вчера статус 5 ×1,25 (AiTacticEval.VisitRuin)
```

**Сила `0x5dda98`** — общая «свои против группы»: B — своя «без города» против числа юнитов охраны; A — охрана против числа
своих юнитов (брони у руины нет); при флаге — C = **поддержка `0x5ddb38`**: отряды в клетках `x ∈ [px − 10, px + 10)`,
`y ∈ [py − 10, py + 10)` (обрезка краем карты), чужой подрасы (`+0x90` против подрасы своего отряда, `0x5f505a`) и с
приказом не `L_STAND` (`+0xa8` против `[0x837910]`), сумма их силы «с городом» против числа своих юнитов. Итог — формула
`0x5dda25` (строка журнала `ai_strength` с возвратом `0x5ddb31`). Сверка (`AiAttackStrengthHarnessTests`, строка силы перед
кандидатом): human — A 146/146, C 144/146, p 113/146; legions — 219/219, 219/219, 201/219; расходится B (своя сила в живом
дне, как у атак).

Порт: `src/D2.Data/Play/AiTactics.Ruins.cs` (`RuinTargets`, `RuinStrength`, `VisitRuins`), исполнение — вплотную ко
входу `Strike` (бой с охраной, после победы — добыча через `Enter`). Кандидаты (`Candidates_MatchJournal`): лишних у порта
5 и 11, недостающих 24 и 30 — почти все при заниженной B (p ниже 0,7).

## 9. Guard (0x15), `0x457317`, ранг 1 (24.09)

Страж (нейтрал с приказом охраны) бросается на чужой отряд рядом.

```
R = GU_RANGE / 2 (GVars +0x120, 0x5879fd; деление к нулю) — в ванили 5 / 2 = 2
по всем отрядам карты S (iterator_omap<0x23>, по id):
    действующий приказ S (+0xa8 == L_NORMAL ? AIORDER : ORDER) == L_STAND → нет
    Чебышёв от позиции стража (слот 0xc обёртки) до клетки S (+4, +8) > R → нет
    подраса S == своя; S в крепости (+0x94); S невидим (+0x9b); союзник (0x5f7ebd) → нет
    страж «только по воде» и клетка S не годна (0x45753f) → нет                     # в порте не сделано
    вид расы лидера S (0x5edb1a: Grace.RACE_TYPE расы юнита-лидера) == свой → нет
    кандидат: точка — клетка S, счёт 150 (0x6d0a10)
```

Действие `0x45763d` (vtable `0x6d0a8c`) — база атаки `0x4544ab` с N = 0: проверка пути `0x45ab0b`, исполнение — перемещение
`0x453095`, статус 5 → 2; то есть атака перемещением, как атака со взятым порогом (`docs/ai-attack.md` §4). Журнал human: у каждого выбора
охраны — шаг к цели и бой в том же исполнении.

Порт: `src/D2.Data/Play/AiTactics.Guard.cs` (отбор — `AiTacticEval.GuardAdmits`), `GameBook.GuardRange`, исполнение —
`ExecuteAttack`. Кандидаты: лишних у порта нет, недостающих 2 и 2 (повторные окна после боя, где у порта цель уже погибла).

## 10. Места: VisitTrainer (9), `0x46ccef`, ранг 1 (24.09)

**Кэш мест** `0x45efa4` (вектор `+0x2c`): все площадки `CMidSite` (торговец, маг, наёмники, тренер) без фильтра, позиция — вход
(`0x601181`: `pos + size − 1`, пятно 3×3), евклид от позиции отряда; радиус у чужих столиц `0x45f5f1` и отбор трёх `0x45f793` —
как у прочих векторов. Построители берут из него свой класс (`dynamic_cast` к `0x798e08` тренер, `0x798520` торговец,
`0x798c20` маг).

**Кошелёк тактики** `CAiTactic +0x515c` (слот `0x14` `IAiTacticInternal`, интерфейс на `+4`: слот `0x18` → `+0x51c4`, `0x1c` →
`+0x51f8`, `0x20` → `+0x51fc`). Заполняется один раз — при входе в состояние тактики (слот `0x10` `CAiTactic` = `0x46586c`, драйвер
`0x471b39`) после стратегии: `0x4659e2` — нейтрал 0, иначе казна × `B_ISO` / 100 по каждой валюте (`0x5838c0`; `B_ISO` — поле
`+0x34` строки `GAI`, во всех семи строках 70). Вычитают из него (`0x586578`, с зажимом в 0…9999): **обучение** (`0x46d322`) и
**воскрешение** при подготовке (`0x451d74`: `REVIVE_C`, только золото). Лечение там же вычитает `0x5de299` — цену, посчитанную
**после** команды лечения, у вылеченного юнита это 0: лечение кошелёк не трогает (ошибка оригинала). Проверка на журналах: модель
«70 % казны на первой оценке тактики минус воскрешения и обучение» даёт кошелёк не меньше цены одного очка во всех 152 окнах с
тренером (human 90, legions 62); с вычетом лечения — нет (день 45 human: лечение на 149 при кошельке 105, тренер всё равно есть).

```
построитель 0x46ccef (оценщик CAiVisitTrainerActionEval, vtable 0x6d2674):
    столица хозяина взята (слот 0x18 обёртки) → нет
    SUGG_LVL ≥ 10 (0x61eb31): кошелёк < 500 золота (0x5869e6) → нет; 0x4692bf ложь → нет
    по местам кэша класса тренера: есть кого учить (0x46ce2d) → оценщик (конструктор 0x46cf4f, слот 0x10 0x46cf99)
0x46ce2d: юнит группы, у которого 0x5e0372 = 0, а цена одного очка (слот 0x60 = TRAINING_C, через 0x61eb4a) не больше кошелька
0x4692bf: первый отряд человека (CMidPlayer +0x88) в чужих сильнейших (+0x51f8); нет — да; иначе
    сила своих «без города» против числа его юнитов < 0,5 × его силы «с городом» против числа своих (0x5dcec7, полное здоровье)
слот 0x10: счёт 0x46d09f (AiTacticEval.VisitTrainer: I_TRAINER, влияние у входа, Чебышёв, захват ×0,1, SUGG_LVL ≥ 10 ×2),
    NoScore → нет; действие CAiVisitTrainerAction 0x46d1f0 (vtable 0x6d2714) — перемещение 0x45a915 к входу (режим 1, N = 0)
```
