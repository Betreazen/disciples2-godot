# Заклинания ИИ на карте: оперативный слой и литьё (срез 7, 24.09.2026)

Разбор `Discipl2.exe` (GOG 3.01) дизассемблером и сверка с корпусом (`20260918-probe65`, `20260919-human`,
`20260920-legions`). Ранги: 1 — прочитано в листинге, 2 — листинг и корпус, 3 — догадка. Код: `src/D2.Rules/Map/AiSpellRules.cs`
(чистые правила), `src/D2.Data/Play/AiSpells.cs` (сборка по карте и выбор), `GameSession.Spells.cs` (место в ходе),
`GameSession.Cast.cs` (проверка и литьё — общие с окном заклинаний человека). Харнессы: `AiSpellHarnessTests`,
`MapSpellCastTests`, `AiSpellRulesTests`.

## 1. Где заклинания в ходе ИИ

В журналах ИИ бросает заклинания из двух мест:

| Место | human | legions | probe65 |
|---|---|---|---|
| оперативный слой (сразу после стратегии, до тактики) | 18 | 42 | 0 |
| тактика: действие «заклинание перед атакой» (тип 3, vtable `0x6d0d2c`; §5) | 11 | 8 | 9 |
| бесплатное развеивание `G000SS0009` у PL0009 (событие сценария?) | 2 | 2 | — |

Оперативный слой `CAiOperational` (ранг 1), драйвер `0x46d602`, поле `+0x24` — состояние:

```
0: нейтрал (0x5e5358) → конец; флаг +0x28 (копия после тактики) → 5, иначе 1
1: 0x46d691 лечение          → 2
2: 0x46dee2 смена приказов    → 3   (уже перенесено: GameSession.OperationalOrders)
3: 0x46fe35 (SUGG_LVL ≥ 10)   → 4   («натиск» на людей, §2; AiSpells.Harass, 28.09)
4: 0x46e322 защита            → конец
5: 0x46d691 лечение (после тактики) → конец
```

Начало хода слоя (`0x46d5b0`): игрок со взятой столицей (`0x5e4e73`) — сразу конец; `+0x2c` — число из аргумента начала
хода (`0x46d5a1`), по порогам 10/20/40 и выбору журналов — **день** (ранг 2).

Списки отрядов (`0x4719f8` → `0x4760b0`, в начале хода, до стратегии; ранг 1): у каждого игрока берутся **два
сильнейших** отряда (`[0x6d2874]` = 2, обрезка `0x47667d`) с действующим приказом `L_NORMAL` (при `L_NORMAL` в `+0xa8` —
приказ ИИ `+0xb8`), лидер не призыв (`0x431d8c`); сила `0x5dcec7(…, 0, юниты, врагов 1, 0, 1, 1)`, по убыванию, при
равенстве — по номеру id (`0x476604`). Свои — `+0x1c`, чужие (все не-нейтральные игроки, союзники тоже, общий список снова по
силе `0x4763fc`) — `+0x18`. Порт: `AiSpells.MainForces`/`Forces`, сила — `AiTactics.Strength`.

## 2. Выбор (ранг 1, числа сверки — §4)

**Лечение `0x46d691`, часть 1.** Каждому своему отряду списка не в крепости (`+0x94` пусто), если он тяжело ранен
(среднее текущее здоровье ≤ половины среднего наибольшего, целые деления) — известное заклинание `L_HEAL` на одну клетку
уровнем не выше **яруса** отряда, которое можно бросить (`0x5dbd75` без второго кошелька); годные сортируются по уровню
(`0x472618`, `list::sort`), бросается последнее (старшее).

**Лечение, часть 2 `0x46d97a` (28.09, ранг 1, `AiSpells.WholeMap`):** при `SUGG_LVL ≥ 10` (`0x61eb31`) и мане больше 1000 в каждой из
адской, жизни, рун и смерти (`0x586a2e(1, 2, 4, 3)`, 16-битные; роща не смотрится) — известные заклинания на всю карту (`0x582b5a`),
которые стоит бросить: лечение — у своего отряда вне крепости есть юнит со здоровьем ниже наибольшего (павший тоже); усиление и
невидимость — своих отрядов вне крепостей ≥ 2; удар — чужих не союзных (`0x5f7ebd`) вне крепостей ≥ 2; прочие — нет. Годные — те, что
проходят `0x5dbd75` в (0, 0) без второго кошелька; перемешивание `0x46a9f5` (копия в вектор, `0x4495d8` — тот же обмен с `rng(i)`,
что `0x43949e`), литьё первого (`0x41e7f3`, `L_NORMAL`, без цели). Часть 2 идёт при каждом заходе в `0x46d691` — и до тактики, и после.

**«Натиск» на людей `0x46fe35` (28.09, ранг 1, `AiSpells.Harass`):** при `SUGG_LVL ≥ 10` два прохода `0x46fe5e` — «далёкий» (флаг 1),
затем «близкий» (0). Проход: `rng(100) ≤ 49`, иначе ничего; число — 1 (далёкий) или `rng(4) + 2`; цели — чужие сильнейшие (`+0x18`),
чей хозяин человек (`CMidPlayer +0x88`) и не союзник; «близкая» — свой отряд не дальше 10 (Чебышёв, `0x470012`). Цели перемешиваются
(`0x46a9f5`); у первой, против которой есть годные, — известные заклинания категорий прохода (далёкий — `L_LOWER`; близкий —
`L_LOWER`, `L_ATTACK`, `L_SUMMON`) на одну клетку, прошедшие `0x5dbd75` в клетке цели со вторым кошельком; перемешивание, литьё по
порядку, пока удачных меньше числа (`0x41e7f3` с `L_NORMAL` и пустой целью); дальше цели не смотрятся. Призыв проверку в клетке цели
(там отряд) не проходит никогда. Корпус — уровень 1: тесты `AiSpellsHighLevelTests`, `AiSpellRulesTests`.

**Ярус отряда `0x476ad2`:** среднее `XP_KILLED` (`IUsSoldier +0x3c`, реализация выросшая уровнем) по юнитам группы, целое:
≤ 25 → 1, ≤ 65 → 2, ≤ 125 → 3, ≤ 210 → 4, иначе 5.

**Жезлы у своих крепостей `0x46f1d1` (27.09, ранг 1, бросков нет):** список клеток — жезлы не дальше 7 от входа своей крепости
(свой — если у этой крепости нет чужих отрядов играбельных рас ближе 8, включая невидимых и союзников), каждая клетка один раз,
устойчиво по Чебышёву от входа столицы; по известным заклинаниям: снос жезла площади 1 — первый чужой жезл списка, прошедший проверку
(со вторым кошельком); смена земли в лес — у первого своего жезла первая равнина по рамкам радиусов 1…4 (строки по y), прошедшая
проверку, иначе клетка жезла; литьё без второго кошелька, не больше одного на заклинание (`AiSpells.GuardRods`,
тест `MapSpellEffectsTests.AiDefend_RemovesForeignRodNearOwnFort`).

**Защита `0x46e322`:** при `SUGG_LVL < 10` — `0x46e37c`, затем всегда `0x46f93e` и `0x46f1d1` (смена земли и снос жезла у
своих крепостей — выше).

- `0x46e37c` — свои крепости без визитёра по id: каждый чужой отряд списка `+0x18` не дальше 7 (Чебышёв) от входа
  крепости (`pos + size − 1`) — **удар** `0x46f08c`; каждый чужой вор (`LEADER_CAT` 5, `0x41b399`) с приказом `L_NORMAL`
  (сам `+0xa8`), видимый, не союзник (`0x46e6af`) не дальше 5 — призыв уровней 1…2, одно заклинание (`0x46e881`).
  Нет ни воров, ни чужих — выход.
- `0x46f93e` — чужие жезлоносцы (способность `L_ROD` `0x837618`; порт — `LEADER_CAT` 4) с приказом `L_NORMAL`, видимые, не
  союзники (`0x46fc33`); по кристаллам (`CMidCrystal`) на равнине или в лесу, чья земля — земля расы игрока (`0x5e515e`): каждый
  жезлоносец не дальше 5 — ярус больше 1 → удар, иначе призыв уровней 2…3 (`0x46fd8d`).

**Удар `0x46f08c`:** по ярусу цели `0x476bc4` (флаг 1) — число и уровни: 1 → (2; 2…2), 2 → (2; 2…3), 3 → (2; 3…4),
4 → (3; 3…5), 5 → (3; 4…99); затем `0x46f193`: наименьший уровень не ниже дневного (день ≤ 10 → 1, ≤ 20 → 2, ≤ 40 → 3,
иначе 4), наибольший — не ниже наименьшего. Ищутся `L_ATTACK` и `L_SUMMON` этих уровней.

**Выбор и литьё `0x46e92c`** (все броски — R250 `0x54851f`):

1. `rng(число записей)` — с какой записи начать круг категорий;
2. годные заклинания каждой записи (`0x46eda3`), в порядке известных: категория записи; на одну клетку (`AREA` 1:
   `0x582b5a` — не вся карта, `0x582b6b` — не площадь); призыв — не иллюзия (`0x438ff3`, `IUsIllusion`); уровень в
   диапазоне; против цели годится по иммунитетам (`0x476c55`: доля юнитов с иммунитетом не `L_NOTIMMUNE` — к `DAMAGE_SRC`
   у удара, к источнику и классу первой атаки призываемого — меньше 0,5); бросить можно (`0x5dbd75` со вторым кошельком; у
   призыва — в клетке постановки `0x5edded`);
3. пусто: если это не запасной заход — запасной с одной записью `L_ATTACK` уровней 2…2 (или 2…(наименьший − 1), если у записи
   атаки наименьший больше 2) и числом 1; запасной — выход;
4. отбор `0x46ef83`: с начала списка убирать заклинания ниже наибольшего уровня, пока их больше числа;
5. `n = min(rng(число) + 1, всего)`; перемешивание `0x43949e` (для `i` = 1…конец — обмен с `rng(i)`, `n − 1` бросков, `rng(1)`
   тоже бросок); обрезка до `n`; порядок `list::sort` с предикатом `0x46ed41` («меньше» всё, кроме призыва перед
   не-призывом — строгого порядка нет, на списке без призывов сортировка его разворачивает);
6. каждое бросается в клетку цели со вторым кошельком (`0x41e7f3`), призыву — приказ `L_ATTACK_STACK` на цель.

Каждый заход в `0x46e92c` тратит хотя бы один бросок R250 — отсюда проверка числом бросков окна (§4).

## 3. Литьё на карте (разбор подагента 24.09, ранг 1, сверка — ранг 2)

**Команда** разбирается на сервере `0x443600`: результат по категории (`0x443828`, классы `CSpellResult*`), у призыва —
клетка постановки `pos' = результат +0xc`; для всех, кроме призыва, тумана, развеивания, сноса жезла и смены земли, —
проверка цели `0x5db2cb` (не прошла — ничего); затем `CEffectSpell` (→ `0x5dc2d6`: проверка с шестым аргументом 1, оплата
`0x5dc334`, запись `0x5dc481`, `TURN_STOP = день + 1`) и постэффекты (урон, гибель отряда, модификатор, новый отряд).

**Проверка `0x5dbd75(заклинание, игрок, клетка, второй кошелёк, бесплатно, arg6, карта)`**, первый отказ:

- игрок нейтрал (`0x5e5358`) — можно, без проверок; в литье нет ни оплаты, ни записи;
- `0x5dab48`: вся карта — можно; клетка вне карты — 7; туман игрока: развеивание — только под туман, туман при `arg6` — без
  проверки, прочее — только видимая клетка (8);
- `0x5dba61`: бесплатно — можно; не изучено — 12; уже брошено сегодня (записей `CMidSpellCast` игрока с этим заклинанием ≥ 1,
  у лорда-мага `[0x837760]` ≥ 2) — 17/18; не хватает казны (при втором кошельке — казна + кошелёк, по каждой валюте) — 9;
- `0x5db2cb` цель: площадь с центром на крепости — 2; туман, развеивание — можно; призыв — клетка годна (`0x5e6db2`), иначе
  2; шесть категорий «на отряд» (удар, ослабление, лечение, усиление, ход, невидимость) — одна клетка: отряд в ней; площадь:
  квадрат без стоящих в крепости; нет — 6; можно, если хоть один проходит `0x5dac42`:
  невидимый чужой — 6, свой — 16; удар/ослабление — свой 2, союзник 15; лечение/усиление/ход/невидимость — чужой 2
  (усиление союзнику можно); в крепости — 2; удар — все живые иммунны к источнику — 3; лечение — некого — 5; ход — запас
  полон — 5; невидимость — уже невидим 5, лидер-иллюзия 2; усиление/ослабление — тот же модификатор на лидере — 4.

**Оплата `0x5dc334`:** хватает основной казны — она минус цена; иначе со вторым кошельком: недостача `max(0, цена − казна)`
по валютам — из кошелька, основная казна обнуляется целиком, золото тоже. Сверка 91/91.

**Эффекты** (сила на площади — `GVars.SPLPWR_0..4` = 100/80/60/40/30 % по Чебышёву от центра):

- удар `0x41c05c`: урон `DAMAGE_QTY · %`, без брони и случайности, только юнитам с `L_NOTIMMUNE` к источнику (`L_ONCE` на
  карте защищает как `L_ALWAYS`, оберег не тратится); павшие не трогаются; лидер-иллюзия — отряд пропускается; нет выживших
  — отряд снят; опыта нет. Сверка 141/141 строк `hp_change` в 68 атаках;
- лечение `0x41cbd1`: `HEAL_QTY · %` живым, до наибольшего здоровья; павшие не встают. Сверка 32/32;
- призыв: клетка `0x5edded` — кольца 0, 1, 3 вокруг точки, в кольце обход с конца (§5), первая годная;
  хозяин — заклинатель; приказ — из команды (у ИИ `L_ATTACK_STACK`), иначе `L_NORMAL`, у нейтрала `L_BEZERK`; полный запас
  хода; срока жизни нет. Сверка 9/9 (тактические призывы).

Порт (`GameSession.Cast.cs`, `GameSession.SpellEffects.cs`): проверка целиком; эффекты удара, лечения, призыва и (26.09, ранг 1 по
листингу) результаты по категории (`0x443828` — один на категорию):

- усиление и ослабление (`CSpellResultModifier` `0x41ca78`): каждому юниту отряда-цели (площадь — все отряды квадрата, вся карта —
  свои) `MODIF_ID` в цепочку и запись `CMidSpellEffects` (`MapState.SpellEffects`: юнит, заклинание, модификатор, заклинатель,
  `TURN_STOP = ход + 1`, `CEffectModifier` `0x4396e2`). Повтор литья человека дня 62 (сохранение 102 → 103, «G000SS0040» и «G000SS0088»)
  дал записи сохранения 103 запись в запись;
- ход (`CSpellResultMove` `0x41c617`): дневной запас × `RESTORE_M` / 100 (`CEffectChangeAP`), не выше запаса; модификатора у этой
  категории нет (у «Swift» `g000um7538` результат хода не кладёт);
- невидимость (`CSpellResultInvisibility` `0x41c9a5`, `CEffectShow` с 0): отряд прячется до нападения (генератор хода `0x43fe65`
  показывает его, когда путь кончается действием — в порте начало боя нападающим, ранг 2);
- развеивание (`CSpellResultUnfog` `0x41c723`): квадрат вокруг клетки, радиус `AREA / 2` (вся карта — сторона карты), эффект тот же, что
  у события `L_UNFOG` — `±(радиус + 1)` (ранг 2).

Срок: в начале хода владельца записи (`CASTER_ID`, пустой — хозяин юнита) с ходом ≥ `TURN_STOP` снимаются вместе с модификатором
(`CEffectRemoveSpell` `0x43b9ef`); записи читаются из `.sg`, так что снимаются и наложенные до загрузки. Зелье усиления на карте —
та же запись (`ORIGIN_ID` — тип предмета). Литьё событием (`L_CAST_SPELL`) делает те же эффекты. Туман — `FogSpell` (26.09).

**Смена земли и снос жезла (27.09, ранг 1 по листингу).** Цель (`0x5db2cb`): смена земли (`0x5db4fc`) — в квадрате `AREA` есть клетка,
где она что-то меняет, иначе отказ 5; снос жезла (`0x5db847`) — в клетке жезл (тип id 0x2b), не свой. Смена земли (`0x41cdd5` →
эффект `0x43591d`/`0x4359a7`): квадрат `c − AREA/2 … c − AREA/2 + AREA − 1`, обрезанный картой; клетка без крепости, дороги, ориентира,
лавки, руины, жезла, жилы (`0x5f5631`, типы 0x1d, 0x22, 0x25, 0x28, 0x29, 0x2b, 0x2c), грунт — равнина или лес, в клетке и восьми
соседях нет жилы, грунт не тот, что делает заклинание → грунт `GROUND_CAT` и нейтральная земля (`L_NE`, категория в поле эффекта; ранг 2
— что визитёр `0x5e685e` пишет обе). Снос жезла — как у отряда, но без штрафа (пустой виновник) и без траты хода. Код —
`GameSession.SpellEffects.cs` (`TerrainCells`, `TerrainSpell`, `RodSpell`), тесты — `MapSpellEffectsTests`. Обереги — только оплата
и запись (в ванили заклинаний нет).

## 4. Сверка (`AiSpellHarnessTests.OperationalSpells_MatchJournal`)

«Живой день» (`AiLiveDay`): сохранение дня, поверх — ходы, бои, наймы лидеров, приказы и **земля игрока из `terrain_day`**
(у движка за день сносят жезлы, и земля кристалла к ходу игрока уже не его). Каждому игроку ИИ — начало хода и стратегия
портом, затем оперативный слой. Против журнала того же игрока и дня:

| Что | Сошлось |
|---|---|
| ходов ИИ | 732 |
| число бросков R250 между концом стратегии и первой `ai_tactic_pick` | 732 (было 727) |
| литья окна (заклинание и клетка) | 732 хода (было 731); все 60 литий журнала повторены, лишних нет (было 1) |
| здоровье юнитов после литья (`hp_change`) | 126 из 126 (было 125: живой день не повторял переносы `ai_reorder` и найм юнитов — 30.09) |

Без ходов предыдущих игроков ИИ броски сходились у 671, без земли из журнала — у 722. Бывший остаток (5 ходов, 28.09) — не
списки сил (`0x4760b0` → `0x476252` перечитан: свои, действующий `L_NORMAL`, лидер не `IUsSummon`, сила `0x5dcec7` с модификаторами
и полным здоровьем — как у порта), а харнесс: (1) найм лидера из журнала шёл после оперативного слоя, а у движка он в стратегии —
новый отряд-гость закрывает крепость для `0x46e37c` (визитёр `+0x8c`): human PL0009 день 45, PL000c день 61, probe65 PL0002 день 2 —
+3 (`AiLiveDay.Begin(hires)` → `BeginAiTurn(journalHires)`); (2) день 23 PL0009 записан трижды (загрузки), живой день шёл с первой
записи — теперь переигранный день начинается с сохранения заново, +2. Проверка старым правилом (без обоих) — прежние 727/731/61.

## 5. Подготовка к атаке: заклинание и подмога перед атакой (тактика, 24.09, ранг 1)

Код: `src/D2.Rules/Map/AiBeforeAttack.cs` (пороги, категории, запасной заход), `src/D2.Data/Play/AiTactics.BeforeAttack.cs`
(построитель производных, планировщик, подмога), `AiSpells.BeforeAttack.cs` (выбор заклинания),
`GameSession.Tactics.cs` (`ExecuteTactic`, `ExecutePrepared`, `AttackDirect`). Тесты: `AiBeforeAttackTests`,
`AiTacticEvalTests`, харнесс `AiTacticFromMapHarnessTests.Candidates_MatchJournal`.

**Классы** (RTTI): `CAiCastSpellBeforeAttackStackAction` (vtable `0x6d0d2c`) / `…CityAction` (`0x6d0bfc`),
`CAiAssistBeforeAttackStackAction` (`0x6d0dc4`) / `…City…` (`0x6d0c94`), итоговая атака
`CAiTacticActionRefCount<CAiBasicAttackStackAction>` (`0x6d053c`) / `<…City…>` (`0x6d0394`). Все делят одно действие атаки
(`+0x68`/`+0x60`, счётчик ссылок).

**Построители** атаки отряда (`0x453d15`) и крепости (`0x452baf`) после счёта S и силы p (байт «порог взят» — пятый аргумент
порога `0x45137e`/`0x4505c9`):

```
S == NoScore → ничего; у отряда и S == 0 → ничего (fcomp [0x6d0528] = 0.0)
тип 3/0x1b (отряд) или 2 (крепость), раса хозяина играбельна, действующий приказ L_NORMAL — иначе одна атака
план = 0x471ec7(...)
  план пуст: разрешил → атака (0x454210 / 0x45301f); не разрешил → ничего (при взятом пороге)
  есть: каждый элемент (id заклинания → «заклинание», id отряда → «подмога») со счётом S, S − 0,0001, …
        (fsub [0x6d0530] — float 0,0001); порог НЕ взят → последней итоговая атака (0x4541d6 / 0x452fe5)
```

Фильтр приказа стоит до построителя, поэтому у `AttackParty` при `L_NORMAL` подготовки (и её бросков) нет.

**Планировщик `0x471ec7`** (`ret 0x30`): p ≥ 0,75 (хозяин цели человек или раса неиграбельна) / 0,7 — атака без подготовки. Иначе,
если хозяин атакующего не нейтрал и у цели есть юниты (длина вектора группы): столица хозяина не взята (`0x5e4e73`) — заклинание
`0x472142`; нет — подмога `0x472909`. Пусто — хвост `0x4720a4`: порог не взят — атака остаётся; взят — при `L_NORMAL` атака, если
`p ≥ 0,6` (у цели неиграбельной расы — 0,7). Итог: у человека при p 0,5…0,6 без подготовки кандидата атаки нет.

**Выбор заклинания `0x472142`** (`ret 0x38`): категории — удар (цель — отряд вне крепости), призыв, при атакующем вне крепости и
взятом пороге — ослабление и усиление; при p < 0,6 и взятом пороге — только удар. Уровни — ярус цели `0x476bc4` с флагом 0
(ярус 1 → 1…2, иначе как у удара оперативного слоя). Годные (`0x47263e`, по известным): категория, одна клетка, призыв не иллюзия
(`0x472840`), уровень, точка литья `0x4724b1` (удар — цель и её клетка; призыв — клетка `0x5edded`; ослабление и усиление —
**сам атакующий** и его позиция, поэтому ослабление отвергает проверка `0x5dac42`), иммунитеты `0x476c55`, проверка
`0x5dbd75` со вторым кошельком `0x45422e` (цель — из чужих сильнейших `CAiTactic +0x51f8` и хозяин её человек). Пусто — запасной
заход ударом 1…(наименьший − 1), если наименьший ≥ 2 и порог взят. Бросок 1 — категория среди встреченных у годных, но
отбор (`0x472372` → `0x47258b`) берёт категорию из нового `begin()` списка (`0x47235a`), а не из итератора броска — всегда первую
встреченную (по порядку изученных — он отсортирован по id, `KnownSpellOrder`); из годных остаются её заклинания, сортировка по
уровню, спереди снимаются младшие; бросок 2 — одно из старших (карта 19, 19.10: литьё 34/34 на корпусе). Счётчик
«уже брошено в эту цель» (`CAiTactic +0x51c8`, `0x46a034`) никто не пополняет — всегда 0.

**Подмога `0x472909`**: отряды с очками хода, той же подрасы, действующий `L_ASSIST` на атакующего, лидер не призыв; воры, затем
прочие, каждая группа по силе `0x4763fc`. Элемент — (помощник, цель, точка атаки).

**Списки `CAiTactic`** (конструктор `0x46556e` из `0x4718ba`): `+0x51fc` = `CAi +0x24` (свои два сильнейших начала хода),
`+0x51f8` = `CAi +0x34` (чужие). Первый из своих — «главный» отряд радиуса кэша целей (`0x466ac7`) — порт берёт его
(`AiTacticTurn.Forces`); в корпусе он совпал с прежним приближением во всех оценках.

**Проверка пути и исполнение.** Атака отряда и крепости (`0x4506fb`): «напрямую» (`+0x5c` — только у слабой атаки во втором
проходе, `docs/ai-attack.md` §8) — пути не ищет, помечает атаку готовой (`+0x50`, `0x45aaf7`); иначе поиск `0x45ab0b` → `0x46903e`,
и `+0x50` — «сегодня встанет вплотную» (исправлено 24.09: раньше порт считал готовой только атаку в пределах обзора). Производные,
пока атака не готова, отдают ей путь, исполнение и статус (подход). Готова: заклинание (`0x458982`) — проверка и литьё в точку литья со своим
кошельком, призыву — приказ `L_ATTACK_STACK` на цель, статус 2 (`+0x5c`); подмога (`0x4586cc`, `0x458c45`) — остаётся, только если
помощник сегодня дойдёт вплотную (флаг `+0x50` поиска `0x46903e`), исполнение — ход помощника к точке атаки (статус 5 → 2).
Итоговая атака — просто атака. Память статусов — по ключу исполненного действия (у готовых — своему).

**Сверка** (`Candidates_MatchJournal`, human / legions): по целям атаки, что есть у обоих, последовательность видов сошлась 635 из
651 и 444 из 481; броски R250 окна оценки — 1530 из 1581 и 1699 из 1752 окон; литьё после выбора журналом «заклинания перед
атакой» — 7 из 11 и 5 из 8 точно (после разбора клетки призыва, ниже; остальное — другое заклинание). Помехи: R250 в харнессе не выставлен (выбор —
броски; `rng_seed` есть только на старте партии, отбраковка `Next` сдвигает шаги), сила p и приказы
помощников в живом дне. `EndCells_OfTheDay`: из ходивших у движка отрядов сошлось 263 из 619 (было 258 из 614).

**Клетка призыва** `0x5edded` (ранг 1, разбор 24.09): три прохода, границы квадрата копятся (к уже расширенным
прибавляется номер прохода) — кольца радиусов **0, 1, 3**. Клетки кольца кладутся по x, внутри по y (`push_back` `0x524c10`);
при двух и больше последняя переносится в начало (`0x5edf3f` — `push_front`, `0x5edf64` — `pop_back`), затем они проверяются
**с конца** (`back` `0x43a220`, неудача — `pop_back`). Годность `0x5e6db2` → `CVisitorCreateStack` (vtable `0x6f0824`, слот
`0x60ceaf`): у призываемого тип-лидер; цена хода `computeMovementCost` `0x6027f3(клетка, карта, сетка 0x5e63a8, план 0x5f61f2,
stackId = null, a6 = a7 = 0, лидер жив, бонусы равнины/леса/воды = 1, «по воде» — слот 0x70 лидера, forbidWaterOnlyOnLand = 1)`
не 0: не гора, нет крепости, ориентира, места, руины, жезла, кристалла, мешка и **никакого** отряда; вода и дорога годятся;
у призыва «только по воде» ещё `0x60cf85` → `0x5e6453` (вода). Раньше порт обходил кольцо с начала и брал только пустую
равнину или лес — после правки литья перед атакой сошлись 7 из 11 и 5 из 8 (было 3 и 4), клетки призыва — все; тест
`MapSpellCastTests.SummonCell_RingFromTheEnd_WaterAllowed` (день 42: вокруг (15,17) — (16,16), как у движка).
