# Правила работы в disciples-godot

Порт Disciples 2 (GOG 3.01) на Godot 4.7.2, C#/.NET 10 (SDK закреплён в `global.json`). Точка продолжения — **`docs/HANDOFF.md`**, начинать с неё.

## Главное правило проекта — `docs/principles.md`

Поведение — как в оригинале (доказывается харнессами по журналам зонда, не на глаз). Устройство — по современным
игровым стандартам: данные отдельно от кода, слои модов, точки расширения, имена по смыслу, графика обычными
форматами. Старые форматы игры (`.dlg`, `.ff`, `.dbf`, `.sg`) только импортируются, в рантайме порт от них не зависит.

## Безопасность данных — нарушение уже стоило потери корпуса (18.09.2026)

- **Рабочие копии git (`../dg-wt-*`) сносить ТОЛЬКО `python tools/wt_remove.py <путь> --branch`.** Он снимает
  ссылки на каталоги и отказывается удалять, если не снялись. `git worktree remove --force` по ссылке стирает
  оригинал.
- **Никаких symlink/junction ради прогонов.** Данные — переменными окружения: `D2_CORPUS_DIR` (журналы),
  `D2_ASSETS_DIR` (корень `assets`), `D2_GAME_DIR` (копия игры).
- Корпус журналов в git не входит; резерв — `C:\Claude code projects\_corpus-backup` (туда пишет `passive_run.py`).
- Код резервируется в приватный `github.com/Betreazen/disciples-godot`; локальные хуки `.git/hooks/post-commit` и
  `post-merge` пушат `main` в фоне (лог `.git/push.log`). После серии коммитов сверять `git ls-remote origin main`.

## Как проверять

- **`python tools/check.py`** — проверка одной командой (сборка, тесты, ui-render-check и pytest по необходимости, итог таблицей).
  **В цикле работы** — без ключей (`--affected`): классы тестов, задетые правкой против main (`tools/affected_tests.py`: граф
  `graphify-out` + прямые пользователи по тексту), плюс smoke; обычно 10–30 с. **Полный прогон — один раз в конце**: `--full`
  (CI-сборка + все тесты + ui-render-check, если задет вид). Ещё `--fast` (без синтетики), `--synth`, `--smoke`. Что задето и
  почему — `python tools/affected_tests.py` (без запуска). Корпус и графику в рабочей копии `../dg-wt-*` скрипт берёт из основного
  каталога сам.
- `dotnet test` — всё (D2.Data, D2.Rules, GodotRef). Сейчас 2590/2591, пропуск 1 (в рабочей копии `../dg-wt-*` — с `D2_CORPUS_DIR` и
  `D2_ASSETS_DIR`) (тест с независимым читателем зовёт `D2_PYTHON`, на Windows по умолчанию `py`). Полный прогон ~1:45–2:10 на свободной
  машине, пик памяти обоих процессов ~11 ГБ (20.10: было ~2:05 и ~23 ГБ — два прогона разом не влезали в 32 ГБ и шли по ~9,5 мин,
  теперь по ~3,3 мин; корпус 2 ГБ журналов и 1265 сохранений — `docs/perf-log.md`, «Скорость проверок, 20.10»). Упирается в процессор
  (сами ходы ИИ в харнессах); память — главное, что держать: кэш, который растёт со всем корпусом, — под слабой ссылкой (`SgFile.Open`). Долгая проверка — своим классом (xUnit гонит тесты одного класса подряд, параллелит классы):
  строки теории на длинных партиях — отдельными классами, как `DailySaveAiTurnsHarnessTests_Legions`.
- **Категории тестов** (`[Trait("Category", …)]` на классе или тесте): `Corpus` — читает корпус журналов и сохранений, `Synth` — партии
  синтетических карт (`corpus/*-port-synth`, `mods/port-synth`); без категории — smoke (`--filter "Category!=Corpus&Category!=Synth"`,
  ~1330 тестов за ~15 с, корпус не нужен). Новый харнесс по корпусу — `Corpus`, по синтетике — `Synth` (сверки синтетических партий —
  отдельным тестом `_Synth`, как у `AiSpellHarnessTests`). Разметку сторожит `check.py --smoke`: он гонит smoke с пустым корпусом,
  пропуск или падение = класс без категории.
- **Журналы и сохранения в тестах — только через общие кэши**: `JournalCache.Read/Battles/Count` (не `CorpusReader` — он для игры и
  разбора временных файлов), `SgFile.Open`, `SaveSnapshots.Of`, содержимое игры — `SharedContent.Load` (D2.Data.Tests), карта и объекты
  сохранения для сверки только чтением — `SaveMaps.Map/Sites` (D2.Rules.Tests; харнесс, который меняет карту, берёт `MapLoader.Load`),
  генератор движка по журналу — `JournalRng` (перематывает от опорных точек). Новый харнесс
  не должен сам заново разбирать большие журналы и сохранения, которые уже разбирает соседний.
- **ui-render-check — только когда задет вид**: сцены `godot/**`, данные `data/{ui,gfx,map,sound,music,video}`, `mods/**`, код вида
  `src/D2.Data/{Ui,Gfx,Map,Content,Sound,Menu}` или тип, который сцены Godot берут напрямую (решает `affected_tests.py`, `check.py`
  запускает сам). Шаги не выбираются — весь, ~20 мин; правка логики без вида его не требует.
- `dotnet build godot/D2.Godot.csproj` перед запуском сцен (иначе Godot берёт старую сборку).
- `python tools/ui-render-check.py` — экраны интерфейса без окна, числами.
- Сборка как в CI: `$env:CI='true'; dotnet build Disciples.sln -c Release` — анализаторы и стиль (`Directory.Build.props`,
  `.editorconfig`), предупреждения — ошибки; сейчас 0. `dotnet format whitespace` по всему дереву не запускать: `.editorconfig`
  описывает плотный стиль проекта, но Roslyn переформатировал бы ~1000 мест (`[Fact] public void …` в одну строку).
- Скорость — `python tools/bench/run_all.py`; «до/после» двух рабочих копий — `python tools/bench/ab.py <до> <после> --pairs 10`
  (вперемешку, ABBA, вердикт по парам: один прогон и правило «все по одну сторону» на коротких случаях врут); журнал — `docs/perf-log.md`.
  Игра через Godot идёт на Debug-сборке C# — она с оптимизацией JIT (`Directory.Build.props`), её и мерят сцены `godot/bench`.
- Запуск игры пользователем — журнал зонда порта (`docs/port-probe.md`, F9 — пометка); разбор: `python tools/port_log_report.py`.
- Факты о движке Godot — `python tools/godot-ref/godot_ref.py <Класс[.член]>` и `docs/godot-notes.md` (проверенные
  прогоном: снимка вьюпорта без окна нет, необработанное исключение C# не роняет процесс — всегда `Quit(код)` и
  таймаут, для сверки пикселей фильтр Nearest).
- Диагностику мерить кодом, а не глазами: сцена печатает числа, скриншот открывать только когда число уже есть.
- Реверс `Discipl2.exe` — Ghidra 12.1.4 и REA (MCP `rea`, скилл `reverse-engineer-anything`): `docs/re-tools.md`.
  Псевдокод — гипотеза, доказательство — харнесс по журналу.

## Граф проекта — `graphify-out/` (graphify)

- Вопрос об устройстве («где это», «кто вызывает», «как связаны», «что заденет правка») — сначала граф, потом grep:
  `graphify query "<вопрос>" --budget 1500`, `graphify explain "Узел"`, `graphify path "A" "B"`, `graphify affected "X"`.
  Обзор — `graphify-out/GRAPH_REPORT.md` (главные узлы, сообщества, неожиданные связи). Граф — карта, не доказательство: перед
  правкой открыть файл по `source_file`/строке из ответа.
- В графе код (AST) и документы `docs/` (разобраны подагентами); границы — `.graphifyignore` (корпус, данные, графика, сторонний код
  зонда — вне графа).
- После серии правок кода — `PYTHONHASHSEED=0 graphify update .` (без LLM, ~35 с). Без переменной graphify 0.9.67 на Windows
  молча падает (код 139: перезапуск через `os.execvpe`) у `update`/`extract`/`cluster-only`/`label`. Изменились документы —
  `/graphify . --update` (LLM, только изменённые); его скрипты идут через `graphify-out/.graphify_python` — интерпретатор uv с 0.9.67
  (старый Python с 0.9.14 разбирает код беднее, и слияние упирается в защиту от усадки графа). Свежесть — коммит в разделе
  Graph Freshness отчёта против `git rev-parse HEAD`.
- `graphify-out/` в git не входит; у каждой рабочей копии `../dg-wt-*` своя копия графа. Новой копии — скопировать из основного
  каталога (`cp -r graphify-out ../dg-wt-<имя>/`, обычная копия, не ссылка), затем `PYTHONHASHSEED=0 graphify update .` в ней.

## Соседний репозиторий `../disciples-modding` — инструменты, не место работы

Оттуда берутся: эталонная копия игры `game-pristine` (таблицы, графика, разметка), рабочая копия `game-dev` с зондом,
запуск партий `tools/gamedrv/passive_run.py`, синтетические карты и памятки `docs/synthetic-maps/`, реверс
`tools/re` (capstone) и отчёты `docs/synthetic-maps/analysis/`. Игру запускает пользователь (или драйвер, только
когда пользователь не занят). `../disciples-mod` и `../disciples-vanilla` — только читать.

## Пользователь

Играет партии по памяткам и сообщает, что видел; знает интерфейс игры — маршруты спрашивать у него. Пишет по-русски,
ответы — по-русски, коротко и по делу. Подагентам в задачах повторять правила безопасности выше.
