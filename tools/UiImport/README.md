# UiImport — экраны порта из старой разметки

Переводит разметку исходной игры (`Interf/Interf.dlg`, `Interf/CustomLobby.dlg`) в набор экранов порта
`data/ui/screens.json`. Файл лежит в git: это данные порта, а не кеш, и правится руками наравне с тем,
что выдал перевод.

## Пересборка

```sh
dotnet run --project tools/UiImport
# свои пути:
dotnet run --project tools/UiImport -- --game "C:/…/game-pristine" --out data/ui/screens.json
```

Без параметров исходники ищутся в `<GamePaths.GameDir>/Interf` (переопределяется переменной среды
`D2_GAME_DIR`), а `CustomLobby.dlg` — там же и в соседней папке `game-dev/Interf`: с эталонной копией игры
он не поставляется.

Сейчас на выходе **132 экрана и 1475 элементов** (128/1429 из `Interf.dlg` плюс 4/46 из `CustomLobby.dlg`),
около 530 КБ.

Перевод повторяем: те же исходники дают тот же текст байт в байт. Это проверяет
`UiScreensTests.Screens_Json_IsUpToDate` — если `.dlg` или правила перевода изменились, а файл не пересобран,
тест падает и называет первую разошедшуюся строку. Тест пропускается, когда исходников на машине нет.

## Что перевод делает сверх перекладывания полей

Экраны порта — своя система, рассчитанная на правку и моды, а не копия старого формата. Правила и оценка
надёжности каждого — в XML-комментариях `src/D2.Data/Ui/DlgImport.cs`; коротко:

- **Id экрана** — имя из `DIALOG`. Все 132 имени различны, поэтому имя и есть устойчивый ключ. Его не
  переименовывают: по нему мод находит экран.
- **`Anchor`** — привязка к краям, которой в исходнике нет: экран делится на трети по каждой оси, и центр
  элемента попадает в одну из девяти клеток. Элемент у левого края останется у левого края при другом размере
  окна; нарисованное посередине (и фоны во весь экран) останется посередине. Ручная правка всегда главнее.
- **Прямоугольник** — левый верхний угол и размер вместо двух углов.
- **Поля разбираются по виду элемента**, как их читает движок: у переключателя четыре кадра выключенного
  состояния и три включённого (`Sprites` и `Checked`), подсказка идёт после них; у списков подсказки нет
  вовсе; коды клавиш — в `Hotkeys`; строка оформления (`\hC;\vC;`) — в `Style`, пока как есть.
- **Списки и счётчики** получают своё устройство: `List` — ячейка и зазоры (у списков картинок), кнопки
  «вверх / вниз / влево / вправо / страница вверх / страница вниз / подтвердить», рамка выделения или
  оформление выделенной и обычной строки; `Spin` — кнопки «больше» и «меньше». Кнопки — ссылки на `Id` того же
  экрана (это проверяет `UiScreensTests.Screens_ListAndSpinLinks_PointToButtonsInSameScreen`).
- **`Legacy`** остаётся только там, где назначение поля неизвестно: первые три поля текстового списка
  (всегда `1,0,0`), флаг кнопки, одиночные нули. Разобранное в `Legacy` не дублируется, пустые хвосты отброшены.

Насколько это надёжно: прямоугольники, кадры, строки локализации и состав групп прочитаны прямо из файла.
Разбивка кадров переключателя 4+3 и смысл кодов клавиш выведены из образцов (`BTN_OK` = 13 = Enter,
`BTN_BACK` = 27 = Esc) — правдоподобно, но дизассемблированием не проверялись. Так же, из образцов, выведена
раскладка полей списков: ячейки с зазорами сходятся с прямоугольником (3×85 + 2×6 = 267), кнопки названы по
назначению; порядок кнопок счётчика совпадает с `increment`/`decrement` в реверсе тулсета.

## Как мод меняет экраны

Мод кладёт рядом свой JSON того же вида — только те экраны, которые меняет, — и он накладывается поверх
базового по `Id`:

```csharp
var screens = UiScreens.Merge(
    UiScreens.Load("data/ui/screens.json"),
    UiScreens.Load("mods/мой-мод/ui/screens.json"));
```

Совпало имя — экран мода **заменяет базовый целиком** (не сливается поэлементно: так видно, что именно мод
показывает, и порядок отрисовки не зависит от порядка слияния). Новое имя — экран добавляется в конец.
Порядок базовых экранов сохраняется. Чтобы поправить одну кнопку, скопируйте экран целиком и правьте копию.

Минимальный экран мода:

```json
[
  {
    "Id": "DLG_ACTION_RESULT",
    "Design": { "X": 0, "Y": 0, "Width": 573, "Height": 586 },
    "Background": "_PG0250IX",
    "Elements": [
      { "Id": "BTN_YES", "Kind": "Button", "Rect": { "X": 421, "Y": 452, "Width": 49, "Height": 94 },
        "Anchor": "BottomRight", "Sprites": { "Normal": "MY_OK_N", "Hover": "MY_OK_H" },
        "TextId": "X100TA0020", "Hotkeys": [13] }
    ]
  }
]
```

Пустые списки (`Hotkeys`, `Members`, `Legacy`) и незаполненные поля в файле не пишутся — при чтении они
дают пустое значение.
