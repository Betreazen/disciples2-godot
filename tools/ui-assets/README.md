# Интерфейсная графика: архивы игры → WebP без потерь + манифест

Порт не должен в рантайме знать формат `.ff` (MQDB) старой игры. Графика интерфейса
вынимается один раз этим инструментом: картинки (WebP без потерь, ключ прозрачности уже вырезан) ложатся на диск, а в git коммитится только
список кадров — по нему порт проверяет, что грузит.

## Пересборка

```
python tools/ui-assets/build_ui_assets.py
```

Игра берётся из `D2_GAME_DIR` (по умолчанию `C:\Claude code projects\disciples-modding\game-pristine`):

```
D2_GAME_DIR=/путь/к/игре python tools/ui-assets/build_ui_assets.py
```

Нужны Pillow с WebP и numpy (`pip install pillow numpy`). Прогон занимает ~3 с (пул процессов на все ядра).

Ключ прозрачности (пурпур, RGB565 0xF81F) вырезается при записи каждого кадра, в одном проходе с распаковкой; сборка идёт
во временный `assets/ui.new`, готовый каталог встаёт на место переименованием в конце (`keyed_webp.py`): прерванная
сборка или запуск игры посреди неё оставляют прежнюю целую графику, пурпурных файлов на диске не бывает. Выход —
`D2_ASSETS_DIR/ui`, если переменная задана.

## Что получается

| Куда | Что | В git |
|---|---|---|
| `assets/ui/<Архив>/frames/<ИМЯ>.webp` | собранные кадры | нет (`.gitignore`) |
| `assets/ui/<Архив>/anims/<АНИМ>/NNN_ИМЯ.webp` | кадры анимаций по порядку | нет |
| `data/ui/assets.json` | список кадров: имя, архив, путь, размер, короткий sha256 пикселей RGBA | **да** |

Всего 1940 кадров, 31 МБ (было 111 МБ PNG вместе с листами-атласами), манифест ≈294 КиБ. Листы-атласы
(`plain`) порт не читает — на диск они больше не пишутся; для обратной упаковки их вынимает `ff_extract.py` сам.

| Архив | Кадров | Примечание |
|---|---|---|
| `Interf/Interf.ff` | 1710 | из них 195 — кадры 7 анимаций (`DLG_WAIT_HOURGLASS`, `_WATER*`, `_FIREFLY*`) |
| `Interf/IntfScen.ff` | 229 | редактор карт |
| `Interf/MenuImgs.ff` | 1 | `TRANS_MAIN2PROTO` |
| `Interf/MenuAnim.ff` | 0 | **не берётся**: 52 записи и все — видео `.BIK`, их переводит `tools/video-import` |

Имя кадра адресует его не однозначно: 10 имён встречаются и в `Interf.ff`, и в `IntfScen.ff`
и при этом разного размера (`DRAGDROP_SMALL_VALID` — 74×89 и 70×85). Поэтому в манифесте
запись опознаётся парой архив+имя, а поиск по одному имени (`UiAssets.ByName`) берёт первый
архив по порядку списка. Принадлежность кадра анимации и его место в ней видны по пути файла.

## Шрифты игры

```
python tools/ui-assets/import_fonts.py
```

Семь растровых шрифтов `Interf/*.mft` (игра — `D2_GAME_DIR`, кириллица — слой `disciples-vanilla/l10n/russobit`, ключ `--l10n`) →
BMFont `assets/fonts/<имя>.fnt` + `<имя>.png` (или `D2_ASSETS_DIR/fonts`), вне git. Порт рисует ими текст по умолчанию
(`data/ui/fonts.json`); разбор формата, кодировки и сверка со снимками — `docs/ui-text.md` §2. Прогон — доли секунды.

## Кто это читает

`src/D2.Data/Ui/UiAssets.cs` — чтение манифеста, `Merge` для модов (как `UiScreens.Merge`),
`PathOf` для пути к файлу. Проверки — `src/D2.Data.Tests/UiAssetsTests.cs`; сверка файлов с
манифестом (WebP без потерь, размер) пропускается, когда `assets/ui` не распакован. Хеш пикселей сверяет сам
сборщик: выборка файлов после записи разбирается заново.

## Откуда взят распаковщик

`ff_extract.py` скопирован из `disciples-modding/hd-mod/tools/` (с тех пор: чтение архива отображением файла и
помощники `base_sheets`/`buildable`/`plain_image` для сборщиков) — там он уже
работает и проверен на этих же архивах. Копия, а не ссылка: порт не должен зависеть от
соседнего репозитория. Его происхождение (MIT, Karnah/Disciples.Net) — в `NOTICE` рядом.
